# 第三轮：M3 DoD 现场演示（由 AI 经 SSH 在 nfvis-vm 执行）

执行时间 2026-09-13，环境：nfvis-vm（VPP 26.06-release、vmxnet3→DPDK、ens160 管理/ens192+ens224 业务）。
证据：`docs/evidence/m3-demo/`（`cli-reachability.txt`、`D1-partial-cli-to-vpp.txt`、`order-dependence.txt`、`D2-l3-only.txt`、`D1-D2.txt`）。
记录：`docs/M3-人工演示记录.md`。执行后已清理（nfvisd 停止、VPP 无残留、DPDK/大页未改动）。

## 关键结论

**M3 DoD 第 3 条（CLI 现场演示）当前无法达成**——不是功能没实现，而是**M3 新增的网络配置语句在 CLI 语句→模型映射层缺失**，导致这些功能无法经 CLI 配置（只能经 API/引擎，M3 的真机验证正是走引擎直连的集成测试，因而未暴露）。

## 【高】CLI 映射缺口（数组/嵌套类语句）

**根因**：需要「数组追加 / 嵌套写入」的语句没有 alias 规则；且**元素不存在时走宽松插入路径**（返回 `[ok]`，但写入的是不符合模型的结构），元素存在时走严格校验（返回“尚未映射到模型”）。于是**先建交换机再配子字段**这一真实使用顺序必然失败。

| 语句（契约已声明） | 真实顺序下的结果 | 证据 |
|---|---|---|
| `virtual-switches <n> gateway ip <prefix>`（FR-NET-014 BVI） | ❌ 未映射 | order-dependence.txt B/C |
| `virtual-switches <n> l3-interface <if> ip address <prefix>` | ❌ 未映射 | D2-l3-only.txt |
| `virtual-switches <n> static-routes <prefix> next-hop <ip>` | ❌ 未映射（同一会话未走到，前一条已中止） | D2-l3-only.txt |
| `acls <n> rule <seq> source … destination … protocol … action …` | ❌ `未知语句: "destination"`/`"action"` | cli-reachability.txt |
| `nat source-pool <n> address-range <ip> to <ip>` | ❌ 未映射 | cli-reachability.txt |
| `nat rules <seq> match source … virtual-switch … action …` | ❌ 未映射 | cli-reachability.txt |
| `port-mirroring <n> … direction <…>` | ❌ `未知语句: "direction"` | cli-reachability.txt |
| `qos policies <n> cir <bps> cbs <bytes>` | ❌ `未知语句: "cbs"` | cli-reachability.txt |
| `interfaces <if> ingress-policy <name>` | ❌ `缺少取值` | cli-reachability.txt |
| `protocols lldp enable <bool>` | ❌ 未映射 | cli-reachability.txt |

**✅ 经 CLI 端到端可用的部分（已验证到 VPP）**：`interfaces <if> description`、`virtual-switches <n> type`、`ports <seq> interface <if>`、`vlan access`、`delete virtual-switches <n>`、`vpp plugins <name> state`。
证据 `D1-partial-cli-to-vpp.txt`：CLI commit 后 VPP 出现 bridge-domain（BD-ID 10365503）、`l2fib` 学到 2 条 MAC；`delete` + commit 后 VPP 侧 BD 消失。→ **CLI→nfvisd→VPP 链路本身是通的，问题局限在映射层**。

另有一个隐患：宽松插入路径会把 `gateway ip` 写成不符合模型的结构（元素不存在时返回 `[ok]`），属于「静默写坏数据」，比直接报错更危险，修复时应一并改为严格模式。

## 【中高】`nfvis-cli -c` 会话泄漏

`-c` 执行完不退出会话（会话按 `user@source` 保留在服务端），后果：

- 后续调用被按上一个模式解释：`-c configure` 后用 `-c "show version"` → `%% 无匹配配置: version`（证据 `cli-reachability.txt` 开头）；
- 残留**脏 candidate + 会话锁**；脚本再次以 `exit` 收尾时报 `%% 存在未提交变更，先 commit 或 discard` 并**非零退出**，使脚本化不可用（本人在演示中因此得到过自相矛盾的中间结论）。

建议：`-c` 模式收尾自动 `discard`（若有 candidate）+ `exit` + `logout`；或在会话上加 oneshot 标记。

## 【中】守护缺口：没有 CLI 语句映射的自动化校验

`internal/api/routes_contract_test.go` 守护了 API↔契约，`internal/schema/gen_test.go` 守护了命令树⇄模型字段，但**没有任何测试断言「契约里的语句能真正落进 candidate」**——这正是上述缺口长期存在的原因。
建议新增 `internal/api/cli_mapping_test.go`：对契约 §2.4/§2.5/§2.9 的每条代表性语句，断言 `set` 后 candidate 发生变化且无 `%%`；纳入 `make check`（CLI 版 route guard）。

## 修复建议（按优先级）

1. 【高】补齐上述 10 条语句的 alias 映射（数组追加/嵌套写入），并让映射失败一律报错、不得宽松插入；
2. 【高】新增 CLI 映射覆盖测试并纳入 `make check`；
3. 【中高】`-c` 会话收尾自动清理；
4. 【中】M3 DoD 第 3 条在修复并重新演示前**不得关闭**；`docs/M3-人工演示记录.md` 已如实记录为「部分通过 + 阻塞」。

## M4 影响

`docs/M4-任务清单.md` 的 M4-12（CLI 侧命令接入）范围需扩大：M4 之前必须先把 M3 的网络配置语句映射补齐，否则 `request vnf …` 系列接得再好，网络侧仍无法经 CLI 配置。
