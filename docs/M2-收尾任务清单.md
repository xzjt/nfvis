## 交付流程（每个任务都走这条）

1. 分支：`feat/m2-<task>`；PR 描述引用本任务编号与 FR 编号。
2. 本地自检：`make check` + `/contract-check`（ZCode 会话内）必须全绿。
3. 涉及契约改动（CLI 命令/API 端点/资源模型）：**先改 docs/ 契约文档 + 附录 A 追加决策**，再写代码。
4. PR 合并前 pre-commit 钩子 + CI 双绿；覆盖率门槛：`internal/config`、`internal/model`、`internal/schema` ≥ 70%。

## 任务 W1：CLI 管道过滤（FR-CLI-005）

- **目标**：`show ... | match <re>`、`| except <re>`、`| count`、`| last <n>`、`| begin <re>`、`| display json`、`| display xml` 全部可用。
- **建议落点**：`internal/api/cliexec.go`（服务端解析管道，因为 `display json/xml` 需要结构化输出，客户端只做展示）。
- **验收标准**：
  - `show configuration | display json` 输出可被 `python -c "import json,sys;json.load(sys.stdin)"` 解析；
  - 管道可组合（如 `| match x | count`）；`except` 与 `match` 互斥语义正确；
  - 无管道时行为与现状完全一致（回归）。
- **注意**：不要把 `|` 之前的命令解析与别名表（matchAlias）混淆——两者正交。

## 任务 W2：命令历史与交互增强（FR-CLI-006）

- **目标**：↑/↓ 历史浏览、Ctrl-R 反查、会话空闲超时自动登出（`system idle-timeout-minutes`，默认 10 分钟）。
- **参考实现**：`prototype/editor.go` 已有 raw 模式按键处理与历史导航（`historyNav`），可直接借鉴；注意 Windows 扫描码（0xE0 前缀）与 ESC 序列双分支。
- **验收标准**：历史跨命令保留且不重复相邻项；Ctrl-R 可搜到旧命令；超时后会话失效并提示。

## 任务 W3：命令缩写（FR-CLI-004）

- **目标**：无歧义前缀即合法（按命令树逐级消歧，见命令树契约 §5.5）；歧义时报错并列出候选。
- **落点**：`internal/schema` 增加前缀匹配解析（`Match` 的前缀路径），CLI 与 API 共用。
- **验收标准**：`conf` → `configure`；`show vir` 歧义时报错并列出 virtual-switches / virtual-machine-functions；`internal/schema` 覆盖率不下降。

## 任务 W4：配置导入导出与校验命令（FR-CFG-007/008 + 命令树 §2.1）

- **目标**：`load override <file>`、`load merge <file>`、`save <file>`（JSON）、`annotate <path> "text"`、`commit check`（只校验不下发）。
- **验收标准**：`save` → `load override` 往返后 `compare` 无差异；`commit check` 不改变 committed 与 rollback 历史；annotate 内容出现在 `show configuration` 输出且可经 API 读写。

## 任务 W5：无底座依赖的 API handlers（第一组）

| 端点 | 依据 | 说明 |
|---|---|---|
| `GET/PUT /resource-pools` | FR-CMP-001~004、FR-SYS-002/003/010 | 账本 M1 已就绪；PUT 需返回“需 reboot 生效”警告；缩减时校验存量占用 |
| `POST/GET /system/login-users`、`PUT/DELETE /system/login-users/{name}`、`POST …:change-password` | FR-SEC-002/003/008、决策 #25 | 口令仅存哈希、永不回显；不能删除自己或最后一个 super-user（409） |
| `GET /system/status` | 规格书 §6.2 | 无运行态的字段先返回配置/主机信息，运行态字段留 M3 补 |

- **验收**：上述端点全部注册且鉴权（read-only 用户写操作 403）；`/contract-check` 通过；审计记录产生。

## 任务 W6：网络配置层 API handlers（第二组）

- **目标**：`acls`、`nat`、`qos/policies`、`port-mirroring`、`bonds`、`protocols/lldp` 的配置 CRUD（写 candidate → commit 落库）。
- **边界声明（重要）**：**配置层属 M2，运行态与底座生效属 M3**。本任务只做配置读写与校验，不 import `internal/orchestrator` 的实现（apply 经既有 Provider 接口，mock 下可运行）。
- **验收**：每个资源 CRUD 往返一致；删除有引用的资源返回 409；配置树实测样例仍全绿（internal/schema/gen_test.go 分支覆盖不下降）。

## 任务 W7：`internal/cli` 落位重构

- **目标**：把 `cmd/nfvis-cli/main.go` 中的行编辑/补全/模式/提示符逻辑抽到 `internal/cli`（骨架 §2），`cmd` 只保留参数解析与装配。
- **验收**：`internal/cli` 有独立单测（补全、历史、前缀匹配、提示符）；`cmd/nfvis-cli/main.go` ≤ 100 行；CLI 行为与重构前逐项一致（手工回归清单写在 PR 里）。

## 任务 W8：内部端点入契约（决策待批）

- **目标**：`/cli/execute`、`/cli/candidates` 登记进 `docs/NFViS-openapi.yaml`，标注 `internal: true`（仅 nfvis-cli 使用，不承诺第三方兼容）；附录 A 追加决策记录。
- **验收**：契约端点集合 ⊇ 已注册路由（由 W9 自动校验）。

## 任务 W9：契约↔路由一致性测试

- **目标**：新增测试断言「server.go 注册的每条路由都在 OpenAPI 中声明」（解析 `internal/api/server.go` 的 `mux.Handle` 与 yaml paths），防止再次漂移。
- **落点**：`internal/archtest`（已有 `go list` 守护）或 `internal/api` 内测试。
- **验收**：故意新增一条未登记路由时测试失败。

- prototype 的 `_`/`.` 前缀文件不参与编译——验证类临时文件命名别踩。
