## 3. 大页容量账（M4 测试 VM 的硬上限）

```
内核参数：default_hugepagesz=1G hugepagesz=1G hugepages=4
实际：    HugePages_Total=3  HugePages_Free=1（MemTotal 仅 5366MB，4 页请求未全部落实）
VPP：     memory { main-heap-size 2G  default-hugepage-size 1G } → 占 2 页
```

- **结论**：vhost-user VM 必需大页（FR-NET-020），当前仅 **1 页空闲 = 1GB 可分配**。
- **M4 测试约束**：VM 内存 **≤1GB（1 个大页）**，同一时刻只跑 1 台大页 VM；多 VM 集成用例须串行且逐一删除归还。
- 若需更大 VM：先改 `HUGEPAGES_1G`（`contrib/dev-vm/provision.sh`）并重启，或下调 VPP `main-heap-size` 释放页；不得在测试中临时挤占 VPP 页池。
- 验证：`-m 1024 -object memory-backend-file,...,mem-path=/dev/hugepages,share=on` 可正常启动。

## 4. SR-IOV 不可真机验证（如实标注，不得记为通过）

- `ens160` 是 vmxnet3（VMware 虚拟网卡），无 SR-IOV PF/VF；`ens192`/`ens224` 亦为 vmxnet3 且已绑 vfio-pci 供 DPDK 使用。
- 因此 M4-4 的 SR-IOV 分支**只交付**：hostdev XML 组装 + 单测断言 + "环境无 PF/VF 时明确报不支持"路径。
- 真机回归延后到具备 SR-IOV 硬件的环境；M4 验收记录中该分支标注 **未验证（环境无硬件）**，不计入通过项。

## 5. 其他环境事实（影响 M4 实现假设）

- **CPU**：Intel i7-9750H，2 socket × 3 core，共 6 逻辑核（`0-5`），NUMA 1 节点（node0 = 0-5）。**内核 cmdline 无 `isolcpus`**——资源池隔离核为配置层概念，可分配全集即 `0-5`；`vpp cpu main-core 4`、`corelist-workers 5` 已占 2 核（FR-SYS-010 账本须先扣）。
- **NUMA 亲和不一致校验（FR-CFG-011⑩）**：本环境单节点，无法构造跨 NUMA 物理拓扑，该警告路径只能单测覆盖，真机标注"单 NUMA 无从构造"。
- **磁盘**：根分区 96G，可用 82G，足够 VM 镜像/快照/数据盘。
- **apt/下载代理**：VM 经 `http://192.168.155.1:2333`（`/etc/apt/apt.conf.d/95nfvis-proxy`）；M4-8 URL 拉取走同一 PROXY。
- **nfvisd 未运行、VPP 已运行**（`systemctl is-active vpp = active`）；真机前保持 `pkill -x nfvisd` 以免与集成测试争用。
- **管理程序**：`apparmor` 对 `/run/nfvis`、`/var/lib/nfvis` 目录的访问限制需在 M4 真机联调时确认（libvirt 以 root 运行，暂未见阻）。

## 6. M4-P0 完成判定

必需项（KVM / libvirt / QEMU vhost-user / Docker / VPP memif+vhost_user / 大页≥1 可用 / 工具链）**全部满足**，M4 真机项可开展；SR-IOV 与跨 NUMA 两项按 §4/§5 如实裁剪。M4-1 起可在本环境 `virsh dumpxml` 复核 domain XML。
