## 4. 本轮教训（入册，接手必读）

1. **veth 是成对设备，一端消失即整对消失**（容器 netns 销毁 ⇒ 容器端消失 ⇒ 宿主端一起没了）。
   「停容器把宿主端留着」在内核里做不到——正确口径是「宿主端随**声明**由网络侧幂等补建、随**声明
   消失/删除**清空」。真机实证（R5-2）。
2. **应用段序与「释放不再声明的成员」会互相咬**：容器 veth 宿主端必须「先建接口（vnf-if 段）、
   后由 bridge-domain 段 enslave」；恢复重放的 veth 段还要**前置**于交换机段，否则交换机段的
   「释放不在声明里的成员」会把运行中容器的宿主端从 bridge 上摘掉（R5-0）。交换机段的声明集要用
   `SwitchMembersOf(cfg,…)`（单一真源）。
3. **清场命令不要只看 `tail -1`**：R6-1 的失败就是这么漏掉的（截断窗口里恰好是 GRUB 告警行）。
   核对面：`show configuration | display set | grep <对象>`、`ip -br link`、`show alarms active`。
4. **vpp 段删叶子会留非 nil 空壳**（`{cpu:{},memory:{},dpdk:{dev:{}}}`）；判「配置内容是否为空」
   必须按**内容**（R4-1）。同理，**删光一个配置族会留空壳并让 `display set` 报内部错误**——修复走
   既有**登记制**（`pruneEmptySingleton` 逐族登记，未登记的容器不动）（R4-3）。
5. **容器 `args` 是单个参数元素**（`args "sleep 3600"` ⇒ `exec: "sleep 3600": executable file not
   found`）；跑长命令用 `command /bin/sleep` + `args 3600`。（既有语义，两数据面一致。）
6. **单测全绿挡不住真机（又一次实证）**：本轮四条真机发现（R5-0 段序、R5-2 veth 语义、R4-1 空壳、
   R4-3 空壳+display set）**全部**是单测/子智能体自检抓不到的；每条都已回灌成守护（按**真机形状**）。
7. **内核模式删对象要在内核模式下做**（切回 vpp 后再删，内核侧 teardown 不跑 ⇒ 留孤儿 bridge/tap/VRF；
   本轮手工 `ip link del` 清掉 ct-vs 三件套）。
8. **子智能体的「偏差」清单要先读再验收**：本轮 S7/S8 各报出 1~2 条真问题（段序、停容器抖动），
   全部采纳并回灌；其中 S7 还自行发现「恢复重放的交换机段会摘掉运行中容器的宿主端」。
