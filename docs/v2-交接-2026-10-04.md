## 4. 本会话教训（round137~139 新增，入册）

1. **派生显示别拿同一个源和自己比**（round137）：概览「（默认）」把 `Committed()` 的生效值同时当左右两侧 ⇒ 注记恒真（真机 `interval=10` 仍显示「默认」）。
2. **「空 / 查不出 / 真没有」必须分得开**（round137）：查询失败不能答成「窗口内无数据」；`truncated` 不能用「点数正好等于 limit」猜，要取存储侧真值。
3. **删空要剪空壳**（round137）：新增的配置单例删光叶子后留 `{}`，会让 `show configuration | display set` 的**回放自校验**报内部错误（与 round84 空 `nat` 同族）——新增配置面时把空壳剪枝一起做掉。
4. **读端点前先看响应形状**（round137）：`GET /configuration` 是 `{configuration:{…}, revision:N}` 包装（一度按顶层键解析，误判「配置被清空」）。
5. **Browser Use 能抓到静态守护看不见的**（round138）：容器详情页新分栏「点了没反应」＝`CT_TABS` 常量漏加 `'exec'`——所有静态守护（端点/写控件/角色门禁）全绿，**真机点一遍才发现**（#141 的价值）。已补「分栏 HTML ⇄ JS 常量一致」守护并自校准。
6. **底座 API 的语义要按实测写，别按语言库的直觉**（round139）：Go 的 `http.ReadResponse` 对 **101** 的 body 语义与本用途不合（读侧立刻 EOF ⇒ 会话刚建立就断开）；改为**手工解析状态行与响应头**，读侧自己持有 `bufio.Reader` 以免丢掉与响应头同包到达的首批数据。
7. **想当然的「释放/收敛」要用对照实验验**（round139）：「连接断则容器内 exec 进程随之终止」被对照实验（会话前无 `sh`、会话后有 1 个）直接推翻 ⇒ 契约/文档/注释/Web 文案**全面改写为实测事实**。**别在契约里写没验过的因果**。
8. **静默丢弃「做不到的操作」＝ 假成功**（round139）：脚本模式（`-c`/`-f`）原来把终端接管请求直接丢掉，只打印「正在打开…」就退出——已按「需交互确认」同一先例改为失败并指引交互式 CLI（**顺带收口 VM 串口同款**）。凡「本模式做不到」，要么做、要么如实拒绝。
9. **工具假红也是缺陷**（round139）：见 §3 的 L2-3 更正——判据要分清「查不了」与「查到残渣」，并做**合成输入自校准**（只有查不了⇒0 判定、真残渣⇒仍抓得到）。
10. **`node --check` 对含 `export` 的 ESM 会漏报语法错误**：把换行转义误写成字符串里的**真换行**时 `node --check app.js` 仍 rc=0，而 `vm.runInContext` 报 SyntaxError——**真正拦得住的是 `contrib/scripts/web-console-config-selftest.sh`**（在 `make check` 的 toolcheck 里跑）。改 app.js 后别只信 `node --check`。
11. **写脚本别赌反斜杠转义**：在 `bash -c "python - <<'PY' …"` 这类嵌套里，`"\n"` 会被某一层吃掉反斜杠、把 Go/JS 的字符串字面量写成真换行。**用 `chr(92)+'n'` 拼，或改走「写文件 + 拼接」**（本会话踩了 4 次）。
12. **换身份做验证必须显式给用户名**（round138）：漏了 `-u`，失败登录计到默认用户 `admin` 头上 ⇒ 触发 **15 分钟锁号**。失败登录是有代价的；等锁定过期比乱试划算。
13. **Windows 开发机 `make check` 会偶发 OOM**（并行编译测试二进制，`VirtualAlloc … errno=1455`）：`GOFLAGS=-p=1 make check` 即 RC=0；判定构建是否真坏看 CI（Linux 双跑）或降并发复跑。
14. **一条客户端报文可能经多条入径各到一次，服务器要去重**（round141）：DHCP 广播帧在 BD 里**既洪泛到内置 tap、又经 BVI 进 UDP/67 的 punt** ⇒ 一 REQUEST 两 ACK（tap sniffer 抓个正着）。按 (chaddr, xid, 类型) 的去重窗只应答一次；**窗长要远小于客户端重传退避**（RFC 2131 ≥4s，取 3s）才不吞真重传。
15. **平台自带语义别当成产品行为**（round141，CI 抓到）：`testing.T.TempDir()` 的每调用子目录按 **0777&^umask**（Linux 0755）创建——本地 Windows 因断言带 `runtime.GOOS == "linux"` 跳过而全绿、CI 红。权限断言只对「产品自己创建的目录」有意义（给不存在的子路径让产品建）。**本地绿 ≠ CI 绿**：这类平台差异单测要在真机 Linux 上跑一遍。
16. **工具的判据要按「现象签名」分类，不要只认一条文案**（round141）：lifecycle L2-3 首版只认 `VPP 未连接`，现场变体是 `broken pipe` ⇒ 假红。同类判据要么按结构性签名（传输层失败族）分类，要么给不出结论时**如实报「查不了」**并单列。
17. **改夹具 user-data 后想复原，别指望 `start` 会重跑 cloud-init**（round141）：instance-id 是「曾经处理过」的 ⇒ once-per-instance 跳过 runcmd；标准路径是 `cli-semantic-fixture.sh up`（重建 VM/新盘）。
