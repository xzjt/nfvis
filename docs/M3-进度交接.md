## 2. 环境与真机操作

### nfvis-vm（`ssh root@nfvis-vm`，密钥免密）

- Ubuntu 26.04.1；VPP **26.06-release**（`vpp`/`vpp-plugin-core`/`vpp-plugin-dpdk`）；libvirt 12；Docker；1G 大页 3 页。
- **VPP 不自启**（有意）：测试前 `systemctl start vpp`（开机后需手动）。
- 网卡：`ens160` = 管理/SSH（`192.168.155.129`，**不要动**）；`ens192`（PCI `0000:0b:00.0`）与 `ens224`（`0000:13:00.0`）交 DPDK。
- 三张 vNIC 在 VMware 中均为 **NAT（同一 VMnet8 网段）**，**有对端**：NAT 网关 `192.168.155.2`（可 ping 通，已验证）。这是 M3-3~M3-5 通流验证的基础。
- 代码部署在 `/opt/nfvis/src/nfvis`；nfvisd 二进制 `/tmp/nfvisd`，库 `/tmp/nfvis.db`，日志 `/root/nfvisd.out`。
- VPP 套接字：`/run/vpp/api.sock`、`/run/vpp/stats.sock`、`/run/vpp/cli.sock`。

### 常用命令

```bash
# 从开发机同步代码并构建（注意 GOPROXY，VM 直连 proxy.golang.org 不通）
git archive --format=tar.gz -o /tmp/nfvis.tgz HEAD
scp -q /tmp/nfvis.tgz root@nfvis-vm:/tmp/
ssh root@nfvis-vm 'export PATH=$PATH:/usr/local/go/bin; export GOPROXY=https://goproxy.cn,direct; \
  rm -rf /opt/nfvis/src/nfvis && mkdir -p /opt/nfvis/src/nfvis && tar -xzf /tmp/nfvis.tgz -C /opt/nfvis/src/nfvis && \
  cd /opt/nfvis/src/nfvis && go build -o /tmp/nfvisd.new ./cmd/nfvisd && go build -o /tmp/nfvis-cli.new ./cmd/nfvis-cli && echo rebuilt'

# 重启 nfvisd（先 pkill，再 setsid 脱离 ssh；pkill 后 ssh 可能返回 255，属正常）
ssh root@nfvis-vm 'pkill -f "/tmp/nfvisd" >/dev/null 2>&1 || true; sleep 1; echo k'
ssh root@nfvis-vm 'mv -f /tmp/nfvisd.new /tmp/nfvisd; rm -f /tmp/nfvis.db*; \
  setsid /tmp/nfvisd -db /tmp/nfvis.db -listen 127.0.0.1:18443 -init-admin-password "Admin@12345" >/root/nfvisd.out 2>&1 </dev/null & sleep 3; \
  pgrep -af /tmp/nfvisd | grep -v pgrep | head -1'

# VPP 重启（配置改后生效；nfvisd 会自动重连）
ssh root@nfvis-vm 'systemctl restart vpp; sleep 8'

# 取 token 调 API
TOK=$(curl -s -X POST http://127.0.0.1:18443/api/v1/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@12345"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s http://127.0.0.1:18443/api/v1/vpp/status -H "Authorization: Bearer $TOK"
```

### 若 VM 重启过：重新绑定 DPDK（ens192/224 会回到 vmxnet3）

```bash
ssh root@nfvis-vm 'modprobe vfio-pci; echo Y > /sys/module/vfio/parameters/enable_unsafe_noiommu_mode
for d in 0000:0b:00.0 0000:13:00.0; do
  echo $d > /sys/bus/pci/drivers/vmxnet3/unbind 2>/dev/null || true
  echo vfio-pci > /sys/bus/pci/devices/$d/driver_override
  echo $d > /sys/bus/pci/drivers/vfio-pci/bind
done
systemctl restart vpp; sleep 8; vppctl show interface'
```
`/etc/vpp/startup.conf` 由 nfvisd 生成（M3-2），含 `cpu main-core 4 / corelist-workers 5`、`dpdk dev <pci> { name ens192/ens224 }`。

## 3. 踩坑清单（真机发现，务必避免重蹈）

1. **接口默认 admin-down**：VPP 接口（含 BVI、VLAN 子接口、bond）创建后都是 down，必须显式置 up，否则配置对也不通流。已由 `ServicesProvider.ApplyInterface`（MTU + ingress-policy + 状态）与 L2/L3 Provider（子接口/BVI）补齐。
2. **govpp 错误码不落在 `Reply.Retval`**：非零 retval 由 `ReceiveReply` 的 error 返回（`api.VPPApiError`）。幂等判断必须用 `vppErrIs`（`internal/orchestrator/network/vpp_err.go`）。已知码：`VALUE_EXIST -81`、BD 已存在 `-119`、IP table 已存在 `-111`、带地址接口迁移 VRF `-114`、NAT 特性未启用 `-169`。
3. **ACL 索引 0 合法**：VPP 首个 ACL 的 index 是 0；用 `!=0` 判"未设置"会误判。新建 ACL 用 `~0` 哨兵，绑定用 `inSet/outSet` 布尔。
4. **`bridge_domain_dump` 双过滤**：同时按 `bd_id` 与 `sw_if_index` 过滤，binapi 的 `default=0xFFFFFFFF` 发送时不会自动填充 → 必须显式传 `sw_if_index=~0`，否则拿到空表误判"不存在"。
5. **VRF 迁移接口前先清地址**：带地址的接口置表会报 `-114`；`ApplyVRF` 先 `del_all` 再置表。
6. **NAT44 EI 需先启用插件**：配置地址池/特性前调 `nat44_ei_plugin_enable_disable(enable)`；插件未启用时 `nat44_ei_user_session_dump` **不应答**（会挂起），故未启用时 `Sessions` 直接返回空。
7. **SPAN 关闭要给源+目的**：只传源口 disable 无效。
8. **删除 bond 前先摘成员**：否则残留从属状态（后续 VPP 对相关接口报 "Interface name is invalid"）。
9. **会话按 `user@source` 记忆**：同一 `admin@ssh` 跨多次 CLI 进程会延续配置模式；演示操作模式命令前先 `exit` 或用新库。
10. **Windows 与非 Linux 构建**：`statsclient` 间接依赖 Linux 专属 syscall，stats 实现用 `//go:build linux`（`stats_linux.go`）+ 非 Linux 桩（`stats_other.go`）。改 stats 相关代码要两边都 `go build ./...`（含 `GOOS=linux`）。
11. **覆盖率门槛排除 `*_govpp.go`**：薄 binary-API 适配层由真机集成测试覆盖；逻辑在 `*_test.go` 用假客户端测。新写适配层请沿用 `_govpp.go` 命名。
