## 3. 踩坑清单（真机发现，务必避免重蹈）

1. **接口默认 admin-down**：VPP 接口（含 BVI、VLAN 子接口、bond）创建后都是 down，必须显式置 up，否则配置对也不通流。已由 `ServicesProvider.ApplyInterface`（MTU + ingress-policy + 状态）与 L2/L3 Provider（子接口/BVI）补齐。
2. **govpp 错误码不落在 `Reply.Retval`**：非零 retval 由 `ReceiveReply` 的 error 返回（`api.VPPApiError`）。幂等判断必须用 `vppErrIs`（`internal/orchestrator/network/vpp_err.go`）。已知码：`VALUE_EXIST -81`、BD 已存在 `-119`、IP table 已存在 `-111`、带地址接口迁移 VRF `-114`、NAT 特性未启用 `-169`。
3. **ACL 索引 0 合法**：VPP 首个 ACL 的 index 是 0；用 `!=0` 判"未设置"会误判。新建 ACL 用 `~0` 哨兵，绑定用 `inSet/outSet` 布尔。
4. **`bridge_domain_dump` 双过滤**：同时按 `bd_id` 与 `sw_if_index` 过滤，binapi 的 `default=0xFFFFFFFF` 发送时不会自动填充 → 必须显式传 `sw_if_index=~0`，否则拿到空表误判"不存在"。
5. **VRF 迁移接口前先清地址**：带地址的接口置表会报 `-114`；`ApplyVRF` 先 `del_all` 再置表。
6. **NAT44 EI 需先启用插件**：配置地址池/特性前调 `nat44_ei_plugin_enable_disable(enable)`；插件未启用时 `nat44_ei_user_session_dump` **不应答**（会挂起），故未启用时 `Sessions` 直接返回空。
7. **SPAN 关闭要给源+目的**：只传源口 disable 无效。
8. **删除 bond 前先摘成员**：否则残留从属状态（后续 VPP 对相关接口报 "Interface name is invalid"）。
9. **会话按 `user@source` 记忆**：同一 `admin@ssh` 跨多次 CLI 进程会延续配置模式；演示操作模式命令前先 `exit` 或用新库。
10. **Windows 与非 Linux 构建**：`statsclient` 间接依赖 Linux 专属 syscall，stats 实现用 `//go:build linux`（`stats_linux.go`）+ 非 Linux 桩（`stats_other.go`）。改 stats 相关代码要两边都 `go build ./...`（含 `GOOS=linux`）。
11. **覆盖率门槛排除 `*_govpp.go`**：薄 binary-API 适配层由真机集成测试覆盖；逻辑在 `*_test.go` 用假客户端测。新写适配层请沿用 `_govpp.go` 命名。
12. **整份 ConfigDocument 覆盖 PUT 会替换 `system.login`**：`PUT /configuration/candidate` 是整份覆盖（load override），若文档不带 `system.login`，bootstrap admin 用户从 committed 配置中消失；下次 nfvisd 重启会重新生成**随机一次性口令**（打印在 nfvisd 日志 stdout）。演示/测试时要么在文档里带上用户，要么每次用 `-init-admin-password` 重启。
13. **API candidate 会话锁在 commit 后仍持有**：`POST /configuration/commit` 不释放 `admin@api` 的会话锁（JunOS 式保持配置模式）；此时重启 nfvisd，`EnsureBootstrapAdmin` 会因"candidate 会话锁被占用"启动失败。API 侧演示完需 `DELETE /configuration/candidate`（或 `POST /logout`）释放锁再重启。
14. **手工删 BD 前先摘成员**：VPP 对仍挂成员的 BD 报 `bridge domain in use - remove members`；CLI 用 `vppctl set interface l2 bridge <if> 0` 摘除成员，再 `vppctl create bridge-domain <id> del`。恢复收敛对已删 BD 会自动补建并重挂成员。
15. **OnConnect 在连接管理协程内同步回调**：回调里做重活（如恢复收敛）务必自行起协程（`cmd/nfvisd` 即如此），否则阻塞 VPP 状态监视。
16. **VPP ping 无 binary API**：ping 插件只有 `want_ping_finished_events`（结果通知），发起只能走 CLI → 经 `vppctl`（`/run/vpp/cli.sock`）。`vppctl ping` 的 `source` 收**接口名**而非 IP，契约 `source <ip>` 需先经 `ip_address_dump` 反查接口。
17. **VPP 26.06 无 traceroute**：无插件/CLI/binary API（`show plugins`、命令树、binapi 均无）；traceroute 只能宿主侧 ICMP，无法经 VPP VRF。
18. **VPP 丢弃「spoofed local-address」ICMP**：ping VPP 自身接口地址会被 `ip4-local` 当作源/目的同为本地地址而丢弃（`show errors` 可见 `ip4 spoofed local-address packet drop`），不能用「ping 自己」做正向验证。
19. **残留 L2 环路会让 NAT 不回 ICMP**：ens192/ens224 两张 vNIC 同在 VMnet8，若同时挂进同一 bridge-domain 会形成环路（VPP `l2-fwd Reflection Drop` 激增），随后 VPP 从 VRF ping 网关 0 收包（TX 增长、ARP 无应答，静态 ARP 亦无效）；清除 BD（先摘成员）并重启 VPP 后恢复正常（实测 2/3 收包）。排查「ping 不通」先确认无遗留 BD/环路，再怀疑地址/路由。
20. **monitor 是客户端轮询**：服务端 `monitor interfaces` 只返回单次快照；nfvis-cli 检测该命令后临时退出 raw 模式（使 Ctrl-C 产生 SIGINT）、按 interval 整屏刷新，Ctrl-C 退出；非 TTY 退化为单次快照。
21. **`ip_address_dump` 不支持 `~0` 全量**：VPP 26.06 传 `sw_if_index=~0`（或 0）均返回空——与 `bridge_domain_dump` 必须传 `~0` 的行为**相反**。要枚举全部接口地址须先取接口索引再逐口 dump（已修 `govppDiagClient.InterfaceAddresses`）；否则 `ping source <ip>` 反查会失败。新增任何 dump 类调用务必真机确认过滤语义。
