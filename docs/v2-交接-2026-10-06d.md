## 4. 本批教训（入册）

1. **「无匹配默认＝放行」要按机制实测**：macip ACL 不带显式 deny 时是**放行**（对照实验：单 permit 的 ACL 伪造源照样通过）——白名单语义必须显式 deny-all。别按「ACL 默认拒绝」的直觉写。
2. **套件解析循环是「逐条独立会话」**：有前置依赖的语句（先 set 后 delete）必须写成同一会话块；严格语义的 delete（「无匹配配置」）在独立会话里无对象可删，会真假红。真机四维与套件编排要分清「产品错」还是「编排错」。
3. **子智能体产出要先落盘/提交**：本批子智能体**配额中断**在实现中途——得益于项目「产出先 commit」纪律，主会话得以在其留下的工作树（模型/校验/数据面主体）上补完（接线/读视图/文档/单测），没有白做。中断恢复时**先盘点工作树**再决定续作方式。
4. **`vppctl` 的多规则语法不可靠**（macip 逗号列表只落 1 条、tag 丢失）：底座类 spike 与实现一律走 **govpp binapi**，CLI 只用于单条查看。
5. **解绑 ≠ 对象删除**：macip 无 delete 消息——解绑即时生效（策略不再执行），ACL 对象残留至数据面重启；读视图/文档如实说明，不粉饰。
