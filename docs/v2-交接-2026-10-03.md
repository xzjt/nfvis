## 4. 本会话教训（新增，入册）

1. **阻塞类问题先只读定位**（journal 分段 / 超时上限对照 / **SIGQUIT 全栈**），不要在调用路径上连叠改动
   （round128 反面；#349 正法证伪了假设）。
2. **归属/统计判据用「全量映射者集合」，不用扫描顺序**——vhost-user 会把 VNF guest RAM 映射进 VPP，
   「首见归属」会随 pid 序在 1↔2 间翻转（round134b，Browser 复核实抓）。
3. **跨事实源对照（CLI/REST/页面/底座）能暴露非确定读数**；Web 面交付必须 **Browser Use 实机复验**
   （#141 规则本会话两次直接变现：round134 翻转缺陷、round127 缓存教训）。
4. **采证窗口要窄/带时间戳**——宽窗口会被上一轮旧日志撞成假阳性（round135 实例，已更正）。
5. relay 回程要求 **DHCP server 回显 option 82**（不回显则应答静默丢弃，唯一线索
   `show errors` 的 `dhcp-proxy-to-client ... option 82 missing`）——已入手册 §8.3。
6. 「接口/端口角色互斥」类正确校验会因**遗留对象**级联出假红（bond0 占 ens192）——清场先行。
7. **「注记/默认」这类派生显示，判据别拿同一个源和自己比**（round137：概览「（默认）」把
   `Commited()` 的生效值同时当左右两侧 ⇒ 恒真；真机 `interval=10` 仍显示「默认」）。
8. **「空/查不出/真没有」必须分得开**（round137 两例）：查询失败不能答成「窗口内无数据」；
   `truncated` 不能用「点数正好等于 limit」猜，要取存储侧真值。
9. **删空要剪空壳**：新增的配置单例（`system.metrics`）删光叶子后留 `{}` 会让
   `show configuration | display set` **回放自校验**报内部错误（与 round84 空 `nat` 同族）——
   新增配置面时把「空壳剪枝」一起做掉，并加往返回归。
10. **`GET /configuration` 的响应是 `{configuration:{…}, revision:N}`**（round137 一度按顶层键解析，
    误判「配置被清空」）——读端点前先看形状。
