## 4. 本轮的经验（避免重走）

- **改仓库里的文本文件必须显式 LF**：用 Python 直接写 `docs/NFViS-openapi.yaml` 没带 `newline="\n"`
  ⇒ 契约变 CRLF ⇒ **`check_openapi_json_sync.sh` 照样报「同步」**，但三个**字段级 UI 守护**
  （`TestUIQosCardFieldsExistInContract` / `TestUISpanCard…` / `TestUISwitchPortTable…`）一起报
  「找不到 Xxx schema（排版变了？）」——它们按行锚定 `$`。改完用 `python -c` 把 CRLF 归一为 LF。
- **改行为必然带出既有断言**：round22 改了 `stop` 语义，四处表达「丢弃」的旧断言（两 provider +
  api 端点 + fake）要按新语义**重写并把理由写进证据**——别只改断言了事。
  **round23 补充**：还要把**同语义的「跑得过」旧片段**全找一遍——套件 phase5 的旧名段照旧全绿，
  却留下冻结会话（在 round23 内核往返时被启动收敛清掉才暴露）；phase4 已修、phase5 漏掉的教训。
- **要区分「事实错」与「说话方式错」**：round19 的归因（`vnf-b`）**是事实**，错的是没解释分配顺序；
  round20 的「不自动重探」**是内核行为**，产品没错。两条都只改文案/口径，不动算法。
- **`make check` 的 `-p` 不改会把宿主打爆**（本轮两次 OOM）——见 §2 的构建提示。
- **跑测会改现场**：套件改 `resource-pools`/`vpp cpu` 标量、留 `interfaces ens224 disable` 残留、
  改资源池**列表顺序**；跑完必须还原（清单见 round20 证据 §3/§4；round23 两轮 fulltest 各完整还原一遍）。
- **「能力前提」要在真机上量，别信直觉**（round23 决定性的那条）：对已启用的 VPP trace 重复
  `pcap trace …` 是**静默 no-op**（RC=0）——不收敛就会出现「命令成功但没在抓所配会话」的假会话；
  这与「off 未启用时幂等无害」一起，把「启动收敛补一次 off」定成了正确解。
- **systemd 的 cgroup 会替我们收尸，但「登记」不会自己回来**：`KillMode=control-group` 下
  `systemctl restart` 会顺带 SIGTERM 掉 nfvisd exec 的 tcpdump（「孤儿进程继续写」的前提在
  systemd 部署下不成立；恢复登记才是真缺口）——读旧注释/旧结论时要把部署方式一起读。
- **新增的「扫描型」收敛要连扫描范围一起做测试隔离**：启动收敛会扫工作位（/tmp 与导出目录）——
  单测夹具若不注入工作目录，会把共享系统临时目录里其它测试留下的 `.part` 搬进本用例导出目录
  （round23 首跑即踩到；`SetWorkDir`/`SetSessionsFile` 注入后干净）。
- **子串断言会把「另一条正确命令」喂成绿的**：teardown 单测 `has()` 的
  `nft delete table inet nfvis-nat` 被步骤 4 的正确删除满足，掩盖了步骤 6 把**族名当表名**的坏命令
  （每次内核→VPP 切换假告警）——行为断言要补**负面断言**（「不得出现 X」）。
