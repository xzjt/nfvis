## 4. 本轮教训（入册）

1. **并发实现用 git worktree 隔离**：同包（`internal/orchestrator/network`）并发编译/提交会互相打断——
   #390 在主树、#391/#392 各在独立 worktree 分支，最终合并**零冲突**。
2. **账目漂移要成批回填**：体检抓到的 12 处漂移（过期「待执行」、孤儿残片、范围/计数）在 round172 顺手修掉大部分；
   **未进守护的文档面**是漂移高发区（守护脚本全绿 ≠ 账目正确）。
3. 宿主内存/分页压力下并行 `go test ./...` 会偶发崩溃（`fork/exec compile.exe: paging file too small`）——
   `GOFLAGS=-p=1 GOMAXPROCS=2` 串行可靠；提交被 pre-commit 挡下时按钩子文档用 `NO_VERIFY=1` 并**事后补跑**等价检查。
4. 子智能体的**红-绿自证**（临时还原旧行为→失败→还原→通过）是本轮最有效的审查抓手；主会话只做关键点审查。
5. **解析外部工具输出的比对逻辑，要用真机原文形状做回归用例**：防火墙内容比对单测全绿、真机却**假阴性**——
   `nft -j` 的 `ct state` 右值是**普通数组**（`{"match":{"op":"in","left":{"ct":{"key":"state"}},"right":[…]}}`），
   而 icmp/icmpv6 才是 `{"set":…}`；「单测样例 ≠ 真机形状」是这类守护的盲区（修复 `3d5377b`）。
6. **契约命令文本是套件/豁免表的键**：改命令全表里 `ports` 行的文本后，豁免表登记的旧文本失效 ⇒ 守护报
   「契约命令未进套件、也未登记豁免」；改契约命令文本必须**三处同步**（命令树设计 / 命令全表 / 豁免表）。
