## 4. 本轮教训（入册）

- **真机复验当场抓出三处实现缺陷**（子智能体单测全绿也挡不住——单测用的是「按实现假设捏的」假事实）：
  ① **Docker 的 `RestartCount` 在 inspect 应答顶层**，不在 `State`（初版按 `State` 读 ⇒ 读数恒缺、
  告警恒不触发）；② **`-91 Classify table not found`** 未被认作「表已不存在」（带链删顺带删掉链上那张后
  复核即得此码）⇒ **风暴配置删不掉**；③ **判据不可达**：Docker 崩溃循环做**指数退避**（40~60s 一次，
  巡检 15s）⇒「两轮巡检间有增长」永不成立，#432 判据已按真机改为「`restarting` ＋累计 ≥3」。
  **教益**：涉及底座字段位置/错误码/时序的判据，必须用**真机应答形状**入守护测试（本轮已补
  `docker_inspect_restartcount_test.go`、`TestStormAbsentCodeIncludesClassifyTableNotFound`）。
- **本底座两条读绑定 API 都不可用**（`classify_table_by_interface` 恒 NONE、`policer_classify_dump`
  恒空）——任何「按实况核对 policer-classify 绑定」的写法都要先探明这一点；`contrib/scripts/vpp-api-probe/`
  是现成的探针（宿主 `GOOS=linux go build` 后 scp 上机跑）。
- **`-f` 脚本文件里的引号必须核对**：本会话用 heredoc 生成 `.cli` 时被吃掉过引号（`set args -c "sleep 3600"`
  变 3 个 token ⇒ 容器 `sh -c sleep 3600` 崩循环）。生成后一律 `cat -A` 核一眼。
- **会话锁**：脚本/交互会话异常结束时可能留下 **dirty candidate 锁**（10 分钟空闲 TTL，随访问清扫）；
  **吊销他人 token 不释放其 dirty 候选**（设计如此：不替操作者丢未提交改动）——要立刻继续就得等窗口或
  `systemctl restart nfvis`。
- **SPAN 拓扑红线**：分析口与源口**同处一个二层域**会形成自持镜像环（实测 ~42kpps），环路检测覆盖不到；
  手册 §8.7 已补红线。**风暴抑制现场止血手法**：`vppctl set interface state <口> down` 掐触发流量 →
  删配置 → 再恢复（本会话两次事故都靠它止血）。
- **文档表格编辑**：替换表头/行首仍会产生「孤儿行」，改完复核行首 `|`。
