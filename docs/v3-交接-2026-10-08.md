## 4. 本轮教训（入册）

- **修复引入的新缺陷要靠真机抓**：R2-15① 的修法（改按配置声明枚举交换机）引入了「取陈旧进程内快照」，
  提交后读视图为空——单测全绿也擋不住，真机一眼命中。**改完读视图必须真机过一遍**。
- **能力前提先行**：#338/#357 的纪律再次奏效——tc 判决语义、nft 转发语义、`linkinfo` 需 `-d` 都是先在真机
  用**只碰 dummy/veth/netns** 的夹具 spike 定死，再动代码。
- **夹具是消耗品**：容器镜像夹具会被套件收尾 `docker rmi`；`/data/incoming/ct.tar` 每轮要先造；
  **夹具缺口会级联**成一片假红——判读失败先看夹具，再怀疑产品。
- **文档表格编辑**：替换表头/行首会让 Markdown 表产生「孤儿行」（本轮踩过两次，`pruning` 后要复核行首 `|`）。
- **口径如实到底**：`.run` 自检那条「安装清单包不在载荷内」在首版闭包（只跟 Depends）如实判红——
  它是本批修好的守护，正好自己证明了不再是空转假绿。
