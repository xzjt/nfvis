§1 结论：**可行**（底座有原生路径）
- VPP 26.06 **无 `storm` 命名的 API**（全量 `api.json` 无匹配），但**有等价原语**：
  `classify_add_del_table` / `classify_add_del_session` / **`policer_classify_set_interface`**（L2 表可挂接口）
  + 既有 `policer_add_del`（产品 QoS 已在用）。
- **整链在真机跑通**（三件套全部成功）：
  1. `policer_add_del`（1r2c、kbps、conform=transmit/exceed=drop）⇒ `show policer`：
     `Name "nfvis-storm-spike" type 1r2c cir 1000 eir 0 cb 1000 eb 0`；
     ⚠️ **`Cb` 必须非 0**——首试 `Cb: 0` 报 `VPPApiError: Invalid value (-7)`（踩坑入册）；
  2. `classify_add_del_table`（**L2 掩码**：16 字节向量里前 6 字节 `0xff`＝目的 MAC，其余 0；
     `skip_n_vectors=0`、`match_n_vectors=1`）⇒ `show classify tables` 出现 `TableIdx 0, Sessions 1`；
  3. `classify_add_del_session`（match＝广播 MAC `ff:ff:ff:ff:ff:ff` + 10 字节 0；**`opaque_index` = policer index**）
     ⇒ retval 0；
  4. `policer_classify_set_interface{sw_if_index=bvi1, l2_table_index=0, is_add=true}` ⇒ **retval 0**
     （`SPIKE-RESULT: chain OK`）。
- 说明：`policer_classify_set_interface` 的 `ip4/ip6/l2` 三个表索引对应**入向**路径的三个协议族分类；
  L2 表即「按以太头匹配」（广播/组播 MAC 可精确表达）。

§2 如实边界（写进契约）
- **`unknown-unicast` 无法用 L2 掩码表达**（「目的 MAC 未学习」不是以太头里的可匹配位）⇒ v1 **只做
  broadcast / multicast**，unknown-unicast 如实不做（如将来要做需另一条路线：与 l2fib miss 路径联动）。
- **速率单位是 kbps**（底座 `policer` 的 1r2c 是 kbps；若要 pps 需产品侧按标称帧长换算——**v1 不换算**，
  命令直接暴露 kbps，手册写明）。
- 分类表掩码的具体位宽/偏移（`skip_n_vectors/match_n_vectors` 与 mask 字节）由本 spike 定形；
  实现时按此写死并在注释里注明来源（真机实测）。
- 真机**未**做「真实广播流下的 conform/violate 计数对照」（spike 只验证链路成立）——该验证属实现轮
  （按 #331 round111b 的「实验组 vs 对照组、以 `vppctl` 计数为独立事实源」做法）。
