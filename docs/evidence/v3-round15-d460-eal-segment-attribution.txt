## 0. 一句话

round12/13 走查登记的**观察③**（「归属数字对、解释错位」）收口：读视图/手册把 1G 池里数据面固定

## 1. 真机取证（两条独立事实源，互相对照）

```
$ vppctl show memory
base 0x71f9c3e00000, size 1g, locked, unmap-on-destroy, name 'main heap'
  page stats: page-size 2M, total 512, populated 512, not-populated 0      ← 主堆走 2M 页（512×2M = 1G）
    numa 0: 512 pages, 1g bytes
  total: 1.00G, used: 258.16M, free: 765.84M, trimmable: 765.30M

$ grep -nE "memfd|hugepages" /proc/$(pgrep -x vpp_main)/smaps
101:140000000-180000000 rw-s 00000000 00:13 32785   /memfd:seg_0-0 (deleted)      ← 1 GiB（0x40000000）
102:Size:            1048576 kB
103:KernelPageSize:  1048576 kB                                                ← 1G 页就在这里
...
201:ac0200000-ac0400000 rw-s 00000000 00:12 32784   /memfd:seg_2-0 (deleted)
351:1000000000-1002800000 rw-s 00000000 00:12 32776 /memfd:buffers-numa-0 (deleted)
```

结论：① `/proc/<vpp>/smaps` 里**唯一的 1G 页映射**是 `memfd:seg_0-0`（1 GiB，`KernelPageSize: 1048576 kB`）；
② VPP 主堆另有其址（base `0x71f9c3e00000`，与 `seg_0-0` 的 `0x140000000` 不同）且 `page stats` 明写
**`page-size 2M`**（512 页 × 2M = 1G）——即主堆**不是**那 1 个 1G 页。这与 round13 的 DPDK 源码级判断一致，
**#347/#353 的「main heap 固定占 1 个 1G 页」措辞不成立**。

## 4. 真机复验（`3.0.10~dev6`）

```
$ nfvis-cli -c 'show system hugepages'    # 摘说明行

        按最大页优先取页），不是 VPP 主堆（主堆按 main-heap-page-size 落在 2M 页）；VNF 可起页数 = 空闲页数（当前 2）
```
