## §3 黑盒回归抓到 v3.0.19 真缺陷（本轮最高价值）

- **现象**：在 dev1 上造好现场后 23 路由扫描——自 `#/compute/containers` 起**全部页面**报
  `页面加载失败：VM_ACTIONS is not defined`。判读：拆分遗留的**跨模块自由标识符缺口**（真 ESM 下
  运行时 ReferenceError）。**round35 未暴露的原因**：当时站点零对象，`rows.forEach(...VM_ACTIONS...)`
  的循环体根本没进——**零对象现场只能覆盖一半代码路径**。
- **逐条清单（6 处，全部只差 import/export，零行为改动）**：
  ① `VM_ACTIONS`：`vms.js` 未 `export` + `containers.js` / `containerDetail.js` / `vmDetail.js`
     未 import ⇒ **有容器/VM 对象时三页整页失败**（本次实测）；
  ② `stripANSI`：`containerDetail.js` 用 `vmDetail.js` 的私有函数未 import ⇒ 容器 shell 收数据即抛；
  ③ `bytes` / ④ `opsMsg`：`boot.js` 未 import ⇒ 导出 pcap / 列 core dump 回显、运维提示即抛。
- **守护加二层（防复发）**：`web-console-esm-link-check.mjs` 在 LINK（`SourceTextModule.link`）之上新增
  **XREF**——跨模块自由标识符静态核对（行首顶层声明 × 非 import 使用；对象键/方法简写/形参/局部声明/
  数组与对象解构规避；novnc 第三方剔除；兜不住的列 `XREF_ALLOW` 白名单并写明理由）。
  **红-绿验证**：注回 `containers.js` 的 VM_ACTIONS 缺口 ⇒ XREF FAIL 精确点名
  （`views/containers.js -> VM_ACTIONS`）；恢复 ⇒ XREF OK。判别力确证。
- **修复后复扫**：27 路由（**含 vnf-a/ct-web/vs-l2/ens192 四个详情页**）**零 JS 错**。

## §5 教训入册

1. **「对象在场」是黑盒回归的必需分支**：零对象现场对列表/详情/动作面板的**循环体**零覆盖——
   同类拆分缺陷会整批逃过。今后 Web 改动的浏览器回归**必须**在有对象现场（≥1 VM + ≥1 容器 + ≥1 交换机）
   上跑全页扫描。
2. **link() 的守备范围要说清**：它能挡「import 名不存在」，挡不了「用了却没 import」——XREF 二层补位
   （本轮已把该二类盲区都变成自动化守护，且各自带红-绿）。
3. 演示现场的**容器 args 引号**：`set args -c 'sleep 3600'` 的单引号成了字面量（容器 exited）——
   改 `/bin/sleep 3600` 无引号形态；与 #485 round34 的 3 元素写法教训同族。
4. 删对象的 CLI 形态：`delete nat static <in> to <out>`（与 set 镜像全形）；**脚本模式 %% 中止只丢当次会话
   candidate（自动释放）**，重跑整批即可。
