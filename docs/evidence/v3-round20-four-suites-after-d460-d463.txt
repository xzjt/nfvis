## 3. 套件自身留下的现场（跑完必须还原，同 round14 教训）

`cli-fulltest` 的 S2-pre 会改**标量**：`resource-pools hugepages page-size 1G count`（3→2）、
`resource-pools cpu isolated-cores`（2-5→1-4）、`vpp cpu main-core/corelist-workers`；清场**只删对象、
不还原标量**。本轮还原动作（一次提交）：`set … 1G count 3`、`isolated-cores 2-5`、`vpp main-core 2`、
`corelist-workers 3`、`delete interfaces ens224 disable`（清 R8-4 同族残留）。**hugepages 列表顺序**
本轮未被破坏（仍是 `1G, 2M`）——round16 的那次 delete+set 重排仍然有效。

## 4. 现场还原（已核对）

- **1G 池**：套件把它改成 2 后**运行期回不去 3**（`echo 3 > nr_hugepages` 无效，需开机预留）⇒
  按 round14 的同一处置**重启一次**：重启后 `nr=3`、**两个 hugetlbfs 挂载点自动在位**（#459 的
  systemd 挂载单元路径再次被顺带验证）、`show system kernel` 回「一致（无需重启）」。
  重启后按固定动作**重新绑定 DPDK**（两口 `bind-dpdk --yes` + `request vpp restart`）⇒ 两口在 VPP 中 up。
- **管理口地址已还原**（`192.168.155.129/24` + 网关 + ens160）。
- 终态：nfvis/vpp **active**、池 **1G=3 / 2M=768**、isolated **2,3,4,5**（vpp-reserved 2,3）、
  无业务对象、告警仅既有 `HUGEPAGE_POOL_ORPHAN`（2M 无主 14 页）、hugetlbfs 挂载点 **2**。
- ⚠️ 两次重启都会**重生成 SSH host key**（本轮与 round14 各遇到一次）：宿主 known_hosts 需 `ssh-keygen -R`
  刷新，否则 `REMOTE HOST IDENTIFICATION HAS CHANGED`。
