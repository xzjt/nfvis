===== V1 收尾第六十一轮：Web 控制台刀 3b 第二段（配置页扩到系统段 + vpp 段）=====
日期：2026-09-23；分支 cfg-sys-forms；决策 #141 第 3 刀第三段（前两段见 round59/60）

----- 1. 交付 -----
配置页由 13 节扩到 **20~21 节 / 163~180 控件**：系统段 7 节（基础含主机名/时区/DNS/NTP 子表/空闲超时、
API 与 TLS、管理口、内核启动参数、日志、健康阈值、登录与口令策略含本地用户与自定义 class 子表）+ **VPP（数据面）节**
（cpu main-core/corelist-workers/workers-per-numa（后两者互斥本地判）、memory 主堆/每 NUMA buffer/大页偏好、
dpdk 全局队列与描述符 + 单网卡覆盖子表、uio-driver、plugins 开关子表）。全部走既有事务流与同一套表单引擎。

**口令处理（本段的关键设计）**：模型只有 `password_hash`，故明文在**浏览器内**就地派生成与命令行同格式的
PBKDF2-SHA256/60 万轮哈希（盐 16B、密钥 32B、无填充 base64），派生后清空控件；口令策略在派生**之前**按服务端
同一判据本地判；**非安全上下文（明文 HTTP 打开控制台）没有 Web Crypto → 拒绝并说明，绝不退化成明文**。

**顺带修掉 2 个真缺陷**：① `vpp.dpdk.per_dev` 的定位器漏一层 `dpdk`（新增行会写进模型里不存在的
`vpp.per_dev`，静默丢数据）；② 系统段 DNS/NTP 原「两槽位 + 整表替换」会**静默丢掉第 3 条**（NTP 改子表、DNS 改多值）。

**未覆盖（如实登记）**：证书/镜像上传与 `request` 族运维动作（属刀 4 的中危确认范围）、
`interfaces … sriov vf-count`（无硬件，沿用界面暂不提供）、`delete vpp cpu|memory|dpdk` 整组（逐字段清空等价）。

----- 2. 浏览器操作验收（决策 #141 口径）-----
环境：明文开发态实例（该分支构建 + 生产库副本 0.0.0.0:8443）。

| 操作 | 断言 | 结果 |
|---|---|---|
| 打开 #/config → 开始编辑 | **20 节**渲染、**163 个控件**；节名含系统段 7 节与「VPP（数据面）」 | ✓ |
| cross-connect 文案 | 端口直通旁写明「**配对＝该交换机的两个成员端口**（恰好两个，按成员端口顺序直通）——打开前先把这两条成员端口配好」，并带环路警告 | ✓ |
| 改 VPP 节 main-core 5→3 → 保存 → 查看差异 | **`[edit vpp cpu] - main-core 5; + main-core 3;`**（新节写入正确，且以 CLI 语句形式呈现） | ✓ |
| 丢弃并结束编辑 | 退出编辑态（**未提交**，运行配置与 VPP 未触碰） | ✓ |

> **未在浏览器验到（如实登记）**：口令字段的"明文 HTTP 下拒绝派生"口径——探针没能在表单里定位到该控件
> （用户子表可能需要先有用户行，或控件 id 不含 pass/user/pw 字样），故这一条**只有引擎级证据**
> （子代理侧临时 Go 测试：浏览器派生的哈希经 `aaa.VerifyPassword(哈希, 明文)` 通过、严格解析与 `CommitCheck` 零错误），
> **浏览器里没亲眼看过**。补验方法：在 HTTPS（或 localhost）下打开配置页 → 用户子表填口令 → 保存 → 预校验，
> 并另开明文 HTTP 复现拒绝提示。**建议下一刀开头补这一条**。
