§0 结论
- **R142-8 收口**：CLI 会话**在仍存活时**自吊销自己的 token ⇒ 输出如实说明「candidate 已丢弃、编辑锁已
  释放」，同用户新会话**立即**取得编辑锁并提交成功（对照修复前的语义：脏锁以 `admin@ssh#<已吊销 token>`
  继续占着、新会话被挡到空闲回收）。提示语与本地会话态（config 模式）同步收尾。
- **R142-9 收口（旧/新 A/B 实锤）**：
  ① **被拒的 commit 不再隐式确认**——旧版：无锁会话 `POST /configuration/commit` 得 409，却把在途
     `commit confirmed` 确认掉（140s 后 banner 仍在=未回滚）；新版：同样 409，**超时回滚照常发生**
     （140s 后 banner 计数 0）。
  ② **confirm 需持有编辑会话**——旧版：无锁会话 `POST /configuration/commit:confirm` 返回 **200**
     （越权背书）；新版：**409**，confirmed 保持并在超时后回滚（banner 计数 0）。
- 四维齐（REST 层 A/B + CLI pty 自吊销 + 生命周期回滚观测 + 单测红-绿）。

§5 如实边界（入册）
  1. **语义变更点**：跨会话确认不再允许（另一会话/另一接入源不能确认或取消别人的 `commit confirmed`）
     ——与 `Rollback` 同口径；恢复途径是重新进入编辑态后再 `commit`（空候选提交也会隐式确认，
     属 FR-CFG-004 既有语义）。
  2. 校验失败（validation error）的 commit 仍会隐式确认在途 confirmed（FR-CFG-004「任意新 commit
     即确认」的既有语义；本轮只收口「被拒请求」这一条）——如需再收紧另立项。
  3. CLI 自吊销的「新会话立即取锁」观测依赖会话**存活**（pty 驱动）；一次性 `-c` 脚本退出时客户端
     本就走退出清理（#318 路径级释放），两种形态都不再存在「死 token 占锁」。
