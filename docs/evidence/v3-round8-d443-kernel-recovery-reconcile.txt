§0 一句话
---------
内核数据面下这族告警（RECOVERY_UNCONVERGED / RECOVERY_IFACE_MISSING）不再只能等全量重放：
两数据面共用 `network.ReconcileRecoveryAlarmsCore`，15s 巡检按来源廉价复核——来源对象已不在
committed 声明 ⇒ 消解；`interfaces/<n>` 的 IFACE_MISSING 且仍声明 ⇒ 内核侧以「口已出现」
（`ip -d -j link show`）当场消解。真机：**口仍缺时不误清、交还后首个巡检周期内自动消解、
全程无重启**（修复前跨约 21 个周期不消解、必须重启）。

§3 真机验证（换装二进制；内核数据面复现 round7 场景）
-----------------------------------------------------
- 上机：宿主同步源码 → VM 构建 → `install` 覆盖 /usr/bin/{nfvisd,nfvis-cli} → `systemctl restart nfvis`
  （`show version` 1.0.0-dev＝dev 构建，正常；发布件 3.0.8 可用 `/root/rel308/nfvis-v3.0.8.run` 重装）。
- ① **告警仍会落**（切内核 `set system dataplane kernel` + restart，两口仍绑 vfio）：
  `10:23:31` 落两条 error `RECOVERY_IFACE_MISSING`（`interfaces/ens192|ens224`，journal
  「网络恢复收敛未收敛项」同刻在场——此刻告警是对的）。
- ② **不误清**（口仍缺，等 40s ≈ 2+ 个 15s 巡检周期）：`10:24:29` 复核，两条**仍在位**。
- ③ **自动消解**（`10:24:38-39` 交还两口 `unbind-dpdk to-driver vmxnet3`；**不重启**）：
  `10:24:47`（首个巡检周期内）复核 `RECOVERY_IFACE_MISSING` 活动条数 **= 0**；journal 确认
  `10:23:31` 之后无任何重启。对照 round7（修复前）：同事实变化后跨约 21 个周期不消解、
  只能等重启触发全量重放。
  善后现象如实记录：重放未被重新触发时 ens192 保持 admin down，由**既有**独立族告警
  `INTERFACE_LINK_DOWN`（scope=interface-link）如实报出——口径一致（全量重放只在启动/重连），
  非本轮引入、非缺陷。
- ④ **切回 vpp 回归**：`set system dataplane vpp` + restart 窗口重放**零未收敛项**——本次 VPP
  启动即接管两口（内核日志 `10:25:05 vfio-pci 0000:0b:00.0: resetting`＝VPP 已在使用设备；
  对照 round7 同窗口曾落 IFACE_MISSING 后经重放消解＝**子秒级时序差**，两侧 raise/clear 机制
  均未改动）；`bind-dpdk`×2 + `request vpp restart` 后：无告警、`show vpp` connected=yes、
  两口 `dpdk` 在位（ens192 up/up、ens224 down 按配置）——与基线逐项一致。
- ⑤ 环境还原：无对象残留；配置基线逐行一致；告警仅既有 `HUGEPAGE_POOL_ORPHAN`（2M 池无主占用，
