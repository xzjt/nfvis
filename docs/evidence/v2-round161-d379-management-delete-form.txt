§0 结论
- R152-1 收口：`delete system management ip address`（**不带值**）不再报「无匹配配置: ip」，与 `interface`/`gateway`
  的 delete 形态一致（值可省）；`set … ip address` 缺值如实报「缺少取值」。**红-绿**；`make check` 全绿；
  真机 A/B（dev101 复现 → dev102 修复）**候选内**完成、**全程未提交任何管理口改动**（守红线）。

§2 实现（ccbb832）
- `internal/api/cli_aliases_system.go`：新增 **4-token 别名规则** `{"system","management","ip","address"}`——
  delete（`isSet=false`）清 `management.address`；set（`isSet=true`）返回 `缺少取值：set system management
  ip address <prefix>`。既有 5-token 带值规则 `{…,"address","*"}` 不动（`patternMatches` 按长度精确匹配，互不干扰）。
- **根因**：树里 `ip address` 比模型多一层 `ip`（模型是 `management.address`）；别名表只有带值形态，无值形态落回
  通用树遍历去找不存在的 `system.management.ip` ⇒ 报「无匹配配置: ip」。`delete` 分派**先过 `matchAlias`**
  （`cliexec.go:1236`），故补一条 4-token 规则即修好。

§3 测试与红-绿
- `TestCLIManagementIPAddressDeleteValueOptional`：4-token delete 清 `address`；4-token set 报「缺少取值」；
  5-token 带值形态仍能设；`interface` delete 不回归。
- **红-绿**：把 4-token 规则的 pattern 临时改成长度不符（`__red__`）⇒ 用例失败，报
  `命令 "delete system management ip address" 失败: %% 无匹配配置: ip`——**与体检记录逐字一致**；还原即通过。
- 既有 `TestCLIManagementStatements` / `TestCLIManagementIsolationEnforced` 不回归。
