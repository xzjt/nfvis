§1 调查结论：谁留下了那把干净锁
- round98 现场：cli-fulltest 198/0/11 → 195/3/11、语义 12/0/1 → 10/1/1，签名同为
  `%% candidate 会话锁被占用: 由 admin@ssh 持有`；`sessions` 里
  `{holder:"admin@ssh", session_id:"<旧 token>", dirty:false}`。
- 逐条定位（代码路径）：
  ① **`commit and-quit`**（配置模式分支，internal/api/cliexec.go）：提交后把 CLI 本地模式改回
     oper，但**从不释放引擎锁**。客户端 `cli.Session.Teardown` 只在本地模式为 config 时
     discard/exit，于是锁活过整个 CLI 进程。真机 fulltest 的三条失败正紧随 phase6 的
     `commit and-quit` 用例（phase6 第 44~50 行）。
  ② **登出清不掉它**（internal/api/handlers_auth.go 的 handleLogout）：登出请求的会话身份来自
     REST（holder `user@api`），`Engine.Discard` 按会话键 `user@api#<token>` 匹配，而 CLI 锁的键是
     `user@ssh#<token>` —— 两者按身份键是两个。**#317 之前**同一用户下一把 CLI 调用能走
     「同身份键 + 同候选幂等」路径接管该锁，症状被掩盖；**#317 之后**新 token = 新会话键
     ⇒ `ErrLocked`，症状暴露。
  ③ **操作模式 `exit/quit`**（execOper）：只 `delete(x.sess, key)` 清 CLI 本地态，对引擎锁不闻不问。
  ④ **一次性 / 脚本收尾**（`-c`、`-f`、单条命令、REST 一次性事务）在本地模式回到 oper 时，
     同样只依赖 ② 的登出路径，故同样漏（②③ 的公共后果）。
- 结论：「干净锁」（dirty=false）本就没有需要保护的东西，却被当成排他锁挡住后续调用；而释放路径
  又因接入源不匹配而失效——两条叠加即成 R98-1。

§2 口径① - 干净锁不排他（internal/config/engine.go）
- `Engine.Edit`：当既有锁的持有会话候选**无未提交改动**（`lockDirtyLocked` 为假）且**同一用户**时，
  允许**接管**：先 `ReleaseLock(旧)`，`clearLockStateLocked()`，记审计 `config.lock-takeover`
  （detail 含原 holder 与新 holder），再 `AcquireLock(新)`；随后候选置为 committed 副本。
- 边界（逐条有测试）：
  · `dirty=true` 严格排他（`ErrLocked`），R79-1 保护不回归；
  · 仅限同一用户（`userOfHolder(li.Holder) == sess.User`），跨用户仍 `ErrLocked`；
  · 接管不改变 `sessions` 端点可见性与 #317 的会话/身份分离（只是换了持锁会话）；
  · `superseded`（被接管者键 → 接管者键，仅内存态）：被接管者只要面对的仍是那把接管者的锁，
    其 `Edit`（写语句的内部路径）/`UpdateCandidate`/`Commit`/`Release`/`Discard` 一律得到新错误
    `ErrLockLost`（REST 映射 409 CONFLICT），**不静默把现场接管回自己**；接管者释放锁后该记录失效，
    原会话可重新进入。
- `requireHolderLocked`：同用户但非持有者 ⇒ `ErrLockLost`；跨用户 ⇒ 仍 `ErrNotEditing`（不泄露他人）。

§3 口径② - 路径级释放
- `commit and-quit`：仅**提交成功**时退出配置模式并 `Release(本会话)`；提交失败保持配置模式与锁。
- 操作模式 `exit/quit`：`Release(本会话)`（未持锁时忽略）。
- **`Engine.DiscardSession(user, id)`**（新）：结束会话时按**稳定标识**（token ID）清本会话的锁与候选，
  **不区分接入源**；`handleLogout` 与「吊销当前会话」改走它（`api.discardOwnSession`）。
  匹配仍只认本 token：同一用户的另一 token 不受影响（R79-1 不变）；`id==""` 返回 `ErrNotEditing`
  （不当 wildcard）。
- 干净锁更快回收：`sweepLocked` 复用既有空闲巡检，干净锁用 `CleanLockIdleTTL`（默认 1 分钟），
  脏锁仍用 `DefaultLockIdleTTL`（10 分钟）。
