§5 数据面切换 vpp → kernel（带对象切换）
--------------------------------------------------------------------------------
5.1 `set system dataplane kernel` 首次 commit **被三条校验正确拒绝**（逐条给出照做路径）：
    ① `vrfs[vs-nat].l3_interfaces[vh-vnf-a-nic1]`：内核侧不存在该 vNIC 派生设备名
       （**R24-C 的缺口已修**，[#469]）；
    ② `virtual_machine_functions[vnf-a].interfaces[nic1].virtual_switch`：VNF 虚拟网卡不能接入
       type=l3 的交换机（内核侧 L3 不建桥，tap 无处可挂）；
    ③ `nat.rules[10]`：内核侧 NAT 不支持跨转发域（[#419]）。
    删除 nat 规则 + nic1 + vs-nat → **rev 26**；再 `set system dataplane kernel` → **rev 27**；
    `systemctl restart nfvis` → **VPP 被 nfvisd 自动停掉**（inactive），`show vpp` 如实报
    「当前数据面为 Linux 内核网络，未使用 VPP」。

【本轮抓到并已修复：R37-1（高）】
  （编号消歧：本条是 **v3 线 round37** 的 R37-1；**v1 线另有一个同名 R37-1**（契约↔实现响应形状
  不符，见 `docs/V1-收尾待办.md`），两者不同事、不同线。）
  **现象（用户报）**：Web 控制台里**所有「详情」都点不开**——点列表行的「详情」按钮或整行，页面
  毫无反应、无任何提示。
  **定位（代码级）**：`internal/api/ui/js/core/dom.js` 的 `goDetail()` 写的是
  `import('../router.js')`。本文件在 `ui/js/core/` 下，`../router.js` 解析到 **`ui/js/router.js`**，
  而 `router.js` 实际在 **`ui/` 根**（`ui/js/views/*` 与 `ui/js/boot.js` 用的都是正确深度）。该
  动态 import 因此 404（`TypeError: Failed to fetch dynamically imported module:
  …/api/v1/ui/js/router.js`），`goDetail` 的 promise 被静默拒绝 ⇒ 按钮与行点击全死。
  **真机取证（浏览器）**：注入 `unhandledrejection` 收集器后点「详情」——`location.hash` 不变、
  捕获到上面那条 TypeError；而**直接改 hash**（`#/network/vrfs/vs-wan`）能正常进详情页
  （那条路走的是 app.js 的**静态** import，一直是好的）——这正是历次走查漏掉它的原因：
  **零对象/纯 hash 扫描覆盖不到按钮路径**。
  **影响面**：`goDetail` 是**全站唯一的详情跳转入口**（`rowClickable()` 行点击 + 各列表页的
  「详情」按钮都走它）——VM/容器/镜像/交换机/网络对象/接口等**所有**详情入口同时失效。
  **引入版本**：v3.0.19 Web 重构（app.js 按域拆分）——`js/core/dom.js` 的深度写错一层。
  **修复**：`import('../router.js')` → `import('../../router.js')`（一行）。
  **守护（三层补齐）**：`contrib/scripts/web-console-esm-link-check.mjs` 新增 **DYN** 层——把
  每个**动态** `import()` 的相对说明符按文件所在目录解析、断言目标存在（LINK 的
  `SourceTextModule.link()` **只解析静态 import**，动态 import 它一概看不见——本缺陷正是从
  这个盲区穿过去的；XREF 只管自由标识符，也挡不住）。**红-绿验证**：注回 `../router.js` ⇒
  `DYN FAIL js/core/dom.js -> ../router.js（解析到 js/router.js，该文件不存在）`；恢复 ⇒ `DYN OK`。
  **真机复验（3.0.21~dev1 交叉编译换装，见 §9）**：真实点击列表行 → `#/compute/vms/vnf-a` 详情页
  正常渲染；「详情」按钮（网络对象页 → `#/network/vrfs/vs-wan`、镜像页 →
  `#/compute/images/alpine.qcow2`）同样正常；`unhandledrejection` 不再出现。
  **教益**：**静态扫描 + hash 直连覆盖不了「按钮/行点击」这条交互路径**——黑盒回归必须**真的点**
  至少一个详情入口（与 round36「零对象现场覆盖不到循环体」同族：**判据的覆盖面**要跟着
  代码路径走，不是跟着路由数走）。
