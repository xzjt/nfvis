------ 0. 结论 -----
- 按待办 §0 第 6 条，用本机已启用的 **Browser Use 插件**（技能 control-browser / web-gui-tester，
  浏览器操作经 `mcp__node_repl__js`，后端 ZCode 内嵌 IAB）对 round37 的 Web 控制台做**可视验收**。
  手法为黑盒：只点可见元素、**不注入 JS 改页面状态**、每个测试点**截图 + 只读 DOM 双向印证**。
- **发现并修复三处缺陷**（决策 #117）：
  ① **CSS `hidden` 属性被作者样式覆盖**——`.login-wrap { display: flex }` 优先于 UA 的
     `[hidden] { display: none }`，**登录后登录卡片不消失、盖住总览页**（已登录会话仍显示登录表单）；
  ② **`POST /login` 响应形状漂移**（与 R37-1 同类但出在 `/login`）——契约 `LoginResponse.user`
     是**对象** `LoginUser`（name/class），实现回的却是扁平字符串 + 顶层 `class`（顶层 class 根本
     不在契约里），照契约写的前端顶栏显示 **"undefined（undefined）"**；
  ③ **`/system/status.uptime_seconds` 语义不符**——取的是守护进程运行时长，而契约描述与 CLI
     `show system uptime` 都是**主机**运行时长（/proc/uptime），页面"运行时长"显示守护进程活了多久。
- 为什么此前没发现：形状守护（决策 #116）只覆盖四个 GET 端点、**不含 POST /login**；CSS 行为
  任何 Go 测试都看不到。"已交付但没人眼看过"的界面，验收不算完——本轮即是例证。
- R37-2 的两处"空"（6 个组件版本空串、开发态实例无 VNF/容器）按既有登记**不当缺陷**；
  `hostname` 未配置时为空串也是形状守护白名单里写明理由的有意行为（不退回内核 hostname）。

------ 2. 可视验收发现的三处缺陷（首轮，对 eb63f2e 构建） -----
| # | 缺陷 | 证据（截图 + 只读 DOM） | 严重度 |
|---|---|---|---|
| 1 | 登录后登录卡片不消失、盖住总览页 | DOM：`login-view.hidden === true` 但**截图里登录卡片仍在**（`display:flex` 压过 UA `[hidden]`）；整页截图出现登录卡片重复平铺；滚到下方才能看到总览各卡 | 高（控制台登录后不可用） |
| 2 | 顶栏用户行显示 `undefined（undefined）` | DOM：`user-line` 文本 = "undefined（undefined）"；API 实测登录响应 `"user":"admin","class":"super-user"`（扁平）而契约是 `user: {name,class}` 对象 | 高（明显破版） |
| 3 | "运行时长"显示守护进程活了多久 | DOM：总览"运行时长 0 小时 5 分"，而 VM `uptime` 已 8h56m；API `uptime_seconds` = `time.Since(startTime)`，CLI `show system uptime` 取 `/proc/uptime` | 中（数据误导） |
