§5 成员枚举口径（本条核心）
- S8 取成员的**唯一正源 = 产品读视图** `show virtual-switches <vs> ports`
  （与 REST `GET /virtual-switches/{n}/ports` 同源；#326 起含 source=config|vnf|container|runtime）。
- 再用 `vppctl show bridge-domain <BD-ID> detail` 的成员表**双向印证**：
  **VPP 有而读视图没有 ⇒ 直接报失败行**（读视图应含运行态成员），不静默取其一。
  真机同一时刻两侧一致：读视图 `[vh-sem-vm-nic0 bvi0]`、VPP `[bvi0 vh-sem-vm-nic0]`。

§6 同批修掉的两处 oracle 缺陷（都会「有证据却报没有」）
(a) `vpp_if_rx` 认错列 ⇒ **任何口的 rx 恒得 0**。VPP 把 `rx packets` 打在**接口名下那一行**
    （`<名> <idx> <state> <mtu> rx packets <n>`，rx 在第 5 列），只有 `rx bytes/drops/ip4` 才是缩进续行；
    旧实现按 `$1=="rx" && $2=="packets"` 认行 ⇒ 永远匹配不到 `rx packets`。
    真机取证（单口查询原样）：
        vppctl show interface vh-sem-vm-nic0
                      Name               Idx    State  MTU (L3/IP4/IP6/MPLS)     Counter          Count
        vh-sem-vm-nic0                    5      up          9000/0/0/0     rx packets                   202
                                                                           rx bytes                   21101
    这正是 r106 报告「有 rx 计数的成员:（无）」的真因之一。修为「在本口输出里找相邻两列 rx packets，取其后一列」。
(b) 成员表查询把 **Index 当 BD-ID** ⇒ `vppctl show bridge-domain <参数>` 只认 BD-ID
    （本机 `sem-vs`：BD-ID=314680、Index=1）⇒ `show bridge-domain 1` 报 "No such bridge domain 1"、
    **成员表恒空**（r106 报告「成员:（空）」的另一真因）。新增 `vpp_bd_id_of_tag`（与
    `cli-lifecycle-check.sh` 同口径——那边早修过同族缺陷并写明）；成员表一律吃 BD-ID，l2fib 过滤仍用 Index。
    真机取证：
        vppctl show bridge-domain 1 detail        → show bridge-domain: No such bridge domain 1
        vppctl show bridge-domain 314680 detail   → 成员表含 bvi0、vh-sem-vm-nic0

§7 判定语义（未放宽；只把「该对端 MAC」改为「成员口学到的 MAC」）
- 正控 = **成员口 rx 在 3s 窗口内增长**（本次 ping 的应答，或既有业务流量穿过该交换机皆可）。
- 有正控 ⇒ 要求 l2fib 有**成员口学到的 MAC**（`vpp_l2fib_learned` 按 verbose 表 `static`/`bvi`
  标志列排除 BVI 合成 MAC `b0:b0:…` 与静态条目）且与 CLI mac-table 条数一致；
  没学到、或条数不一致 ⇒ FAIL。
- 无正控（无成员 / 无对端且无流量 / 有成员但窗口内无帧）⇒ **UNKNOWN**（三档语义不变，见 §4 反证）。

§8 自校准（make check 的 toolcheck，桩式、CI 可跑）
`bash contrib/scripts/cli-semantic-selftest.sh` 新增 5 条断言（全部 ✓）：
- 读视图成员枚举含派生条目、跳表头与「（来源 …）」说明行；空读视图得空集；
- l2fib 学习条目只留非 static、非 BVI（两个 BD 过滤各一条）；
- `vpp_bd_id_of_tag` 与 Index 不同（vs-vnf 的 BD-ID=6252701）、tag 不存在得空；
- 成员口 rx：rx packets 在**接口名下那行**（ens192→189、只有 tx 的口→0、不存在→0）；
- S8 判定三档（含「旧行为此处判 PASS」的红-绿：空结果不得 PASS）。

§9 环境观察（如实登记，非本条引入）
① 内存必须用 **1G 大页**：本机 `/dev/hugepages` 以 `pagesize=1024M` 挂载，2M 大页**无挂载点**，
   libvirt 以 `定义 domain 失败: invalid argument` 拒绝定义 domain（1G/1024MB 才成）。
② **libvirtd 重启而 nfvisd 未重启**时定义 VNF 同样报该 `invalid argument`（nfvisd 缓存的 libvirt
   连接失效）；`systemctl restart nfvis` 后即刻成功。两条都写进前置脚本头部。
③ Alpine 云镜像在本环境**未应用** user-data（guest 无静态地址、无 ping 循环）；其内核 isofs 只作为
   模块存在、镜像无 udev 自动加载，NoCloud 的 iso9660 seed 未挂上（诊断到此，未再深挖）——
   故前置脚本缺省用 Debian 12 cloud image（真机证明可读 seed）。

§11 方法学（本轮新增一条）
- **判据错与实现错一样会毁掉信任**：S8 报「不可判定」时，先查的是**套件自己的两个 oracle**
  （rx 认错列、成员表喂错 ID）——它们让「有证据」的现场看起来「什么都没有」。修 oracle 与修实现
  必须一起做，且 oracle 的错法要进**桩式自校准**（§8），否则同样的假红会再回来。
