===== V1 收尾第七十七轮：一次性事务提交后交还全局编辑锁（决策 #151）=====
日期：2026-09-24；分支 `fix/one-shot-lock-release`（main `adcb83e` 之上）
范围：交接文档 §2.3 登记项「`login-users` 写路径提交后仍持有全局编辑锁」
（round72 验收首次查出、round76 校验**三次复现**、round76 证据 §5「仍未裁」第 1 条）。

----- 1. 起因与交付 -----
起因：用 REST（如 `POST /system/login-users` 带 `X-NFVIS-Auto-Commit: true`）建完账号的会话**没登出**，
随后任何其它会话的配置写（CLI `configure`、删账号、**自助改密**）都被
`409 CONFLICT candidate 会话锁被占用: 由 X 持有` 挡住，直到该会话 `POST /logout`（决策 #119）
或空闲超时（`lockIdleTTL`）。round76 的发布校验脚本为此**三次**改道（补跑 G3/G4 只能先登出）。

根因：`Engine.Commit` **不释放**锁（只有 `Release`/`Discard`/空闲超时释放）；控制台**配置页**是
**客户端**显式收尾（`internal/api/ui/app.js` 的 `cfgEndSession()`），而「取锁 → 写候选 → **立即提交**」
这类**一次性事务**服务端没有收尾。

----- 2. 助手语义（`endOneShot`，判据只有一条：**候选不脏才释放**）-----
- 提交成功（候选已清空）→ **释放**；
- 写候选**之前**就失败（校验 400/409、`UpdateCandidate` 失败）→ 候选没动过 → **也释放**（留着锁只会挡住别人）；
- **候选脏 → 不释放**：那是操作者的未提交改动，不能替它丢掉（与配置页同款语义）；
- **提交因校验失败（`ErrValidation`，候选保留）→ 不释放**：操作者要接着改。
调用方须已成功 `Edit`（本会话持锁）；未持锁时 `Candidate` 返回 `ErrNotEditing`，助手静默返回——
不替别的会话、也不替已交还的会话收尾。释放失败只记一条日志（REST 侧 `s.log`；CLI 侧无 logger 传 nil）。

----- 4. 真机复验（**留给主会话**，本会话未碰真机/VM）-----
建议步骤（nfvis 1.1.33 待发布件或开发态实例；独立事实源＝`GET /system/configuration/sessions`）：
1. 取 admin token：`POST /api/v1/login`（口令按交接 §3.1 哈希比对法核对后再用）。
2. `POST /api/v1/system/login-users`（body `{"name":"lock77","kind":"user","password":"…","class":"operator"}`，
   不带 Auto-Commit 头——该族恒提交）→ 断言 **201**；随后 `GET /system/configuration/sessions`
   **不含 `admin@api`**（改前：含）。
3. 同一 token 直接 `POST /api/v1/system/login-users` 再建一个 / 或 `DELETE` 掉 lock77 → 断言成功（不被自己的锁挡）；
   再换 **CLI/ssh 会话**执行 `configure` → 断言**不报**「candidate 会话锁被占用」（改前必报，round76 三次复现即此）。
4. 反向复验（语义未被改坏）：`PUT /configuration/candidate`（**不带** Auto-Commit 头）→ `sessions` **仍含**
   `admin@api` 且 `dirty=true`；再 `POST /configuration/commit` → 锁**仍在**，`DELETE /configuration/candidate` 后消失。
5. 控制台回归（浏览器黑盒）：配置页「保存到 candidate → 提交」照旧生效并在提交后释放锁（页面提示「提交成功」，
   `sessions` 空）；「用户与权限」页建/删用户后 `sessions` 立即为空。
6. 收尾：删掉复验用的账号、`show log audit last 20` 确认审计成对（决策 #150 口径未被破坏）。
