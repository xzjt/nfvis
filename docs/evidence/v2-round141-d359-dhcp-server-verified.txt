§2 四维覆盖
2.1 作用效果（真客户端 DORA）
- 启用 `set virtual-switches sem-vs dhcp-server pool 192.168.99.100 192.168.99.110` +
  `lease-time 300`（rev 1485）→ 内置 tap 建成（VPP 侧 tap0 idx 6 **up**、内核侧 `nfvisdhe80e75a8`
  15 字符、入 BD 314680）、punt 注册 UDP/67 → `/run/vpp/nfvis-dhcp.sock`。
- guest 启动后 **完整 DORA**（tap sniffer 逐帧可见 DISCOVER→OFFER→REQUEST→ACK）→
  **`LEASED 192.168.99.100`**；租约表 `192.168.99.100 52:54:42:e6:31:0d active`（剩余秒数递减）。
- 读视图三面同源：CLI detail 的「DHCP 服务器」块（池/租约时长/DNS=缺省 BVI/在租数）＝
  REST `GET /virtual-switches/sem-vs` 的 `dhcp_server`（逐字段同契约）＝Web 详情页同块；
  租约三面同值；**内置 tap 不出现在端口读视图**（CLI ports / REST / Web 均按产品自持
  sw_if_index 过滤——实测 foreign 成员口照常显示、仅产品 tap 被滤）。
- 双向连通：`ping 192.168.99.100 vrf vr-sem-vs` **5/5 0%**（网关↔租约地址，ARP 正常解析）。
- 双客户端并存：guest（vhost 口，99.100）+ 注入客户端（第二 tap，99.105）同表各自 active。

2.2 生命周期
- **`request vpp restart`** → tap/punt 注册全失后**自动重建**（恢复重放按 HostIfName 复用/重建），
  租约文件保留、客户端续租在重建后照常被应答（租约到期时间持续刷新）。
- **`systemctl restart nfvis`** → 同样自愈：tap 按 HostIfName 复用（不重复建）、punt 重申、
  租约从 `/var/lib/nfvis/dhcp/sem-vs.json`（0600/原子写）恢复，续租不断。
- **停用/删除清理**：`delete virtual-switches sem-vs dhcp-server`（rev 1497）→ VPP 与内核侧
  tap 消失、租约文件删除、端口视图无残留、CLI 报「未配置 DHCP 服务器（set … 启用）」、
  REST `GET …/dhcp-leases` **409**（契约口径：空数组会误导）。
- **重新启用不重启客户端**：server 回来后 guest 的下一次广播续租即被应答、租约恢复（rev 1498）。
- **R140-1 回归**：`relay 配过又删（rev 1490/1491）→ 再启用 server（rev 1492）` 后，以太单播
  REQUEST（真实续租形态：src=租约地址 → BVI:67）经 punt 被应答（ACK 可观测）——server 的
  每次 Sync 重申注册（deregister+register）兑现。对照注入：relay 在位的域里单播请求不被
  server 应答（proxy 拦截），与 spike 结论一致。
- **环境顺带验证**：本轮机器发生一次整机重启（SSH 主机指纹变更、sem-vm shutoff）——
  重启后四服务 active、恢复收敛完成日志在场（#348/#351/#354 链路再次自证）；
  sem-vm 未自启是因为夹具未声明 autostart（#348 文档化行为，非缺陷）。

2.3 跨对象组合
- 同一交换机多客户端（vhost VNF + 第二 tap 注入客户端）各自取租约、互不串址（同 MAC 优先
  续用、异 MAC 最小可用）。
- 与 DNS 代理（#345）组合：option 6 缺省下发 BVI 地址后，guest 的 resolver 查询经 punt 到
  nfvisd 转发器（`ip4-udp-punt-socket Socket TX` 持续增长即其痕迹）。
- 容器侧如实登记：**受 T0-3（离线无自带 memif 客户端的镜像）限制，容器经 memif vNIC 取
  DHCP 租约未验**——与既有「容器 memif 通流未验」同一口径，非本决策引入。

2.4 对抗性

§3 实测发现与修正
1. **一 REQUEST 两 ACK（已修，dev70）**：同一条客户端广播报文经「BD 洪泛到内置 tap」与「经 BVI
   进 UDP/67 的 punt」各达一次 → 服务器应答两次（tap sniffer 同 xid 可见两条 ACK）。修法：按
   (chaddr, xid, 消息类型) 的 **3s 去重窗**只应答一次（窗长远小于 RFC 2131 重传退避 ≥4s，
   不吞真重传；决策行已补记该口径）；dev70 复验一 REQUEST 一 ACK。单测
   `TestDHCPServerDedupeDualPath`；测试帧的 xid 改为逐帧递增（真实客户端语义）。
2. 池校验文案「包含BVI」→「包含 BVI」（空格，dev70）。
3. 观察项（不改行为，如实登记）：MAC 学习表里经内置 tap 学到的表项如实显示 `tapN`（真实
   运行态事实，不过滤）；`expires_in_seconds` 显示下限钳 1（表内条目不显示 0）；OFFER 保持
   时长 2 分钟（代码常量，非配置项）；foreign 成员口（非产品 tap）照常在端口视图显示。
4. **lifecycle L2-3「查不了」变体漏网（工具假红，已修）**：round139 的修复只认字面
   `VPP 未连接`，而本轮现场是 API 通道写失败
   （`unable to process request: write unix @->/run/vpp/api.sock: write: broken pipe`）——
   VPP 重启窗口内 15s 巡检打出的三条被算成「查到残渣」⇒ 干净现场偶发假红（首跑 21/1/3）。
   修法：判据抽为 `l23_kind`（按**传输层失败签名**分类：`VPP 未连接|connection refused|broken pipe|
   transport is closing|connection reset|no such file or directory|i/o timeout|EOF`）；
   新增 `--selftest` 合成输入自校准（4 例：仅查不了⇒0 判定 / broken pipe 变体⇒0 判定 /
   真残渣⇒1 判定 / 混合⇒分列），并挂进 `make check` 的 toolcheck（`make toolcheck`）。
   复跑 lifecycle **23/0/2**、与基线一致。
