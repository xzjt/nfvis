----- 0. 起因（交接文档 §0 第 1 项 / §2.9 #10）-----
报错原文（真机复现，见 §1）：
  % 登录失败: 连接 nfvisd 失败: Post "https://127.0.0.1:443/api/v1/login":
    tls: failed to verify certificate: x509: cannot validate certificate for 127.0.0.1
    because it doesn't contain any IP SANs
CLI 的缺省连接是 https://127.0.0.1:443 且以服务端证书为信任锚做**完整主机名校验**（决策 #78），
故证书一旦少了回环 IP SAN，「重签」这个动作本身就掐断了唯一的零配置管理通道。

----- 2. 单测红-绿（先写失败测试，再改代码）-----
新增 internal/api/tls_san_test.go：以**重签出的证书自身**为信任锚请求 https://127.0.0.1
（与 nfvis-cli 同一条校验路径），断言口径是契约语义「重签后 CLI 还连得上吗」，不是 SAN 列表长相。
修前：
--- FAIL: TestCLIRegenerateKeepsLoopbackSAN
    [CLI] 重签后的证书应仍可用于 CLI 缺省连接（127.0.0.1），实际校验失败:
      x509: cannot validate certificate for 127.0.0.1 because it doesn't contain any IP SANs
--- FAIL: TestRESTRegenerateKeepsLoopbackSAN
    [REST] … x509: certificate is valid for …, 192.168.1.7, not 127.0.0.1
修后：ok github.com/xzjt/nfvis/internal/api / ok github.com/xzjt/nfvis/internal/system
**顺带更正交接文档的一处表述**：REST 路径原先**也不对**——`localIPs()` 只收**非回环**地址，
重签出的证书同样不含 127.0.0.1（上面的 REST 断言即证明），并非「REST 对、只有 CLI 错」。

----- 3. 改法（决策 #99）-----
- `system.ServerCertSANs(listen)` = ListenSANs（**始终含** 127.0.0.1/::1 与监听地址）
  ∪ `LocalIPs()`（本机各接口地址），经 SortedIPs 去重排序；
- `TLSManager.SetListen(addr)` 记录实际监听地址；新增 `RegenerateSelfSigned(hostname)`，
  SAN 由**管理端自己**推导；
- `api.TlsRuntime` 接口**不再暴露带 `ips` 的 Regenerate**（REST/CLI 调用方没有机会漏传），
  旧的带 ips 版本收为包内 `regenerate` 只作原语；
- 四处调用同源：启动期 EnsureSelfSigned、REST handler、CLI 执行器、applyTLSSettings。
