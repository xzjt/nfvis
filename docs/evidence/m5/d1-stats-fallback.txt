----- 5. ACL 命中计数：不可落地（正式降 V2 的依据）-----
VPP 26.06 消息表（vppctl show api message-table）：
  107  acl_del          108  acl_del_reply
  135  acl_stats_intf_counters_enable        136  acl_stats_intf_counters_enable_reply

govpp 解析（conn.GetMessageID，均 err=nil）：
  acl_del                            crc=ef34fea4 -> ID=107
  acl_del_reply                      crc=e8d4e804 -> ID=108
  acl_stats_intf_counters_enable     crc=b3e225d2 -> ID=135
  acl_stats_intf_counters_enable_reply crc=e8d4e804 -> ID=136
  ↑ 两个应答 CRC 相同（e8d4e804，均为仅含 retval 的应答）

调用 acl_stats_intf_counters_enable(Enable=true) 的实测结果：
  retval=0 err=received unexpected message (seqNum=1), expected
  acl_stats_intf_counters_enable_reply (ID 136), but got acl_del_reply_e8d4e804 (ID 108)
  （在全新通道上作为**第一条**请求即复现，非排队/陈旧应答问题）
  → 请求被 VPP 当作 acl_del(107) 执行：**不仅无效，且可能误删 ACL**，故不接线。

基础 ACL 下发本身可用（同一探针，真机）：
  create loopback            sw_if_index=3 retval=0
  acl_add_replace            idx=0 retval=0 err=<nil>
  acl_interface_set_acl_list retval=0 err=<nil>

绑定后 stats 段 ACL 相关路径：
  仅 /err/acl-plugin-*（错误计数，默认存在，如 2:0:0:0:/err/acl-plugin-in-ip4-l2/ACL deny packets）
  **无** /acl-plugin/<ACL名>/... 逐规则命中计数（共 122 行全为 /err/ 前缀）
