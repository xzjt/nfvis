===== V1 收尾第七十五轮：高危档动作的审计记「意图 + 结果」两条（决策 #150）=====
日期：2026-09-24；分支 `feat/audit-intent-result`（main `f7c441b` 之上）
范围：设计文档 §7 的高危档审计口径 —— 交接文档「仍未裁」第 ④ 条（round64/65/67/70/71 五次登记）。

----- 1. 起因与交付 -----
起因：设计 §7 要求高危档动作「审计记『意图』与『结果』两条」，而服务端**只写一条结果行**：
round65 的浏览器验收（建/删用户）实测审计里只落一条 `config.commit`（detail 是 diff），
界面侧无从补——「动作已开始」这件事服务端根本没记；**中途崩溃/被杀**的破坏性动作更是什么都不留。

1.1 先查证：高危动作 × 现在写几条 × 写在哪（**裁决与实现的依据**）

| 设计 §7 高危档动作 | 服务端入口（CLI / REST） | 现在写几条（改前） | 写在哪个实现里 |
|---|---|---|---|
| 恢复出厂 | `request system zeroize` / `POST /system:zeroize` | **1**（仅成功；失败**不写**） | `cli_compute_oper.go` `systemZeroize` / `system_ops.go` `handleZeroize` |
| 软件升级 | `request system software add` / `POST /system/software` | 1（成功/失败各一） | `cli_compute_oper.go` `systemSoftware` / `system_sw.go` `handlePostSoftware` |
| 软件回退 | `request system software rollback` / `POST /system/software:rollback` | 1 | 同上 |
| 恢复配置 | `request system configuration restore <path>` / `POST /system/restore` | CLI 1；**REST 仅成功 1、失败 0** | `cli_compute_oper.go` `systemRestore` / `system_ops.go` `handleRestore` |
| 证书上传 | （CLI 无 PEM 直传：`set system api tls cert-file …` + `commit`）/ `PUT /system/tls` | REST 仅成功 1、失败 0；CLI 走配置提交 → 1 条 `config.commit` | `tls.go` `handlePutTLS` / `cmd/nfvisd/main.go` `applyTLSSettings`（提交时按配置安装） |

1.3 口径（决策 #150 的正文，摘要）

- **`action` 不变**（不新增动作分类：界面审计页与 `show log audit` 都逐字打印 Result 列，无需新映射），
  用 `result` 区分三态：**`intent`**（动作开始执行**之前**落库）/ `success` / `failure`（动作结束后落库，失败写原因）。
  两条 `action` 相同、按时间配对；`show log audit` 里只看得到 `intent` 而无结果 ⇒ 该动作没走完。
- 意图行位置：**下发底座之前**，但在**校验与 confirm 守卫之后**——那些是「没开始动作」的拒绝，不该留意图。
- **同源**：直接动作用 `internal/api` 的 `runHighRisk`（REST handler 与 CLI 执行器都调它，意图文案同一份构造器）；
  配置事务型变更没有独立动作入口（CLI 的 `delete system login user x` 只改 candidate，动作发生在 `commit`），
  故由 `internal/config` 在 `Engine.Commit` 按**差异**判定——CLI 与 REST 都汇到它，不存在两个入口各写一遍。
- **只覆盖高危档**（＝控制台 `tier:'high'` 那批），其余动作仍是一条（防审计噪音）；
  恢复出厂/恢复配置**各只记一对**（它们提交的空配置/归档配置会连带改掉本地用户，引擎按会话来源跳过二次判定）；
  被前置拒绝的请求（`confirm=false`、没给确认词、参数不全、读不到归档）**不落审计**（动作没开始，与既有口径一致）。
- **脱敏沿用既有口径**：意图 detail 只写人话 + 关键参数；重置口令写「值 «已隐藏»」（`model.RedactedPlaceholder`）、
  sha256 只取前 12 位、PEM 正文与私钥一律不进审计（FR-SEC-007）。

----- 3. 真机复验（**由主会话执行**：nfvis-vm 上的开发态实例 + 生产库副本）-----
环境：本分支构建的实例（明文 + `-allow-plaintext`，或 HTTPS 带 `--cacert` 的既有探针口径）+ 生产库副本，
操作者 = super-user（admin）。**独立事实源**：配置库 `audit_log` 表原文 + CLI `show log audit last 20`
（两者同源：`Engine.AuditTrail` ↔ `GET /audit-logs`）。

| 步骤 | 命令（真机） | 断言 | 独立事实源 |
|---|---|---|---|
| ① 高危**成功**路径两条 | `request system configuration restore <归档路径>`（或界面「恢复配置」） | 该 action 出现两条：`Result=intent`（detail「从备份归档恢复配置（<路径>）：归档里的配置将替换当前配置」）在前、`Result=success`（「已恢复配置（revision N…）」）在后 | `show log audit last 20` 原文 + `sqlite3 /var/lib/nfvis/nfvis.db "select result,action,substr(detail,1,40) from audit_log order by audit_id desc limit 4"` |
| ② 高危**失败**路径两条 | `request system configuration restore /no/such.json`（**前置拒绝**：0 条）→ 再喂一个**坏归档**（合法路径、内容非归档） | 前者审计**0 条**；后者两条、结果行 `Result=failure` 且 detail 带原因 | 同上（`audit_log` 行数前后差 = 0 / 2） |
| ③ 配置事务型（删用户） | CLI `delete system login user <临时账号>` + `commit`（先 `set … password … class operator` 建一个临时账号） | 建/删各两条：intent 行 detail「创建本地用户 X（权限类 operator）」/「删除本地用户 X（原权限类 operator）」，结果行 detail 仍是既有 diff | `show log audit last 20` + 配置库 `config_json`（临时账号真的没了）；**审计里不得出现 `pbkdf2$`** |
| ④ 非高危仍是一条 | `set system hostname <新名>` + `commit` | 该提交**只有一条** `config.commit`（`Result=success`，detail 是 diff） | `audit_log` 行数前后差 = 1 |
| ⑤ 界面侧对照（可选） | 控制台「审计日志」页刷新 | 高危动作那两条在页面「结果」列显示 `intent` / `success`；`#/system/users` 删用户后同样两条 | 页面 DOM 快照 + ①~③ 的库侧原文（决策 #141：界面显示对了不算完） |

**收尾**：临时账号、临时归档与开发态库副本用完即删；生产库除本轮动作外不得有其它改动
（核对 `rev`/`audit` 计数与 `config_json` 指纹）。

----- 4. 存疑 / 未做（如实登记）-----
- **CLI 的「证书上传」与 REST 的证书上传机制不同**：REST 是 `PUT /system/tls` 直传 PEM（操作级助手记两条，
  action=`system.tls.install`）；CLI 只有 `set system api tls cert-file … key-file …`（配置引用，提交时由
  nfvisd 按配置安装），它记的是 `config.commit` 的两条。**两条路径的 action 名因此不同**——机制本就不同
  （一个是上传正文、一个是声明文件路径），已在决策 #150 与 `internal/api/audit_highrisk.go` 的注释里写明。
- **意图行与动作之间不是事务**：意图先落库、动作后执行（这是设计要求的顺序）；若动作**崩溃**在中间，
  审计里会留下一条 `intent` 而**没有**结果行——这正是「只看得到 intent 即说明没走完」的读法，
  不额外补偿（补偿会把「崩溃」这一事实掩盖掉）。
