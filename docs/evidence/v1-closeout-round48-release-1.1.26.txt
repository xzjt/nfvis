----- 7. 发布件重切（R48-5；照 round29 的先例）-----
**为什么重切**：发布校验时顺带核对「随包文档是否为当前版本」，发现 **round43~47 只更新了契约/
测试/证据，没有同步用户手册**——§10.12 的标题与正文都还写着「Web 界面（只读总览）」
「**只是只读视图**：本页面不修改任何配置」，而 v1.1.26 的控制台**能改配置（candidate → 差异 →
预校验 → 提交/丢弃）与做诊断（ping / 服务端日志）**。手册随 deb 发布 ⇒ 发布件里有一句与自身功能
相反的错述。故：**修手册 → 合并 → 用新 main 重切发布件**（round29 对"发布当日手册变更"的先例）。

**重切步骤与证据**：
1. 修 `docs/NFViS-用户手册.md` §10.12（重写为「Web 控制台（总览 / 配置 / 诊断）」，按界面上
   **真实存在的按钮**写，写明管理口变更须两步确认、提交/丢弃都释放编辑锁，并列出界面上还没有的
   能力）+ 交接文档 §1.1 交付物表同步 + 登记 R48-5；`make check` 全绿（手册受 `user_text` 守护）；
   经 PR #156 合并 → main `46f0180`。
2. `make deb VERSION=1.1.26 SOURCE_DATE_EPOCH=1790088035` → **1f8799ff…**（7,829,582 字节）。
3. **逐文件对照首切件**（`dpkg-deb -x` 后对每个文件算 sha256 再 diff）：
   - 内容差异**只有一行**：`usr/share/doc/nfvis/NFViS-用户手册.md`
   - `usr/bin/nfvisd` = `8e2178a170f7feb0…`、`usr/bin/nfvis-cli` = `8685864d6622c51c…`
     **两次构建逐字节相同**；`nfvis.service`、两个安装器脚本、`control`/`postinst`/`prerm`/`postrm`
     全部相同；其余随包文档（规格书/命令树/命令全表/OpenAPI/M5 验收记录）全部相同
   ⇒ **首切件的实装 / purge / 重装 / 拓扑收敛 / 流量复通结论对重切件同样成立**（代码与控制脚本
     一个字节都没变），故未重复跑装机链路。
4. 删除首切 release 与 tag、用重切件重建（tag 仍指 `main`，非 draft/prerelease）；
   回下载 sha256 与构建端一致（1f8799ff…）；期间修正过一次 asset 命名（首传带上了 `.recut` 后缀）。
   tag 最终指向重切件的构建提交 `46f0180`（"哈希可用于溯源这份包出自该 commit"因此仍然成立）。
5. **重切件也实装到目标机**（`dpkg -i` 升级路径，同版本、仅随包文档不同）：服务 active、
   `nfvisd`/`nfvis-cli` = 1.1.26、**配置库未变**（rev 55 / audit 103 / cfgsha 084c3a64…）、
   已装手册 §10.12 为新版（「只读视图」0 处）、流量复通（BVI ping 双向 5/5 0% 丢包，
   `vppctl ping` 独立源 3/3；宿主经 DPDK 物理口 3/3、0.42~0.66ms）——即**目标机上的随包文档
   与发布件一致**（round48 收尾态）。

**结论**：v1.1.26 的发布件现在与它自己描述的功能一致；两次构建的差异可被逐文件复算复核。
