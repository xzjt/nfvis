------ 0. 结论 -----
本刀把增量 2（Web 控制面配置读写）的三块前置一次收口：

1. **新增 `GET /configuration`**（round42 缺口 #1）：返回 `{configuration, revision}`；
   权限 `ClassReadOnly`（与 CLI `show configuration` 同类——show 树默认读权限，同一用户经
   CLI 能看的经 REST 也能看；且 `GET /system` 系统配置段早已是读权限）；脱敏口径与
   candidate 读取一致（`redactConfigView`，FR-SEC-007 / 决策 #25）。
2. **`GET /configuration/candidate` 契约按实现形状声明**：契约原写 `ConfigDocument` 本体，
   实现回 `{candidate, dirty}` 包装——**同 R37-1 类的契约↔实现不符**，只是出在配置族、
   形状守护没覆盖。新增 `CandidateView` schema 对齐实现，并把该端点收进形状守护覆盖清单。
   `PUT` 的 200 响应有两个分支形状（未提交=`CandidateView`、`X-NFVIS-Auto-Commit`=
   `CommitResult`），契约只写 description 不声明 schema——如实登记，留待写路径页面定稿时收。
3. **缺陷 #19 收口**：`POST /logout` 除吊销 token 外**同时丢弃本会话 candidate 并释放锁**
   （与 CLI `Teardown` 的 discard → exit → logout 对齐）。未在编辑（`ErrNotEditing`）是常态、
   不算失败；其它错误只记日志、**登出恒 204**（清理失败不该让登出失败）。
