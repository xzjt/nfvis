§2 实现（920a8b1 + 打磨）
1. **B7**（`internal/orchestrator/container/docker_client_docker.go` `Exec`，两处）：
   判据由 `wctx.Err() != nil` 收紧为 `errors.Is(wctx.Err(), context.DeadlineExceeded)`——**只有等待窗口到期
   才算超时**；`context.Canceled`（wctx 派生自调用方 ctx，客户端断开/上层取消）**透传为错误**，
   demux 流中断分支保留已捕获的 stdout/stderr 并返回错误（不再设 `TimedOut`）。
2. **B8**（三层）：
   - `internal/orchestrator/provider.go`：新增 `ErrContainerUnavailable`（API 503）。
   - `internal/orchestrator/container/docker_client_docker.go`：新增 `errDockerUnavailable` 哨兵；
     **用类型 `dockerUnavailableError` 承载**（`Error()` 只回原始文本、`Is()` 归哨兵）——避免哨兵文案
     泄漏进用户可见消息；`do()` 连接类失败（非 `context.Canceled`）与 `ExecShell` 拨号失败都带上它；
     404 仍走 `errDockerNotFound`。
   - `internal/orchestrator/container/docker.go`：新增 `normalizeDockerErr`——`errDockerNotFound`⇒`ErrVMNotFound`
     （State 与 Exec 之间的**竞态**窗口）、`context.Canceled` 原样透传、其余⇒`ErrContainerUnavailable`；
     `ContainerExec`/`ContainerShell`/`ContainerState` 的底座错误均过它。
   - `cmd/nfvisd/dynamic_provider.go`：持有层「未接入」错误 `errContainerNotConnected` 改由类型
     `notConnectedError` 承载——`Error()` 与 CLI 既有正文逐字一致（「容器编排未接入（Docker 未装配），
     运行态不可用」），`Is()` 归 `orchestrator.ErrContainerUnavailable`（**Docker 启动时即不可达**的场景同样 503）。
   - `internal/api/container.go`：`containerExec` 增 `ErrContainerUnavailable`⇒503；
     `internal/api/container_shell.go`：`handleContainerShellTicket` 的 State 检查改为**任一错误⇒503、
     不再照发 ticket**（此前非 deadline 错误会继续签发，操作者拿到「连上即断」的终端）。
3. **B10**（`pkg/cliclient/console.go` + `internal/cli/console.go` + `internal/cli/session.go`）：
   `DialConsole(wsPath string)` → `DialConsole(wsPath, what string)`——`what` 为**会话显示名**；
   CLI 侧新增单源 `consoleKindName`（「串口」/「容器终端」），`consoleKindLabel` 由它派生（`" "+name`），
   `runConsole` 传 `consoleKindName(req)`。SDK 不新造 kind→文案映射。同步 4 处测试桩签名。
4. **B11**（`internal/api/ui/index.html`）：`#vm-console-in` / `#ct-shell-in` 两处 placeholder **删去
   「Ctrl-C 可中断」**，改为「文本框不能发送控制字符；需要 Ctrl-C 请用 CLI 交互终端（容器页另提「执行命令」）」——
   Web 文本框无法注入 0x03，原提示承诺了做不到的事。

§4 真机验证（四维，dev99）
① **作用效果（B8）**——`systemctl stop docker.socket docker` 后（socket 消失、连接被拒）：
   - exec（REST）：`503` `{"code":"UNAVAILABLE","message":"容器底座（Docker）不可用: docker GET
     /containers/sem-ct/json: Get \"http://docker/containers/sem-ct/json\": dial unix /var/run/docker.sock:
     connect: connection refused"}`（对照修复前 500 INTERNAL）。
   - shell ticket（REST）：`503`（**不再照发 ticket**）。
   - **Docker 启动时即不可达**（装包时 docker 停着）⇒ 持有层未接入：exec/shell 均 `503`
     `{"code":"UNAVAILABLE","message":"容器编排未接入（Docker 未装配），运行态不可用"}`（对照修复前 exec 500）；
     CLI 侧文案逐字不变（`%% 容器编排未接入（Docker 未装配），运行态不可用`）。journal 警告同样带
     `容器底座（Docker）不可用: … connection refused`（无 `docker: unavailable:` 哨兵文本泄漏）。
   - **恢复**：`systemctl start docker` ⇒ ~30s 内 `容器编排已接入（后台）`（既有 #351 循环）⇒ `exec` 恢复成功。
② **生命周期**——正常路径不回归：`exec "echo HELLO-DEV97; id -un"` ⇒ 退出码 0、stdout 正确；容器 `exited` 时
   exec 如实 `409`（`容器未处于运行态: sem-ct（当前 exited）；先 … start`）；`request … start` 后恢复；
   `request vpp restart`/重装 deb 后仍可用。
③ **跨对象组合（B10）**——真 pty（`script -qec`，Ctrl-] 退出）：
   - 容器：`[已进入 sem-ct 容器终端，Ctrl-] 退出]`
   - VM：`[已进入 sem-vm 串口，Ctrl-] 退出]`
   同一单源 `consoleKindName`，两类会话标签各自正确。（拨号失败文案由单测红-绿覆盖——真机难以在 CLI 侧
   确定性制造握手失败；非 TTY 路径的既有文案走的是另一分支，未受影响。）
④ **对抗性对照**：
   - **B7 超时 vs 取消**：`exec sleep 30 timeout 3`（窗口到期）⇒ `504 EXEC_TIMEOUT` + 审计
     `exec 容器 sem-ct: sleep 30（超时 3s，已停止等待…）`；客户端 1s 主动断开（`curl --max-time 1`，
     exec timeout 30）⇒ 审计 `exec sem-ct: docker exec 读取输出: context canceled`——**记错误而非「超时」**
     （修复前此处会 `TimedOut=true` ⇒ 504 + 记「超时」）。
   - **B8 竞态**：State 与 Exec 之间容器被删 ⇒ 归一 `ErrVMNotFound`（404）由单测钉住（真机竞态窗口难确定性构造）。
   - **B11**：Browser Use（IAB）实机复核——先确认页面加载的是**当前构建**（总览页显示 `NFViS 2.0.0~dev99`）；
     容器详情页「交互终端」分栏连接后 `#ct-shell-in` `getComputedStyle.display=block`、`offsetParent` 真、
     placeholder = 新文案（截图 `docs/images/round158-web-terminal-placeholder.png`，画面可见终端已连接、
     输入框提示为新文案）；VM 详情页「串口」分栏连接后 `#vm-console-in` 同样为可见的新文案。
     服务端下发的 `index.html` 与新文案一致，且旧文案 `Ctrl-C 可中断` 出现 0 次。

§6 未竟 / 边界（如实）- **B7 的取消侧**在真机上以「客户端断开」观测（审计记 `context canceled`）；「窗口到期」正向路径同场复验（504）。
- **B8 的竞态 404**（State 与 Exec 之间容器被删）与 **B10 的拨号失败文案**在真机难以确定性构造，由单测覆盖（红-绿）。
- **`containerAction`（start/stop/restart）与 `logs`** 的底座错误仍按既有映射（500）；契约未对这两个端点声明 503，
  本轮**有意不改**（决策 #375 明文），如后续统一另立项。
- **Docker 启动时即不可达**场景依赖既有 #351 后台接入循环（~30s）恢复；本批未改其节奏。
- **教训入册**：真机验证**当场暴露了 B8 的另一半**——「Provider 运行期不可达 ⇒ 503」修好后，
  「**Docker 启动时即不可达 ⇒ 持有层未接入 ⇒ 500**」才在真机（装包时 docker 停着）显现；
  只读代码会漏掉持有层这一层。这与 round149~151 的「修复后仍失败要按链路逐环验证」同族。
