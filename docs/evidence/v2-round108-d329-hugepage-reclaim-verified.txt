§1 决策 #329 真机验证（✓ CLI/REST + 独立事实源 sysfs）
现场起点：1G 声明 2 / 实际 2 / 在用 1 / 空闲 1；2M 声明 768 / 实际 768 / 在用 533 / 空闲 235。
① **读视图四方数字与状态如实**：`1G 2 2 1 1 0 一致`、`2M 768 768 533 235 0 一致` + 「- 无需回收（无空闲的多余页）」✓
② **造无主占用**（root 抬高 1G 池）→ 内核实际只给到 **3**：产品如实报
   `1G 2 3 1 2 1 有无主占用（可回收）` + 「- 1G：实际 3 高于声明 2：有 1 页空闲可回收」
   ——**内核给不了 4 就报 3，不编造声明外/请求值** ✓
③ **手动回收**：`request system hugepages reclaim` → 「已回收 1 页，各池均已收敛到声明值。」（并如实说明 2M 无需回收）
   + **独立事实源** `sysfs nr_hugepages = 2` ✓
④ **空操作如实**：再次执行 → 「无需回收：内核实际已不高于声明值，未做任何改动。」✓
⑤ **自动收敛**（不手动）：再抬高 → 等 70s → `sysfs = 2` ✓（沿用既有 60s 巡检，未新造定时器）
⑥ **REST**：`GET /system/hugepages` → `pools[{page_size,managed,declared,actual,free,in_use,reclaimable,state}]`，
   与 CLI、sysfs 三方一致 ✓
⑦ 同一套流程在 **2M 池**复做（抬高到 900）：卡显示 `768 900 533 367 132 有无主占用（可回收）` ✓

§2 Web（Browser Use）
- ✓ **资源池页「大页池」卡**（`#/system/pools`）实机读出：四方数字表（声明/内核实际/在用/空闲/可回收/状态）
  与**口径说明文字**（「声明=配置唯一真源、在用一律不动、取不到内核值时如实显示『取不到』、回收不改声明值」），
  数字与 CLI/REST/sysfs **逐项一致**；「回收空闲的多余页」按钮**存在且可见**（admin，超权限门禁按 class）
- ❌ **未取得可归因证据的一项**：**在浏览器里点击该按钮**的动作——第一次坐标取点偏了（误开「我的账号」对话框），
  修正后点击**未产生确认弹窗**；而此时距我造占用已过去数分钟，**60s 巡检早已把池自动收敛**，
  因此无法把「池已收敛」归因于这次点击。**如实登记为「Web 端动作未验」**；
  同一动作已由 CLI + REST 两条路径端到端验证（§1③），且按钮的服务端门禁与端点 class 有守护测试覆盖。
