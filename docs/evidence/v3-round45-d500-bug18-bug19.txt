§2 修法（决策 #500；三道闸 + 归档保护 + 文案分岔 + 读口维度）
================================================================================
① dpkg 退出码吸收（R44-1 收口）
   脚本 `dpkg -i '<暂存>' ; rc=$?` 后**立即**落 install.rc（`<attempt> <rc>`，
   attempt 前缀防上一轮残渣冒充）；日志重定向改**整段分组** `{ …; } >>install.log 2>&1`
   ——dpkg 的报错从此落日志。
   进程侧判定吸收 rc：稳定观测到「installed+目标版本+audit 干净」**且 rc!=0** ⇒ 报失败
   （场景 A 的最后一道闸：同版本时状态判据全失明，退出码是唯一证据）。
   撞锁重试第一次真正可用（以前判 launchShell 退出码恒 0，重试从未触发）。
② 脚本终判比对**目标版本**（字面量）并要求 rc==0；结论 version 写目标版本；
   reason 分五种如实说明差在哪（rc/状态/audit/版本/未稳定）。
③ 双写者收口：进程侧判定完成后，只要 dpkg 已退出（rc 已知）就 `systemctl stop` 该次
   transient unit（stop 等 unit 真正终止才返回）——最后落笔的人唯一；rc 未知时**不停**
   （dpkg 可能仍在事务中，杀它只会制造 half-configured）。
④ 结论文件带 attempt（尝试标识）与 time（RFC3339）——旧记录不再冒充新结论。
⑤ 归档保护：Add 先拷**暂存名**（nfvis_<ver>_amd64.deb.<attempt>.staging，archived()
   的正则匹配不到），脚本在 rc==0 时才 mv 晋升为正式归档名——坏包/失败包不进回退池；
   判定失败由进程侧兜底删除暂存件；超 1 小时的残渣由下次 Add 顺带清扫。
⑥ BUG-19：失败文案分岔——状态行已达标而版本不达标时，主句说**版本差距**
   （「包未更新到目标版本——已装 X（目标 Y）」），不再出现
   「当前状态为 "install ok installed"（未达到 "install ok installed"）」；
   两类失败文案都带 dpkg 输出尾部（3 行）与可照做的重试指引。
⑦ 读口（show system software result）加**版本维度**交叉核对，且失败记录**不翻案**：
   「包当前完好」与「那次升级成了」是两件事；目标版本不在机上时明说
   「该次升级确实未发生」。成功记录与当前版本不符时注明「其后可能又升级过」。
   渲染新增「时间:」行；结构化视图带 attempt/time/matches_record（含版本）。

语义边界（有意如此，如实登记）：
  · rc 未知（适配层不写 install.rc）⇒ 沿用只看状态的旧语义，不停 unit；
  · 补救（dpkg --configure）成功即算成功——configure 自身的成功就是证据，
    不因 dpkg -i 那次的 rc!=0 翻回失败；
  · 回退（rollback）不参与归档晋升（它装的就是归档原件）。

§5 方法论附记（如实登记）
================================================================================
  · 验证用 deb 的两跳（3.0.28→dev1→dev2）是必要的：升级由**发起方**的代码执行，
    修复必须由修复版二进制自己发起的升级来验证——第一跳（旧进程发起）的结论文件
    仍是旧格式，属预期不是缺陷。
  · 本轮踩坑：Windows 侧 tar 组装 deb 树会丢执行位（MSYS tar 对 NTFS 的 chmod
    不落档），装出 0644 的 /usr/bin/nfvisd——postinst 的 try-restart 是 best-effort、
    包状态照样 installed，CLI 侧表现为「240s 重连失败」。经纬：发行 deb 一律走
    `make deb`（install -m 定权限），验证 deb 在 VM 侧解包后 chmod 再封装。
  · 撞锁重试的真机路径未构造（需可控地占住 dpkg 前端锁）；由单测
    （fakeRunner 传播 dpkg 错误 + rc 落盘）覆盖，如实登记。
