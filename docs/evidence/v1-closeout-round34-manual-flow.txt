----- 2. 本轮发现与修复（全部入 main，决策 #111~#114）-----
1. **废除 ISO 交付**（决策 #111）：删 deploy/iso、contrib/iso、make iso target；手册删「方式 C」还原编号。
2. **wizard 假绿 + 导航错误**（决策 #113，修前真机实测）：计划里的 `top` 只回配置层级顶层、**不离开
   配置模式**，最后的 `request system kernel apply` 被判「无效命令」；而失败判定只查 `%%`、漏掉
   单个 `%` 的错误输出 → 向导照样打印「向导完成」返回成功。修：计划收尾改 `commit → exit → apply`
   （exit 必须在 commit 后，否则被未提交变更拒绝）；判定抽 `stepFailed`（行首单/双 % 或「校验失败」，
   与 cli-fulltest 判定模式同源）。修后真机向导全流程通过、基线成功写入。
3. **bind-dpdk 模块自理**（决策 #112）：模块未加载时命令直接失败、操作者须手工 modprobe，而绑定
   不跨重启 → 每次重启的固定动作都含它。修：缺则自动 `modprobe`（失败报明原因），成功后写
   `/etc/modules-load.d/nfvis-vfio-pci.conf`（幂等、失败仅告警）。真机验证：**首次绑定无需手工
   modprobe**，drop-in 落地、模块已加载；重启后重绑同样无需手工步骤。
4. **user-data 文件路径不生效**（决策 #114①）：`set cloud-init user-data <路径>` 把**路径字符串
   本身**当脚本注入 seed，guest 侧 cloud-init 直接 exec 报 `Exec format error`——表现为「VM 起来了
   但初始化啥也没发生」。修：`ResolveUserData` 读文件内容（读不到报错，不静默回退）。
5. **user-data 内容类型静默无效**（决策 #114②）：缺 shebang 的脚本 / 既非 cloud-config 的内容在
   guest 里静默丢弃或 exec 失败。修：`ValidateUserDataType` 在 seed 构建期拦下并给可照做提示。
6. **改 user-data 后重启不生效**（决策 #114③⑤）：
   - instance-id 原先只取 VM 名 → cloud-init 按 once-per-instance 跳过 user-data；
     修：instance-id 改为「VM 名-输入摘要（hostname+user-data+SSH 公钥 sha256 前 4 字节）」；
   - seed 原先只在配置变更（DefineVM）时重建，而 user-data 取值是**文件路径**——改文件内容不改配置值
     → seed 不重建（真机实证：guest 报 `previously ran`、跑的还是旧脚本）；
     修：新增 `RefreshSeed`，`request … start/restart` 前按当前配置重建（幂等，~50ms）。
   真机验证：改文件 → restart → guest 日志出现新脚本标记、地址就位、流量通。
7. **VPP 主堆不受 default-hugepage-size 管辖**（决策 #114④）：`vppctl show memory` 实测主堆
   `page-size 4K`，VPP 仍占 2×1G 大页 → wizard 承诺的「1G 留给 VM」落空、每次 commit 都报
   「大页 1G：期望 N，实际 N+k」假红。修：memory 段同时写 `main-heap-page-size`（VPP 26.06 二进制
   确认接受该键）。真机验证：重启数据面后主堆 `page-size 2M, total 512` ✓。

----- 3. 登记未修（如实）-----
- CLI 引号内的 `|` 被当作 CLI 管道切分（`%% 未知管道: grep`）、多行引号值只取首行——多行 user-data
  目前只能走文件路径（手册 §9.2③ 已写明）；属解析器改动，未在本轮做。
- `request vpp restart` 返回后立即查询可能撞上 API 未就绪（broken pipe），重试即好。
- 大页池的「无主占用」现象（1G nr 高于 cmdline 声明）仍可复现（VPP/DPDK 侧分配所致），
  基线比对因此可能长期显示「运行实际 > 期望」；主堆转 2M 后 VPP 不再吃 1G，此现象已显著收敛，
  但未做池回收（shrink）逻辑。
- 本轮为跑通流程临时动过：`set resource-pools hugepages page-size 1G count 2`（1 页不够两台 VM）。
