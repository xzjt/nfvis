4. 本轮实修记录（全部落进脚本/决策 #110 补记）
════════════════════════════════════════════════════════
a) indev→outdev `-boot_image any keep` 无法编址 26.04 的 EFI El Torito（附加分区字节区间的
   "隐藏映像"）→ 产物 as_mkisofs 报 SORRY。改按 `-report_el_torito as_mkisofs` 自报配方
   全树重建（配方值含空格/引号，须经 eval 展开且先并行——两处 shell 语义坑实测踩过）。
b) 闭包裁剪两轮根因（同为候选组展开）：
   ① libvirt-daemon-driver-qemu Depends 的四选一候选组把 qemu-system/-hwe 元包拖进
      模拟器全家（mips/ppc/riscv/sparc/s390x/arm…）——产品只要 x86_64，按清单剔除；
   ② <pkg> 与 <pkg>-hwe 双变体互斥（Conflicts/Replaces）：dpkg -i -R 直灌解包一个拆另一个，
      libvirt 全链 reinstreq half-installed → dpkg 退出 1。同名非 hwe 在闭包时剔除 hwe。
c) dpkg -i -R 换**本地 file 仓库 + apt 解析**：候选组/互斥变体/已装同旧版本由 apt 挑选跳过，
   与正常安装语义一致（dpkg 直灌还被 cron/bcron/systemd-cron、dnsmasq-base/-lua、
   opensysusers/systemd-sysusers、runc 自冲突连环坑）。
d) user-data 的 mkdir -p /target/opt/nfvis 缺失 → cp -a 中间目录报错（第三次装机才暴露）；
   dpkg/apt 输出落 target /var/log/nfvis-*-install.log，失败可 qemu-nbd 挂盘直接取证。
e) 运维事故：nfvis-vm 被误恢复为干净快照（现场全失）→ 凭仓库内脚本全量重建现场
   （USTC 源、构建工具、闭包 243、官方 ISO 校验、deb、ISO），流程本身即是手册方式 C 的走查。
f) qemu -m 4096 曾致宿主机不可达（疑 OOM 冻结）→ 降为 -m 3072；1G 页在 3G guest 上算出 0
   （min(3/4,8)），属机器规格函数、非 ISO 逻辑，故验证脚本不对其断言。
