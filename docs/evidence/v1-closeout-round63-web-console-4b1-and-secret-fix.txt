----- 1. 交付（刀 4b 第一段：低风险端点接入）-----
接入 5 条低风险端点、新增 3 个页面：
- `GET /system/hardware` + `GET /system/health/thresholds` → 新页 `#/system/hardware`（硬件健康与阈值，**poll 30s**——
  采集较重不跟 5 秒轮询）；
- `GET /protocols/lldp` + `GET /protocols/lldp/neighbors` → 新页 `#/network/lldp`（邻居表从「网络对象」页移出，避免两页重复取数）；
- `GET /virtual-switches/{name}/mac-table` → 虚拟交换机详情页 `#/network/switches/:name`，**按需拉取**（带 limit 上限与「已达上限」提示，不进 endpoints、不进轮询）；
- `POST /system/ntp:sync` → 运维动作页新增「时间（NTP）」→「立即同步时间」，走**低危档**确认。
**阈值写入的裁决**：走既有 candidate 事务（`PUT /system/health/thresholds` 本身即 candidate 写；前端全库无 auto-commit 用法；
直写会与「配置」页整体写候选相互覆盖），故硬件页只读回显阈值并指路到配置页既有表单。
覆盖数字：**已接 71→76 / 未接 28→23**（契约 99）。

----- 2. 两处服务端修复（本段顺带发现，**协调方真机确认后修**）-----
**① `GET /system` 泄露口令哈希原文（严重，安全）**：真机实测响应仅 166 字节却含
`"password_hash": "pbkdf2$sha256$600000$0ka…"`（对照 `GET /configuration` 是脱敏的）。
修法：脱敏规则抽成通用 `redactView`（**规则一行未动**），`handleGetSystem` 改走它；
**守护扩到 23 条配置出口逐个核实 + 兜底扫全部 GET 路由**（将来新增"直接回配置段"的端点会当场红）；
红-绿：拿掉脱敏 → 报 ✗（响应里能看到哨兵哈希）→ 恢复 → 绿。
**真机复验（本段完成）**：`GET /system` 的 `password_hash` **0 次**、`pbkdf2` **0 次**，
非敏感字段保留（`login.users` 仍回 `name`/`class`）✓。

**② LLDP 邻居字段名契约与实现不一致**：契约声明 `local_interface`，实现发 `interface`；
且 `ui_test.go` 的字段守护**运行态未注入时恒跳过**（守护没守住）。
裁决：**改实现对齐契约**（契约名更精确：邻居同时有"本端接口"与"对端端口"，裸 `interface` 有歧义；
前端与字段守护本就按契约名写）。同时把守护改成"未断言要显式登记 + 至少断言一次 + 邻居表必须被断言到"，
并注入最小运行态让该条真的跑一次；红-绿：把 tag 改回 `interface` → 两处报 ✗。
