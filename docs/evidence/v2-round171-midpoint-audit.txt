   - 步骤：`request interfaces ens224 enable`（rev1137）→ 单会话提交 `set acls f1acl rule 10 source
     10.99.9.9/32 destination any protocol icmp action deny` + `set virtual-switches vs-a type l3` +

     interface` = `2: 0`（#341 伴随 macip 在）。

     `reassignLocked`（`l3.go:248-273`）把 ens224 从 vs-a 的 `ifaces/subifs` 登记里摘掉；删除段的
     `DeleteVRF(vs-a)`（`l3.go:630`）只按登记取解绑清单 ⇒ 空清单、不解绑。
   - 依据：决策 #361 ③ 明文「删整台交换机时对其声明的 L3 接口逐个解绑」；属修复同族漏网（R142-1 形态）。

【簇 C1a：VXLAN / storm control / 端口安全】（决策 #383/#385/#389）
- **F1 [中·确认·已真机复现（§1.3）]** 接口元素整条删除路径不触发 storm/portsec 撤销；validator
  （`validate.go:617`）论证「不可达」只覆盖「端口仍被交换机引用」，漏了同提交两处一起删。
- **F2 [中·确认]** 决策 #385 ④「巡检按登记复核（幂等）」**无实现**：`cmd/nfvisd/main.go:707-735` 的 15s
  巡检无任何 storm 调用、`StormProvider` 无 Reconcile ⇒ 带外删 policer/表后不自愈（登记 `applyDone`
  仍为真），直到 VPP 重连全量重放；期间防护静默缺失（读视图能看出未在数据面，但无告警）。
- **F3 [中·确认（校验缺口）]** storm-control 允许配在 **bond 成员口**（`validate.go:592-606` 无成员口检查）
  且能 attach；而同一文件 `:1697` 写明「成员口入向被 bond-input 吃掉」⇒ 保护假象；与 portsec 明确拒绝
  成员口（`:650`）不一致（portsec 注释还自称「照 storm-control 同例」）。
- **F4 [中·确认·已真机复现（§1.2）]** portsec↔L3 ACL 的 **macip 同槽交接次序**未覆盖：一次提交
  「删白名单 + 改挂 L3 acl-in」⇒ 伴随 macip 先绑后被 portsec teardown 解掉，非 IP/ARP 静默被丢。
  双向校验只保证「不共存」，不保证交接次序（单测/真机均未覆盖）。
- **F5 [低·确认]** QoS 策略名可与 storm policer 名空间碰撞（storm 名 `nfvis-storm-<if>-<kind>`
  `storm.go:95-97`，teardown 按名删 `:398-405`；QoS 直接以策略名建 policer `services.go:132`，`checkName`
  无保留前缀）⇒ storm 撤销可能删掉同名 QoS policer（限速静默失效）；`storm.go:94` 注释「命名空间独立」
  不成立。
