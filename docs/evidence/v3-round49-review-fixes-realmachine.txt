### 2.3 `rollback to <版本>`（决策 #509；含真机抓到的装配漏转发）
拒绝三类（最终构建）：
```
to 3.0.32~r49 → %% 目标版本 3.0.32~r49 已是当前版本，无需回退
to 9.9.9      → %% 目标版本 9.9.9 高于当前版本 3.0.32~r49：那是升级不是回退，请用 request system software add 显式安装
to 3.0.29     → %% 归档中没有版本 3.0.29（可见版本：3.0.31、9.9.9）；回退只安装归档里已有的包…
to（缺值）/未知尾参 → %% 语法: rollback [to <版本>]（…）
无参 rollback（归档空） → %% 无可回退的版本：归档目录 /var/lib/nfvis/software 为空…
```
**命中路径（真实安装）**：把仓库里留存的 `nfvis_3.0.31_amd64.deb` 放入归档后——
```
$ nfvis-cli -c "request system software rollback to 3.0.31 --yes"
回退动作已受理：nfvisd 因此重启，本次连接已断开（预期行为，不是失败）。
已自动重连并读取服务端记录的实际结果：
  版本: 3.0.31
  状态: install ok installed
结论: 成功。
$ nfvis-cli -c 'show version' → NFViS 3.0.31
$ dpkg -i build/nfvis_3.0.32~r49_amd64.deb && systemctl restart nfvis → NFViS 3.0.32~r49
```
**真机首次跑出的缺陷（本文件的重点）**：首版实现把 `RollbackTo` 只做成 **api 侧可选接口**，
`cmd/nfvisd` 的适配器 `softwareController` 没转发 → 真机上 `rollback to` 恒报
`%% 当前装配不支持指定版本回退（rollback to <版本>）`，而**所有单测注入的假件自带该方法、全绿**
（与 BUG-17 的 `PackageState` 同族）。修法：把 `RollbackTo` **升为 `api.SoftwareRuntime` 的成员方法**
（适配器漏实现即**编译失败**）+ `cmd/nfvisd` 静态守护钉转发
（`TestSoftwareControllerForwardsRollbackTo`）+ 真机复验（上）。

## §4 环境坑（本轮实测入册）

1. **套件收尾会删掉 docker `alpine:3.20`**：fulltest 结束后 `docker save alpine:3.20` 报
   `No such image`，导致语义夹具的 `ct.tar` 生成失败 → 需 `docker load -i /root/alpine-3.20.tar` 重备
   （AGENTS round47/48 已登记，本轮再次实证）。
2. **套件会改 `resource-pools` 与 `vpp cpu` 声明**（fulltest 阶段 2 设 1G=2 / isolated 1-4 /
   main-core 1 / workers 2），且产品的池对账会把 1G 池从 4 收敛到 2。**还原必须三处一起改回**
   （`vpp cpu main-core`、`corelist-workers`、`resource-pools cpu isolated-cores`——隔离核必须涵盖
   VPP 线程核，否则校验拒绝），再 `request system kernel apply` + 重启，内核池才会回到 4。
3. **VM 重启后 SSH host key 再生成**：出现
   `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED`，需 `ssh-keygen -R 192.168.155.129` 后重连
   （AGENTS round45 收尾注记过同现象，本轮第二次遇到）。
4. **远程脚本用管道喂 `cat > file` 会落成 0 字节**：改用 `scp` 传脚本 + `setsid nohup … </dev/null &`
   才真正脱离 ssh 会话（首轮踩过）。
5. `pkill -f <名>` 会匹配到自己的 ssh 命令行并自杀：用 `[n]ame` 形式规避。
