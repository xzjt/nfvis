§2 造环实证（**关键发现：v1 判据结构性漏报 → 补判据③后通过**）
- 现场：L2 交换机 `loop-vs`（`learn-limit 8`）+ 一台**双 vNIC 的 VNF**（nic0/nic1 同挂 loop-vs），
  user-data 在 guest 内 `ip link add br-loop type bridge` 把两 vNIC 桥接——经典两口环。
- **缓解生效（独立事实源）**：`vppctl show bridge-domain <id> detail` = `Learn-co 1 | Learn-li 8`
  （配置值已落到数据面）；`delete virtual-switches loop-vs learn-limit`（rev 879）后 `Learn-li`
  回到默认 **16777216** ✓；产品读视图 `learn-limit 8` 行随配置出现/消失 ✓。
- **环是真的（原始读数）**：成员口计数 5s 增量 **+684,739 包（≈137k pps）**，链路两端各 ~137k~139k pps
  持续；宿主 loadavg ≈1.2~2.0（受控，未见打满）；拆环（停 VM）后计数立即冻结。
- **v1 判据漏报（本轮最重要的事实）**：dev24 上该环跑了 5 个巡检周期，`LOOP_SUSPECTED` **恒 0**——
  `l2fib` 里 MAC 稳定落单口（判据①不触发）、学习数只有 3（判据②远离上限 8）——**判据①②对
  「两口环 + 广播风暴」这一最经典形态结构性盲**。据此**契约先行修订 #337 判据段**（新增判据③）
  并实现（PR #263），附录 A 已写明「round115 真机实证补入的必要判据」。
- **补判据③后复验（dev25，✓）**：同一场景 5 个周期内命中：
  `LOOP_SUSPECTED loop-vs — MAC ea:f8:dd:a3:69:85 在成员口 vh-loop-vm-nic1 与 vh-loop-vm-nic0 之间
  来回抖动（连续 3 轮落在不同口）；疑似广播风暴/环路（成员口同时高负载）：vh-loop-vm-nic0≈138823 pps、
  vh-loop-vm-nic1≈138821 pps；连续 3 轮 ≥ 50000 pps`——**两条证据同时命中**，且 138.8k pps 与 vppctl
  原始读数（137k）独立吻合。
- **拆环消解（✓）**：停 VM 后连续两个平静轮次 → 第 3 轮 `LOOP_SUSPECTED` 消解（0）；随后
  VNF_PORT_DOWN 按 #188 随对象消失自动消解；删现场后 `（无 active 告警）`、配置无 loop-* 残留，
  最终 rev 880。
- 现场复现教益（写进证据）：**停/起 VM 不会重建 guest 内的桥**（cloud-init once-per-instance，
  桥不持久）——造环复现须按「红线 12」改一次 user-data 内容再 restart（本轮实测：直接 start 无环无告警，
  按红线 12 重启后才复现）。
