§1 真机四维验证

1.1 作用效果 + 对抗性（A/B，同一现场翻转）
  配置（rev 1612）：
    set acls r144 rule 10 source 192.168.155.1/32 destination any protocol icmp action deny
    set virtual-switches acl-vs type l3
    set virtual-switches acl-vs l3-interface ens192 ip address 192.168.155.230/24
    set virtual-switches acl-vs l3-interface ens192 acl-in r144
  形态：**物理口 ens192 作 L3 接口**（与 round133 的 ACL enforcement 同形态；宿主与 ens192 同在 VMnet8，
  可直接 ping 该地址——deny→放行的翻转就是用户可见判定）。
  - **相位 A（绑定在场，deny 生效）**：
    · `vppctl show acl-plugin interface` → `sw_if_index 1: input acl(s): 0`（ens192，idx 1）；
      `show acl-plugin macip interface` → `sw_if_index 1: 0`（#341 伴随白名单，ARP 得以通过）；
      `show interface address` → `ens192: L3 192.168.155.230/24 ip4 table-id 13923525`。
    · 宿主 `ping -n 3 192.168.155.230` → **已发送 3，已接收 0，丢失 3（100%）**；
      `vppctl show errors` → `acl-plugin-in-ip4-fa  ACL deny packets 3` + `checked packets 3`
      （两路独立证据：包真到了 ACL 弧且被逐包拒绝）。
  - **相位 B（只清绑定，rev 1613：`delete … acl-in r144` + commit）**：
    · `show acl-plugin interface` → **无 `input acl(s)`**；`show acl-plugin macip interface` → **`sw_if_index 1: -1`**
      （伴随 macip 一并解绑）；接口地址/表归属不变（本步只撤绑定，符合语义）。
    · 宿主 `ping -n 3` → 2/3 通（首包在 ARP 刷新），紧接着 `ping -n 4` → **已发送 4，已接收 4，丢失 0（0%）**；
      `show errors` 的 ACL 计数**不再增长**（保持 3/3——绑定已不在，包不再经 ACL 弧）。
    ⇒ **R142-1 的缺陷形态（配置删了、VPP 还在拦）不再存在**。

1.2 整条删 l3-interface 的回收（rev 1615）
  - 先重绑（rev 1614：`input acl(s): 0` 回来），再 `delete virtual-switches acl-vs l3-interface ens192` + commit：
    · `show acl-plugin interface`：无 `input acl(s)`；`show acl-plugin macip interface`：`sw_if_index 1: -1`；
    · `show interface address`：ens192 **无 L3 行**（地址已摘，round142 §1-1b 的「地址不摘」消除）；
    · `show configuration`：`virtual-switches acl-vs { name acl-vs; type l3; }`（声明整条已清）。
  - **如实登记**：「口回默认表（table 0）」在真机 CLI **没有读数**——VPP 只对**带地址**的接口显示
    `table-id`（`show interface address`），无地址口无表归属展示（`show ip table` 只列表、不列成员）。
    该项由单测断言调用序钉住（`SwInterfaceSetTable(idx, v4/v6, 0)` 必须在解绑之后、摘登记之前），
    真机可见的后果是：旧表（13923525）不再带该口、接口可被重新归口（清场后 `delete … acl-vs` 删表成功即证）。

1.3 对抗性组合：同一提交「清绑定 + 删 ACL」（rev 1617）
  - 前置重绑（rev 1616：`input acl(s): 0`），随后一次提交同时 `delete … acl-in r144` + `delete acls r144`：
    · `show acl-plugin acl` → **空**（ACL 本体已删）；

    · `show acl-plugin interface` → 无 `input acl(s)`。

§5 如实边界（入册）
  1. 无 VPP 侧「接口 ACL 绑定 dump」能力：若「配置无绑定**且**进程内登记也空」而 VPP 侧仍有绑定
     （带外改动/进程重启后未重放），本实现无法验证式解绑——正常路径上恢复重放会按声明重建登记，
     不落此窗口。ACL 本体残渣仍由既有 `ACL_LEFTOVER` 对账（#321）覆盖。
  2. 「口回默认表」无真机 CLI 读数（见 1.2 如实登记），由单测钉住调用序。
  3. `DeleteACL` 循环内先改登记后下发 VPP 是既有结构：若伴随 macip 解绑报真错误，重试时该接口已不在
     rebind 列表（pair 已空）⇒ macip 解绑不会自动重试（换绑/再删该接口可再触发）。如实登记，未改结构。
  4. `l3IfaceKeyOf` 含 vlan：同一物理口 `vlan 100 → 200` 判为「旧子接口删除 + 新子接口新增」，
     旧子接口走完整回收（这正是残留族要修的行为）。
