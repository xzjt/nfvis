------ 3. 256 条冒烟（对**已装实例**跑）：26 条失败**全部**是前置级联 -----
跑法（§3.3）：`SRV=https://127.0.0.1:443 CLI_BIN=/usr/bin/nfvis-cli NFVIS_PASSWORD=… API_PORT=443`。
结果 **171 通过 / 26 失败 / 3 预期报错**（合计 200 条，与历史基线条数一致）。
逐条判读后**没有一条是产品缺陷**，三条根因：

**根因 A：阶段 2 预块的**第 1 条**语句是空操作 → 整块中止（1 + 6 条级联 = 7 条）**
- `[S2-pre] configure … resource-pools hugepages page-size 1G count 2` →
  `%% 语句未产生配置变更（尚未映射到模型或值未变化）`——已装实例的 committed 里本来就是 `count 2`，
  所以这条是"值未变化"。
- `-c` 脚本模式是**任一行失败即停止**（`cmd/nfvis-cli/main.go` 的 `runScript` 注释原文：
  「多行脚本模式：任一行失败即停止」），故预块里**其后所有语句都没执行**。核对（`show configuration`）：
  `virtual-switches vs-l2/vs-l3`、`acls acl-test`、`qos policies pol-test`、`port-mirroring pm-test`
  全部 0 命中，`vpp cpu main-core` 仍是 5（预块要设 1）——**证实中止**，不是"设了没生效"。
- 级联：`[S2] set virtual-switches vs-l2 vlan access 100` → `%% 无匹配配置: vs-l2`；
  阶段 5 的 `show virtual-switches vs-l2 {detail,ports,statistics}`、`show vrfs vs-l3 [routes]`、
  `show acls acl-test detail`（6 条）；

  （那个地址正是预块里 `vs-l3 l3-interface ens192 ip address …` 要配的，没配上）——**报错本身正确且可操作**。

**根因 B：1G 大页池被两台已声明 VNF 占满 → cli-vm 提交被**正确**拒绝（1 + 15 条级联 = 16 条）**

------ 5. 语义校验：修掉 3 处**工具假红/假报**，并给 oracle 加自校准 -----
首跑 **10 通过 / 1 失败 / 1 登记**，其中 S8 失败是**脚本自己的 oracle 错了**，不是产品错：

**S8「MAC 表 ↔ VPP l2fib 条数」假红**——两处成因（都在 oracle 侧）：
1. `vppctl show l2fib`（**非 verbose**）在 VPP 26.06 **只打印一行汇总**
   （`L2FIB total/learned entries: 1/0 …`），条目行只有 `verbose` 才有。旧实现按非 verbose 输出的行数计，
   **只要有表项就恒得 0** → 必然假红。实测：CLI mac-table 报 1 条（`b0:b0:00:00:00:00 bvi0`，
   即 BVI 自身的静态表项），而 VPP 汇总行本就写着 `1/0`。
2. `vppctl` 输出是 **CRLF** 行尾：`BD-Tag` 取成 `"vs-vnf\r"`，与 `"vs-vnf"` 精确比较恒不成立
   （该 bug 只在 Linux 上现形——MSYS 的 `sed` 会吞掉 `\r`，本地 Windows 复现不出来，见 §7 红线）。
3. 顺带把对照改成**按 BD 过滤**（l2fib 的 `BD-Idx` 是 `show bridge-domain` 的 **Index**，
   不是 BD-ID：本机 vs-vnf 的 BD-ID=6252701、Index=1，两者差很大），避免多 BD 环境下再次假红。

**S9「运行态对象是否被视图反映」假报**：原实现只凭"libvirt 有域"就打印「libvirt 有域而 CLI 未列出」，
而本轮 CLI **两条都列出了**（vnf-a/vnf-b）——该句为假。改为**只登记确有差异的项**（集合差集）。

**收尾残留**：连跑 5 次后，committed 里多出 `interfaces bond0 { name bond0; }`。
审计库原文（`config.commit` 的 detail）显示每次都是 `[edit interfaces] + bond0 ;` 与
`[edit interfaces bond0] - description sem-rt-…`——即**收尾只删了自己写的 description，
却留下了自己顺带建出来的 `interfaces <n>` 空壳条目**（发现 #15 的同类：恢复不彻底）。
修法：扰动前记下该接口**在配置里原本是否存在**，收尾时"原本不在"就整条删掉。

**红-绿验证（两处都做了）**：
- oracle：把实现换回旧版（`build/sem-old-oracle.sh`），自校准脚本在 Linux 上**报 5 处 ✗**
  （l2fib 3 处得 0、CR 2 处取空/取到带 `\r`）；换回新版**全绿**。
- 收尾还原：跑前跑后 `show configuration` **逐字节一致** ✓（修前会留下 `interfaces bond0` 空壳）。
- 产品侧对照：向 VPP 注入一条静态 l2fib 表项（`vppctl l2fib add …`）后，CLI mac-table **跟着变成 2**
  ——证明该视图确实读运行态，且新 oracle 会随事实源变化（随后 `l2fib del` 复原）。

**新增自校准并入 `make check`**：`contrib/scripts/cli-semantic-selftest.sh`
——把脚本里**真正在用的** oracle 函数抽出来（不另写一份），用**桩 vppctl** 喂合成输出，
断言「1 条表项→1」「2 条→2」「别的 BD 的表项→0」「CRLF 的 tag 能精确匹配」等 9 项；
`SEM_SCRIPT=` 可指向改了 oracle 的副本做红-绿。语义校验本身只能在真机跑，
**只有这里的桩式自校准能在 CI 挡住 oracle 回归**（与 `cli-fulltest-selftest.sh` 同一套路，已并入 `toolcheck`）。

修后复跑：**11 通过 / 0 失败 / 0 登记**（与 round10 的历史基线 11/0 一致）。
