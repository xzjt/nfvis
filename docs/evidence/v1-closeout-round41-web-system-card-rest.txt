------ 0. 结论 -----
- app.js 删除 `parseMetrics`/`apiText` 与 `/metrics` 取数，系统卡片全部改读
  `/system/status`：CPU 核数/使用率取 `cpu.total`/`cpu.usage_percent`，内存取
  `memory.total_mb`/`used_mb`（经既有的 `mb()` 呈现），根文件系统取
  `storage.{total,free}_bytes`/`used_ratio`。**显示口径不变**，取值逐位一致
  （唯一可感差异：handler 把 used_ratio 四舍五入到 4 位小数，边界上已用百分比
  可能差 0.1——同一同源摘要的正常精度，非缺陷）。
- 每次刷新少取一个端点（页面 5 秒轮询 + 事件触发刷新都走这条路径），系统卡片的
  数据来源收敛到一个端点。
- 守卫迁移（覆盖转移，不是消失）：删 `TestUIReadsOnlyExistingMetricNames`——前端
  已不读 `/metrics`，该守护失去保护对象；其要防的"字段/指标改名让页面静默变空"
  转移到 `TestUIFieldNamesExistInResponses`：新增系统卡嵌套键检查（点分路径
  `cpu.total` 等 7 个键），宿主指标非 Linux 不产出时**跳过而非报红**（沿用
  round37 既有口径，否则开发机恒红 = 工具自造假红）。
