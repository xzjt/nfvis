------ 0. 交付 -----
1. **`POST /configuration/check`**（缺口 #10 收口）：CLI `commit check` 的 REST 等价物——
   调用既有 `Engine.CommitCheck`（与提交同一份校验：schema + 语义 + 镜像存在性），
   **不落库、不下发底座**；会话前提与 commit 相同（须持 candidate）。
   **校验发现问题时仍返回 200**——检查本身是成功的，结果在 `{ok, errors[]}` 里
   （客户端不必把 400 当"检查失败"处理）；契约新增 `ConfigCheckResult` schema。
2. **配置页表单扩到三节**：系统（原有）+ **接口**（对每个已声明接口：描述 / MTU / 启用三态）
   + **资源池**（隔离核 `2-5,7` 文本 ↔ 数组解析/格式化 + 1G/2M 大页数量）；三节与原始 JSON
   共用同一份 candidate 与同一套"改字段 → 写回文本 → 保存"路径。
3. **编辑态新增「预校验」按钮**（先保存再校验；通过给绿字，问题逐条列出）。
