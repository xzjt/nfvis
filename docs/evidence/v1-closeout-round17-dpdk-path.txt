===== V1 收尾第十七轮（发现 #8，高）：业务口交 VPP 的路走通（决策 #100）=====
环境：nfvis-vm（Ubuntu Server 26.04 / VPP 26.06-rc2 / 内核 7.0）；ens160=管理口（全程未触碰）
日期：2026-09-18
起点：裸机全流程测试批次二发现 #8 —— 新装环境经 CLI 把业务口交给 VPP 走不通；
      产品一旦重生成 startup.conf 就把带外播种的口弄丢。
分支 `fix/dpdk-port-path`，提交 `620bc84`。本文件为**原始输出摘录**。

----- 0. 死锁（三处约束互相打架）-----
① `set vpp dpdk dev <X>` 的校验要求 X 已在 interfaces 里声明（model/validate.go）
② 接口 apply 要求端口**已在 VPP**（network/services.go，硬失败 + **整体回滚**）
③ startup.conf 生成按**名字**解析 PCI（pci_sysfs.go 读 /sys/class/net/<n>/device/uevent），
   而绑定后 netdev 已不存在 → 端口一旦交 DPDK，任何重生成都失败
即：提交要端口先进 VPP → 端口进 VPP 要 startup.conf 先更新 → 更新要 netdev 还在。

----- 1. 修法（决策 #100，(a)(a′)(b)(c)）-----
(a)  `network.Bindings`：绑定时把「口名 → PCI」落盘（/var/lib/nfvis/dpdk-bindings.json；
     Bind 本就返回 PCI），解绑按 PCI 删除；startup.conf 解析器 = sysfs → 记录 回退
     （netdev 还在时 sysfs 是活的事实；消失才说明确已交 DPDK）。
     启动时把已部署 startup.conf 的 `dev <pci> { name <口> }` 导入记录（存量迁移，不必重绑）。
     记录同时让「按口名解绑」成立（此前接管后只能凭 PCI 地址）。
(a′) 重生成前若「已交 DPDK 但未声明」的口会掉出数据面，打印明确告警。
(b)  接口 apply 对「已声明为 DPDK 单网卡覆盖项、但还没进 VPP」的口**延后收敛**而非整体回滚；
     判据取配置意图（vpp.dpdk.per-dev），故真错的口名照旧失败。
     ErrIfaceUnavailable 上提到 orchestrator 包，network 包别名复用（依赖方向约束）。
(c)  9 处「（是否未由 DPDK 接管？）」改为「若该口由 DPDK 接管：重启数据面后才会出现…」；
     per-dev 校验文案改为点明「先 set interfaces」；手册 §3.2/§3.3 改写为产品路径。

----- 2. 单测（红-绿 + 变异验证）-----
新增 internal/orchestrator/network/bindings_test.go、internal/orchestrator/apply_dpdk_test.go：
  · 记录往返/解绑按 PCI 删/重启后读回；解析顺序（sysfs 优先，netdev 消失才回退记录）
  · 导入两种写法（产品多行 + 手册压一行），文件缺失=0 条不算错
  · 掉口告警只报未声明的口
  · 延后收敛：已声明 DPDK 口缺失 → 不阻断 + 可读告警；未声明口缺失 → 照旧失败；其它错误不延后
**变异验证**（拆掉实现即报红，防止测试是空转）：
  去掉解析器回退 → `TestPCIResolverPrefersLiveSysfs` 报「netdev 消失时应回退到绑定记录: "" 未找到接口 ens224」
  去掉 a.warnDroppedPorts(cfg) → `TestApplierWarnsAboutDroppedBoundPort` 报「Apply: 解析 "ens224" 的 PCI 地址失败」
门禁：`make check` 全绿（覆盖率 network 74.2%，全部 ≥70%；决策条数 100）。

----- 7. 顺带发现（本轮登记，未修）-----
`show vpp` 只打印 threads/buffers/memory：**契约（命令全表）声明它含「版本」，未打印**；
`pending_restart` 在 CLI 侧完全不可见（仅 API /vpp/status 有）——而它正是本修复依赖的
「下一步动作」指示。故手册 §3.3 改为按 `show interfaces physical` 确认，并说明
「待重启」由 commit 自身警告。见 docs/V1-收尾待办.md 的新发现 #11。
