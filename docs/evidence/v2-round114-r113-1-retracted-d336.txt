§1 R113-1 撤回：round113 的登记是误判（代码级更正，无产品缺陷）
- round113 曾登记「停机 VM 改配置后 start 不重定义 domain」（依据：sem-cli 执行
  `delete virtual-machine-functions sem-cli memory hugepage-size` 提交后，start 仍以 hugepages
  backing 失败；`systemctl restart nfvis` 后依旧）。
- **更正依据（代码）**：`model.AllocationFor`——`HugepageSize` **未设时缺省回落资源池主池**
  （`ResourcePools.Hugepages[0].PageSize`，本机 = 1G）；`domain_xml.useHugepages`——除非
  `memory backing normal`（且产品限定无 vhost-user 的 VM）否则大页后备。故「删 hugepage-size」
  的语义是**回落缺省 1G**、不是「改普通内存」——域仍带 1G 是**正确的文档化行为**。
  `internal/orchestrator/apply.go` 对变更 VM 确有 `vm[<名>]`→`DefineVM` 重定义操作，commit 成功
  即已重定义（以 1G），start 路径不重定义也不违反「配置唯一真源」。
- 结论：round113 §4 的 R113-1 系把「正确的 1G 缺省」误读为「start 未重定义」；已在
  `docs/v2待做.md` 二.23 划线撤回并写明教益（判定前先确认字段语义；要普通内存须
  `memory backing normal`）。**产品代码零改动**。
