===== V1 收尾第七十八轮：整文档提交的「至少留一个 super-user」自锁兜底（决策 #152）=====
日期：2026-09-24；分支 `fix/commit-require-superuser`（main `6a91dd3` 之上）
范围：交接文档 §2.3 登记项「整文档提交缺少『至少留一个 super-user』的兜底」
（round77 真机复验捅出，见 `docs/evidence/v1-closeout-round77-one-shot-lock-release.txt` §4b）。

----- 1. 起因与交付 -----
起因（round77 §4b 原症状）：`login-users` 的 **DELETE** 路径早有「不能删最后一个 super-user」守卫
（`internal/api/resources_w5.go` 的 `handleDeleteLoginUser`），但**整文档提交**这条路
（`PUT /configuration/candidate` + `POST /configuration/commit`、CLI `load override`、
`request system configuration restore` 一类）**没有等价兜底** ⇒ 一次提交就能把本机提交成
「无人可登录」（自锁，只能带外恢复）。round77 复验时探针用空配置提交，**开发态副本的账号真被清空**。
`internal/model/validate.go` 只拦了「用户存在但 PasswordHash 为空」，**空用户表**这一形态没拦。

1.1 先摸清落点（复核结论，与交接给的线索一致）
| 事实 | 结论 |
|---|---|
| 引擎默认校验链 | `NewEngine` 里 `e.validate = model.Validate(c) + model.CheckResources(c)`，**且可注入**（`Options.Validate`） |
| 守卫该放哪 | **不能**放进 `e.validate` 链（装配方换链即静默失效）⇒ 直接放 `Engine.Commit`，在 `e.validate` 之后 |
| 判定函数放哪 | `internal/model`——`internal/config` **不能**反向 import `internal/aaa`（aaa 依赖 config，会成环，archtest 会拦） |
| 有效 class 判据 | 与 service 侧同源：`Class` 为空按 **read-only** 算（`aaa.effectiveClass` / `api.effectiveClassOf`）⇒「没写 class 的账号」不算 super-user |
| 首启引导 | `aaa.EnsureBootstrapAdmin` 走「Edit → 写含 admin 的候选 → Commit」⇒ 新守卫**不挡**它（`internal/aaa` 全包测试已复跑通过） |
| 唯一例外 | `internal/system/backup.go` 的 `Zeroize` 提交 `model.Config{}`（恢复出厂的**目的**就是复位账号） |

----- 2. 守卫语义 -----
- **判据**：candidate 里**至少一个**有效 class 为 `super-user` 的用户即通过；有效 class ＝ `Class` 为空按
  `read-only` 算 ⇒「没写 class 的账号」不算 super-user（与授权判定同源，否则会出现
  「守卫认为还有 super-user，实际没人有权限」的假通过）。
- **失败语义与既有校验完全一致**（挂在同一个失败分支上）：返回 `ValidationError`（逐条 `ValidateError`，
  `path=system.login.users`）、**候选保留**、**编辑锁保留**、审计留一条 `config.commit … failure`——
  操作者补一个 super-user 后可直接重提（用例 ① 钉住了"不是卡死，是改完再提"）。
- **例外**：`CommitOpts.AllowNoSuperUser`（唯一赋值点在 `internal/system/backup.go` 的 `Zeroize`）。
  恢复出厂提交空配置后账号表为空，由**下次启动的引导**重建 admin（既有行为，未改）。
- 报错原文（可操作、不含需求编号）：
  `提交被拒：配置里至少要保留一个 super-user 账号，否则本机将无人可登录——请先建一个 super-user 账号；若要复位账号，请用 request system zeroize（恢复出厂）`

----- 3. 用例、变异验证与结构守护 -----
3.1 用例
- `internal/config/superuser_guard_test.go`：
  ① `TestCommitRejectsEmptyConfigWithoutSuperUser`：空配置提交 → `ValidationError`、**候选保留且仍脏**、
     锁保留（他人 `Edit` 得 `ErrLocked`）、committed 与 rev 不动、报错含 `super-user`/`无人可登录`/`zeroize` 且无 `FR-`；
     补回 super-user 后**同一候选**即可提交（rev 2）。
  ② `TestCommitRejectsNonSuperUserOnlyConfig`：只有 operator / 只有 read-only / **class 为空** 三种都被拒。
  ③ `TestCommitWithSuperUserStillPasses`：含 super-user（+ 一个 operator 混排）照常提交（rev 2）。
  ④ `TestCommitAllowNoSuperUserExemptsZeroize`：不带豁免的空配置被拒；带豁免则提交成功，committed 变空配置。
  ⑤ `TestSuperUserGuardSurvivesCustomValidateChain`：把 `Options.Validate` 换成「什么都不校验」的自定义链后，
     **兜底仍然生效**（证明它没走那条可注入的链）。

----- 4. 真机复验（**由主会话执行**；本节为占位，未在本会话执行）-----
> ⚠️ **真机上不要跑 `request system zeroize` / 恢复出厂**：它会删 `/var/lib/nfvis/images` 等**共享路径**，
> 破坏冒烟阶段 3 的前置（`alpine.qcow2`、`docker alpine:3.20`）。例外点（`AllowNoSuperUser`）已由单测覆盖
> （用例 ④），真机不必也不该验它。

环境：本分支构建的开发态实例（明文，`/tmp/nfvisd-csu`）+ **生产库副本**；操作者 = super-user（admin）；
`ens160` 是管理口——**全程不碰**。

| 步骤 | 命令/请求 | 断言与**独立事实源** |
|---|---|---|
| ① 记录基线 | `GET /system/login-users`；`curl -s .../configuration/history \| jq length`；`show configuration \| display set` | 账号表含 `admin`（super-user）；记下 rev 与 cfgsha（配置库指纹） |
| ② 空配置整文档提交 | `PUT /configuration/candidate` body `{}` → `POST /configuration/commit` | 期望 **400 `VALIDATION_FAILED`**，detail 里 `system.login.users` 一条、文案含「super-user」；**rev 不变**（历史长度与①一致） |
| ③ 自锁未发生（关键） | 用 admin 口令 `POST /login`；`GET /system/login-users`；`CLI show system login-users` | 期望 **200 + token**；账号表仍含 admin；三条路径口径一致（REST/CLI 与配置库**逐字段**相同） |
| ④ 候选/锁保留 | `GET /configuration/candidate`；`GET /system/configuration/sessions` | 期望候选仍在（`dirty:true`，内容为①的替换稿）、锁仍由该会话持有（决策 #151 的收尾**不适用于校验失败**） |
| ⑤ 改完再提（闭环） | `PUT /configuration/candidate`（含 admin 的文档）→ `POST /configuration/commit` → `DELETE /configuration/candidate` | 期望 **200**、rev +1；`virsh`/`vppctl` 无关故只对配置库取指纹，确认与提交内容一致 |
| ⑥ 只读/操作员文档同样被拒 | `PUT candidate`（只有 operator 的文档）→ `commit` | 期望 400 且点明缺 super-user（与 DELETE 守卫同源） |

**收尾**：删掉探针产生的修订（或整库副本删除）、停开发态实例、核对生产库指纹与动作前一致（**逐字段**）。
