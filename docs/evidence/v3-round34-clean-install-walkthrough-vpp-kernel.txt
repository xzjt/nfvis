§9 缺陷与观察
--------------------------------------------------------------------------------
【R34-1（低危，已修）】`request capture export [name <n>]` 是**幻影参数**：语法提示与命令全表都
  挂着 `[name <n>]`、cli-fulltest 阶段 4/5 也在传 `name cli-trace`，而实现**从未消费该取值**
  ——导出文件名恒由编排层按 `<接口>-<时间戳>` 自动生成，多余参数被静默吞掉（「说了不做」；
  git 溯源：自 M5 首版实现起即如此，契约（命令树/openapi）里并不存在该参数）。
  幻影参数在**三处**同时存在（**命令树** `internal/schema/tree_oper.go` 的 `Opt(name)` 叶子——
  这是 `?`/Tab 补全与契约守护的单一真源；CLI 语法提示；命令全表；另有用户手册示例与套件调用）。
  修法（**契约如实化**，不为幻影参数补实现）：**树里删掉两处 `name` 叶子**（中立名 + 兼容别名）；
  语法提示去掉 `[name <n>]`；`export` 分支对多余参数**显式拒绝**（`%% request capture export
  不接受参数（导出文件名由系统按 <接口>-<时间戳> 自动生成）`，作分派层之外的兜底）；命令全表与
  **用户手册 §10.4 示例**同步（手册那行 `export name my-capture` 会变成无效命令）；cli-fulltest
  阶段 4/5 的 3 处调用去掉 `name`；单测/夹具改两面断言（红-绿：改前带参静默通过）。
  **真机复核（3.0.17~dev2，nfvisd + nfvis-cli 同时换装）**三面：
  ① `export name cap9` → `% 无效命令: request capture export name cap9（输入 ? 查看可用命令）`、
  RC=1（**树级拒绝**——比执行器兜底更早）；② `start→export` 正常取走真实 pcap（自动名
  `nfvis-cap-ens192-<ts>.pcap`，204 B）；③ **真 pty `?` 补全不再列出 `name`**（客户端内嵌树随
  nfvis-cli 一起更新——只换 nfvisd 不够，这是本轮实测到的一条换装注意点）。
  守护：`TestCommandTableCoversOperTree`（命令全表⇄操作树覆盖，**首跑即以「树里有 name 而全表没有」
  报红**——正是它把「树才是真源」指出来）、`internal/schema` 路径夹具、`check_suite_contract_sync.sh`
  全绿；fulltest 阶段 2~5（dev1）零失败。
【观察·非缺陷】
  O1 alpine **generic** 云镜像不消费 NoCloud seed（#483 已定性；本镜像默认口令亦不可用）——
  夹具改用 debian12（round3/24 先例）；产品 seed 交付未改。
  O2 VPP DPDK 口 unicast promisc=off（`show hardware-interfaces`），抓包只见「发给本口 +
  广播/组播」；安静网络下会得到空 pcap（如实报「未捕获到报文」）——环境语义，产品无 promisc 开关。
  O3 `ping <域内目标> source <VRF 内地址>` 不带 `vrf` 时宿主 ping 报原始
  `bind: Cannot assign requested address`（带 vrf 即通 2/2；web 页与全表都写明域内目标须填 vrf）
  ——用法路径，失败文案未做到「须填 vrf」的定制化（登记为文案改进候选）。
  O4 实验室 VMnet8 外置 DHCP 抢答（R31-O2 同族）：测试 DHCP server/relay 时需临时停宿主
  VMnetDHCP（本轮两处都用其做了 lab 控制并恢复）；产品行为正确。
  O5 顺序性瞬时错误：两口逐个 `unbind-dpdk` 时，第一口的收敛会报「另一口还在 vfio」——如实、
  可照做（补第二条命令即收敛），非缺陷。
  O6 Web 会话随 nfvisd 重启失效——页面明确提示重登（正确行为）。
【教训入册】
  L1 夹具 user-data 的 cloud-init 列表形式必须写 3 元素 `[ sh, -c, "..." ]`；`-c "..."` 写一起
  会生成 `sh '-c "..."'` → `Illegal option`（静默失败、cloud-init status=error）——本轮先踩后修。
  L2 套件选跑（`cli-fulltest.sh 2 3 4 5`）**同样要求撤管理口地址**；不撤则 S2-pre 被重叠守卫
  正确拒绝并级联 35 红。诊断时**读 /tmp/cli-test/full.log**（小结日志不含块内报错文本）。
  L3 读 tc/qdisc 时 `head -N` 会截掉 `clsact` 行造成「没配」的误判——先取全量再判。
