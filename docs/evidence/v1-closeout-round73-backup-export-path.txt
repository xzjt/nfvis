日期：2026-09-24；分支 `fix/backup-export-path`（main `8c7b8e2` 之上）
范围：`request system configuration backup to <path>` 的导出目标路径 —— 交接文档「仍未裁」第 ② 条。

----- 1. 起因与交付 -----
起因：该命令的目标路径由操作者直接给出，**源侧**有 `sys.Path()` 把归档限定在备份目录内，
**目标侧原本什么都不校验**，直接交给 `copyFile` 的 `os.OpenFile(dst, O_WRONLY|O_CREATE|O_TRUNC, 0o600)`，
而 nfvisd 以 **root** 运行（`deploy/nfvis.service` 的 `User=root`）⇒ 一次手误
（`to /etc/fstab`、`to /usr/bin/nfvisd`）就把系统文件**截断成归档 JSON**。
决策 #143 已把该命令收回到 super-user（故**不是提权路径**），但仍是「手误即毁系统」的脚枪。

判据（三条 + 两条同源，**全部是「拒绝」而非「改写」**）：
1. **必须绝对路径** —— 相对路径会随工作目录漂移，操作者以为写到了 A 实际落在 B。
2. **目标不得已存在** —— 判定的权威点是打开时的 `O_CREATE|O_EXCL`：唯一判据、原子生效，且堵住
   「检查与打开之间目标刚被建出来」的竞态。「已存在」**故意不写进前置检查**——否则 O_EXCL
   只是一道永不生效的第二防线（本轮的变异验证正是要给这一条上锁，见 §2.2）。
3. **父目录必须已存在且是目录** —— 把「目录写错」如实报清楚，不留给打开文件时的 ENOENT/EACCES 去猜。
4. （同源）目标**是目录**即拒：目录永远不是合法导出件目标。
5. （同源）目标**是符号链接**按「已存在」拒：`Lstat` 不跟随链接、`O_EXCL` 也不跟随，
   不借链接去写它指向的文件（实测见 §2.1 的 `TestBackupExportRejectsSymlinkDst`）。

**有意不做**：**不**维护「哪些目录敏感」的名单（如「只许写备份目录」）——那会连带挡住把归档导出到
`/data/incoming/`、`/root/` 一类**合法**用法（导出件的用途正是交给操作者取走），而第 2 条已足以
挡住「手误毁掉系统文件」。理由与口径写进决策 #148。

关键断言（原文）：
- ④ 导出件与源归档**逐字节相等**、内容含 `nfvis-config-backup`，权限 0600（POSIX 平台；Windows 跳过该断言，

- ⑤ 的一个观察（**既有行为，非本轮引入**）：同一秒内两次 `Backup()` 会落到**同名归档**并覆盖之
  （文件名含秒级时间戳）。故「归档自身是否被改写」这一条改用**另存的一份归档**作目标来验，避免被这个
  同名覆盖干扰；真机脚本不必碰这一条。

----- 3. 真机复验（**由主会话填**）-----
占位：本节的步骤与断言已按「不碰管理路径、不碰真系统文件」的口径写好，由主会话在 nfvis-vm 上执行后填写结果。
该命令声明为 **super-user**（决策 #144 起运行期判定也按声明执行），故须以 super-user 账号执行。

| 步骤 | 命令（真机） | 断言 |
|---|---|---|
| 1 相对路径被拒 | `request system configuration backup to /tmp/nonexist-rel.json` 的**相对写法**：`request system configuration backup to rel-export.json` | 输出含 `%%` 且原因含「绝对路径」；**不产生** `rel-export.json`；同一次输出仍含「备份已生成」 |
| 2 已存在目标被拒且内容不变 | 先 `touch /root/keep-me.txt`（写入一行已知内容并记下 `sha256sum`），再 `request system configuration backup to /root/keep-me.txt` | 输出含 `%%` 且原因含「已存在」；`sha256sum /root/keep-me.txt` **与执行前一致**（原文件未被改写） |
| 3 合法路径成功且 0600 | `request system configuration backup to /root/export-<时间戳>.json`（**新文件名**、父目录 `/root` 存在） | 输出含「已导出到」；`ls -l` 该文件为 `-rw-------`（0600）；文件头含 `nfvis-config-backup`；`show system backup` 仍列出自动命名的归档 |
| 4 源归档与既有归档均完好 | 步骤 1~3 之后：`ls -l /var/lib/nfvis/backup/`、`python3 -c 'import json;json.load(open("…"))'`（对自动命名归档） | 备份目录内归档仍在且可解析为 JSON；既有归档未被任何一次被拒的导出改写 |
| 5（可选，**只读探测式负例**——不要真的写系统文件） | 以**已存在的系统文件**为目标：`request system configuration backup to /etc/fstab` | 输出含 `%%` 且原因含「已存在」；`sha256sum /etc/fstab` **与执行前一致**。⚠️ 该路径已存在 ⇒ 只可能被「已存在」挡住，**不会**被写；**绝不要**为了试 `O_EXCL` 去删/改名 `/etc/fstab` 或 `/usr/bin/nfvisd` |
