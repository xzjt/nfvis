§6 R24-E 真机复验（dev1 发现缺口 → dev2 闭环）
--------------------------------------------------------------------------------
6.1 正向（dev1）：宿主 `ip addr add 192.168.155.130/24 dev ens160` → 声明管理口 .130
    （commit confirmed + 同会话确认，rev 40）：
    · `ss -ltnp`：`192.168.155.130:443`（**运行期换绑**；改前需重启服务才收敛）；
    · journal：「监听地址 :443 为通配，已收敛为管理口地址 192.168.155.130（管理面仅监听管理网卡）」
      ——**以原始旗标 :443 为基**（启动时就地改写后的 .129 未被沿用，证据行可见）；
    · curl 经 .130 → 200；经旧 .129 → 拒绝新连接；SSH（22）全程无感。
6.2 **真机捕获 R25-2（#471 行内回修）**：改 .130 后用 `nfvis-cli -server https://192.168.155.130:443`
    登录 **失败**：`certificate is valid for …, 192.168.155.129, … not 192.168.155.130`
    ——监听换了、**自签证书 SAN 没随之**（`tlsMgr.SetListen` 只影响之后生成的证书）。
    回修：换绑成功后若 `Info().SelfSigned` 则**立即 `RegenerateSelfSigned`**（外部证书不代重签、
    只记日志提示），并已属 #471 行内记录。
    dev2 复验（同一现场重放）：journal「监听地址变更后已重签自签证书（SAN 随新监听地址）」；
    `openssl x509 … subjectAltName` **含 192.168.155.130**；**严格校验的 nfvis-cli 经 .130 登录
    成功（RC=0）**——修复前此路必失败。
6.3 反向闭环：经 .130 会话改回 .129（rev 45）→ 监听回 .129、严格 CLI 经 .129 成功、.130 拒新
    连接；`ip addr del .130` 还原宿主。全程 **产品未改宿主地址/netplan**（地址是操作者加的，
    产品只收敛监听——口径见命令全表/手册同步）。
6.4 失败安全（设计，已由单测覆盖）：新地址被占用时 Rebind 失败并**回退旧地址**（服务继续可用）；
    解析不出本机可达的管理口地址时**保持现状、绝不放宽**（只记日志）。单测见 `internal/api/rebind_test.go`。
