===== V1 收尾第七十轮：幽灵端点收口（内核基线 apply/rollback）+ class 列守护（决策 #146）=====
日期：2026-09-24；分支 `fix/kernel-endpoints`（main `1406885` 之上）

----- 1. 起因 -----
round64 登记：`POST /system/kernel:apply` 与 `:rollback` **契约里早就声明、服务端从未注册**——控制台
「内核基线」页的写入/回退按钮点了得到 **404**（界面按既有口径如实说明"本机服务端没有提供这个接口"，
不谎报成功）。与 R51-2 的 `GET /system/kernel` 是同一类"幽灵端点"，只是方向相反（`routes_contract`
只查"注册的都在契约里"）。

**顺带查出的第二处（同类：声明与实现不同源）**：命令树 §3 与《命令全表》都写
`request system kernel apply|rollback` 为 **S**，而**代码树漏了 `Su()` 标记** ⇒ 按 `request` 域的 O 级放行，
**operator 能改写 GRUB 启动参数**。（决策 #144 把运行期判定与声明对齐之后，这个漏标才成为唯一屏障。）

----- 2. 处置 -----
1. **命令树补 `Su(K("kernel", …))`** —— 与两份契约文档一致（写 GRUB 启动参数、需重启生效）。
2. **抽出共用实现**：`applyKernelBaseline` / `rollbackKernelBaseline`（`internal/api/cli_kernel_baseline.go`）——
   CLI 与 REST 走**同一份**"派生期望基线 + 同一落地器"，CLI 只把结构化结果渲染成文本。
   （同源，不是两条路径两套行为；沿用 `deriveKernelDesired` 的既有做法。）
3. **注册两条端点**，class = **super-user**（与文档一致）；契约补 `summary`/`description`/`403`/`503`
   与 `KernelBaselineAction` schema；内嵌 `openapi.json` 重生成。
4. **形状**：`pending_reboot` **恒为数组**（apply 无差异 → `[]`；rollback → `[]`，不会发 `null`）
   ——契约声明的是 array，发 `null` 会让"字段没发出来"与"没有差异"分不清（形状守护的既有口径）。
   （首轮真机复验看到 rollback 回 `null`，当场修掉并重跑。）
5. **新增守护** `TestRequestClassMatchesCommandTable`：《命令全表》`request` 族的 class 列必须与命令树
   `RequiredClass()` 一致（**46 条**；占位符填探针值、可选组整组略过；跳过上限 3 条——防止解析器失效后
   守护变恒绿）。它当场抓出第三处漂移：**`request system password change` 表写 S、树是 O**——已按树改表为
   **O**（自助改密＝本人 + 验旧口令，不该要 super-user）。

----- 6. 登记（未改）-----
1. **控制台没有 read-only 可用的自助改密入口**：该表单在「用户与权限」页，而决策 #145 起该页对 read-only
   隐藏（导航不列、页内写入口隐藏）⇒ read-only 用户在**界面上**无处改自己的口令（REST 允许 R 自助）。
   建议给顶栏加一个"我的账号"入口（属界面增量，需浏览器验收）。
2. **`request system password change` 的 CLI/REST 不对称**：CLI = O（受 `request` 域 `Op()` 结构所限，
   树里无法表达"比域节点更低"的 class），REST = **R**（自助改密，验旧口令）——属自助语义的既有取舍，
   已在决策 #146 里写明。
3. `request system configuration backup to <path>` 的目标路径仍无校验（round67 起该命令仅 super-user 可用）。
4. `GET /system/tech-support/{file}` 同类口径不一致（待裁决）。
