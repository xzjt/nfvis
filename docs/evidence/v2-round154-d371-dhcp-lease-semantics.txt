§2 实现（1ae80c4）
1. **C7**（`dhcpserver_lease.go` `allocate`）：对 **active** 条目**原样返回**（不改 state/到期）——此前无条件改写成
   `offered` + 2 分钟 OFFER 保持窗，一次 DISCOVER 即把生效租约降级、2 分钟后被 sweep 回收 ⇒ 地址可分配给别的
   客户端（重复地址）。offered/其它非 active 条目仍按保持窗刷新。
2. **C6**（`dhcpserver.go` REQUEST 分支）：先取 `owner := ownerOf(req)`，新增「owner 为 declined 且未到期 ⇒ **NAK**」
   分支（在任何 MAC 相等判定之前）——此前同一 MAC 因 owner.MAC==本机落进默认分支被 `commit` 夺回；`ownerOf` 自带
   sweep，到期隔离自然解除。
3. **C10**（`dhcpserver_packet.go`）：DHCP 载荷按 BOOTP 下限**补零到 300 字节**（在 UDP 长度/校验和计算之前补；
   零填充位于 END 之后）。

§3 单测与红-绿
- `TestDHCPLeaseTableAllocateKeepsActive`（C7：active 经 allocate 状态与到期均不变；对照 offered 仍刷新保持窗）；
  `TestDHCPServerDeclinedNotReclaimableBySameMAC`（C6：DECLINE 后同 MAC REQUEST ⇒ NAK；他人 ⇒ NAK）；
  `TestDHCPReplyPaddedTo300`（C10：OFFER/ACK 载荷 ≥300）。
- 红-绿三项逐一：临时摘除各自修复 ⇒ 对应用例 rc=1（按预期失败），恢复即绿。

§4 真机验证（dev89，dns-vs 启用 server + 原始帧注入）
- **注入通道**：向交换机内置 tap（`nfvisdhfe341987`）以 `AF_PACKET` 原始帧注入 DHCP（自写 `dhcp_inject.py`，构造
  Ethernet/IPv4/UDP/BOOTP+选项）；应答用 tcpdump 抓（客户端单播回帧需混杂/抓包器——**探针自身教训**：
  AF_PACKET 非混杂模式收不到单播回帧，首轮「无应答」是探针问题而非产品问题，租约表同时已证明 server 处理成功）。
- **C7（探测不降级）**：DISCOVER→REQUEST 得 `active`（ExpiresIn 86396）；再发一条**新 xid 的 DISCOVER** ⇒
  租约仍 **active**、到期 86393（仅随时间流逝 3s，**未**被重置为 120s 保窗）——旧实现此处会变 offered+120s。
- **C6（隔离不可夺回）**：DECLINE `.10` ⇒ 读视图 `declined`；**同 MAC** 再 REQUEST `.10` ⇒ 读视图**仍 declined**
  （未被夺回）；**另一 MAC** REQUEST `.10` ⇒ tcpdump 抓到应答 **NACK**（`DHCP-Message (53): NACK`）。
- **C10（补零）**：tcpdump 显示应答 `BOOTP/DHCP, Reply, length 300`、以太帧 `length 342`（= 14+20+8+300 恰为
  BOOTP 下限）；客户端请求帧仍为 244/250（只补服务端应答，符合口径）。
- 端到端：DISCOVER→Offer、REQUEST→ACK 全流程正常（tcpdump 双方向可见）。
- **清场**：`delete dhcp-server`（rev 304）⇒ 无 tap、无 dhcp 配置、租约目录空、无 RECOVERY/池耗尽告警；注入脚本与抓包文件已删。
