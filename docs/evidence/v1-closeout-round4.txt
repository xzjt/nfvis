----- 3. FR-NET-001：网卡 DPDK 驱动接管（完整周期，真机）-----
前置：ens192=0000:0b:00.0、ens224=0000:13:00.0 均绑 vfio-pci（DPDK 接管态，内核无 netdev）；
停 VPP 释放设备后操作。

**(a) 解绑 → 交还内核驱动（并重现内核网卡）**
$ nfvis-cli -c "request interfaces 0000:13:00.0 unbind-dpdk to-driver vmxnet3 --yes"
接口 0000:13:00.0（PCI 0000:13:00.0）已解绑并交还内核驱动，当前驱动 vmxnet3
  sysfs: driver=vmxnet3, driver_override=(null)
  ip link: ens224  DOWN  00:0c:29:a9:61:98        # 内核网卡回来了

**(b) 绑定 → DPDK 驱动**
$ nfvis-cli -c "request interfaces ens224 bind-dpdk --yes"
接口 ens224（PCI 0000:13:00.0）已绑定到 DPDK 驱动，当前驱动 vfio-pci
  sysfs: driver=vfio-pci, driver_override=vfio-pci
  （ens224 作为内核网卡消失——符合 DPDK 接管语义）

**(c) 幂等**：按 PCI 重复绑定直接返回 vfio-pci，无多余写入：
$ nfvis-cli -c "request interfaces 0000:13:00.0 bind-dpdk --yes"
接口 0000:13:00.0（PCI 0000:13:00.0）已绑定到 DPDK 驱动，当前驱动 vfio-pci

**(d) 复位并核对 VPP**
ens224 绑回 vfio-pci、ens192 保持 vfio-pci → 重启 VPP：
  ens192  down / ens224  down / local0  down     # VPP 正常识别两张数据口

**真机实测到的两点平台行为（实现中已处理）**：
① **绑定后内核网卡即消失**，故已接管的网卡只能按 PCI 定位（解绑的常态）；
   且绑定结果必须**按 PCI 回读驱动**——按接口名回读会失败并把结果误报为「无驱动」
   （首轮真机即出现该误报，已在 `dpdkController` 改为按 PCI 轮询回读）。
② **清空 driver_override + rescan 不足以让内核重新探测原生驱动**：实测解绑后设备停留在
   `driver=none` 且 ens224 未出现；显式 `echo <pci> > .../vmxnet3/bind` 后立刻恢复。
   故 `unbind-dpdk` 增 `to-driver <驱动名>`；未给出且未自动绑定时返回**可操作错误**
   （不静默留下无驱动网卡）。
