§7 缺陷/观察登记（R31-*；逐条独立事实源）
--------------------------------------------------------------------------------
R31-1【低·可发现性】`nfvis-cli "show version"`（把命令当作**位置参数**、未用 -c/-f）**静默什么都不做**、
  退出码 0：main.go 不解析 flag.Args()，非空位置参数被忽略 → 进入 REPL → 非 TTY stdin 立即 EOF 退出。
  典型「假成功」（脚本/操作者以为命令跑了）。建议：对非空位置参数报错并指引 `-c`/`-f`。
  现场：`nfvis-cli -u admin -p … "show version"` → 输出仅「连接 … 」+「nfvis>」；`-c "show version"`
  正常。
  → **已修（决策 #482）**：`cmd/nfvis-cli/main.go` 新增 `rejectPositionalArgs`——多余位置参数在握手/登录前
  **fail fast 拒绝**（点名首个参数 + 给出 `-c`/`-f`/交互两种正确用法，退出码 **2**）；`-c`/`-f`/交互不变。
  单测 `TestRejectPositionalArgs` 红-绿；`make check` 七项 RC=0。**真机换装 `3.0.14~r31fix1` 复验**：
  `nfvis-cli … "show version"` ⇒ `% 不接受位置参数 "show version"：…`、退出码 2；`-c "show version"`
  照常返回版本表、退出码 0。
R31-2【低-中·guest user-data 未被消费（**定性更正：guest 镜像兼容性，非产品缺陷**）】现场：某
  Alpine 3.20 cloud guest 的 cloud-init 找到产品 seed 设备（/dev/vdb，blkid `LABEL=cidata TYPE=iso9660`）
  但 `mount -o ro -t auto /dev/vdb` 报 **EINVAL** → 落 `DataSourceNone`（「Used fallback datasource」）、
  user-data 完全未应用、产品侧无告警（VNF 仍 running、无 VNF_PORT_DOWN）。
  → **已定性更正（决策 #483）**：真机根因实验（真 guest 内探针）证明——该 guest 用 **BusyBox `mount`**，
  其 `-t auto` **不触发 `request_module`**（只试 /proc/filesystems 已注册的 fs）；该内核只**内建
  ext3/ext4**，iso9660/vfat 均为 `=m` ⇒ **任何模块化 fs 都挂不上**（实测换 vfat 同样 EINVAL，
  故「只改 seed 格式」无益）。纯 Go ext2（内建 fs）seed 能被该 guest 挂上，但 cloud-init 的 NoCloud
  检测在该（嵌套虚拟化、慢启动）guest 上仍不认该设备——**未取得端到端成功证据**，按「不留假功能」
  纪律**不成立即不改**（实验分支已回退，`internal/orchestrator/compute` 保持 `cloud-localds` ISO 原状；
  #139 的 virtio 磁盘交付不变——它在常规 guest 上有效，round24 的 alpine/debian 均实证消费）。
  结论：属 **guest 镜像兼容性/环境**（BusyBox mount + 慢启动 udev 时序），产品侧无「仅改 seed 格式
  即修好」的路径；根治需同时解决 cloud-init 检测时序（后续候选，未立项）。
R31-O1【口径】`ping <ip> vrf <L2交换机名>` 报 `no FIB table for lookup`——L2 交换机的 BVI 转发域
  名为 `vr-<交换机名>`（vppctl `ip4 table-id`），`vrf` 参数按 VRF 名解析，故传交换机名取不到表；
  L3 交换机（vs-wan）其 VRF 名即交换机名、可用。非缺陷（内核侧设备名与 VPP 侧命名族不同），
  如实登记供文档说明。
