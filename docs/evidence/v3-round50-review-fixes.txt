四、Web 面同步核对（结论：无需改 JS）
-------------------------------------
- 镜像上传/拉取失败：`internal/api/ui/js/views/images.js` 的 multipart 路径用 `httpErrText(res)`
  （取服务端 `message`），JSON 路径与 zeroize 用 `api()`；`internal/api/ui/js/core/api.js` 的
  `api()` 已把 message 与 `detail[]` 逐条并入错误文案。因此新的 409（被引用不可覆盖）与
  500（zeroize 残留）都会如实显示。
- zeroize：`views/ops.js` 走 `api()` + catch → `opsMsg('恢复出厂失败：' + e.message, true)`，
  成功分支才显示「已恢复出厂」。
- 本轮因此未改任何前端文件；只把新语义写进 openapi 与手册（见下）。

七、如实边界
------------
- 本轮**未做真机验证**（未发布件安装、未跑四套件）；所有结论来自源码复核 + 单测/包测试。
- `-race` 在本机不可用（`-race requires cgo`）；两个队列（hostApplyQueue、identityFinalizer）的
  正确性靠「状态迁移都在同一把锁下 + 无非阻塞唤醒丢失」的推理与确定性 channel 用例，未做竞态检测。
- #519 的「删除链路本地地址后是否影响后续 v6 ND」需真机 A/B 复核（本轮只按同族网关撤销路径的
  既有口径对齐）。
- #514 的 URL「发布期第二道复核」在真机上基本不可达（配置引用一个未 ready 的镜像会被
  `Lookup` 拒），属防御性路径；测试以「下载中途翻转配置来源」制造确定性时序覆盖。
- `checkPublishAllowed` 在未注入配置来源或 `Committed()` 报错时**不阻断**（无配置事实无从判定
  引用，与 `Delete` 由调用方给 refCount 的既有口径一致）。
- 未提交 git。
