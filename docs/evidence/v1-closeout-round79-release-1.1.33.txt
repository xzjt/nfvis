----- 7. 本轮发现（如实登记）-----
**① 一条既有跨会话行为（非本版引入，登记进待办「仍未裁」）**：`POST /logout` 的候选清理是按**身份键** `user@api`
生效的（`internal/api/handlers_auth.go` 的 `Discard(sessionFromIdentity(r))`），而 CLI 每次收尾都会 REST 登出
（`internal/cli/session.go` 的 `Teardown()` → `Logout()`）⇒ **同一用户跑一条 CLI 命令（哪怕只是 `show version`）
会静默丢弃控制台/脚本侧的未提交候选并释放其编辑锁**。现场最小复现（检查 H 的 H5 段，脚本先"意外"撞到、再单独复现）：
```
token1 PUT candidate（脏）-> 200   sessions: [{"holder":"admin@api","dirty":true}]
token1 GET /system/version -> 200（token1 本人在认证）
token2 POST /logout        -> 204
  → sessions: null（token1 的候选与锁被 token2 的登出丢弃）
  → token1 读 candidate: CONFLICT
  → token1 仍认证? 200（仍登录，但编辑态没了）
再复现真实路径：token1 PUT candidate（脏）-> 200 后跑 /usr/bin/nfvis-cli -c 'show version' → sessions: null
```
影响＝**未提交的编辑被静默丢弃**（不动已生效配置）。判据错在"会话"被表示成了 `user@source` 身份键：所有 REST
流量（控制台、脚本、CLI 的收尾登出）共用 `user@api`。修法需要契约先行（`sessions` 目前只按 `user@source` 列出），
故本轮**只登记不改**：非本版引入、且改动会触及会话模型。
**② 空闲后首个 BVI ping 丢 1 包**（**复现 3 次**：重装恢复收敛后一次、两次长时间空闲后各一次；均为 4/5 = 20%），
**热态连打全通**（本轮共 9 轮 `repeat 5` = 45 包 **0 丢**），宿主经 DPDK 物理口 4/4 双向正常。
**判读：不是功能回归**——本版两刀**完全没碰数据面**，同一链路在热态、宿主侧、独立事实源（`vppctl` ↔ `virsh`）三处都正常；
丢的**总是**"长时间空闲后的第一个 ICMP"，符合 L2/L3 邻居表在空闲后首次发包需要重新解析的形态
（现场旁证：BVI 上 `show ip neighbor` 表项的 Age 随空闲增长到 400s+，一发包即归零）。
**未定位到具体层**（VPP 侧还是 guest 侧）：本轮为此写过一个"用接口 rx/tx 计数做差"的探针，
但脚本取错了列（见下 ③④），**没拿到决定性证据** ⇒ 如实登记为**环境侧待查**，不作产品结论。
**教训**：这类"空闲态瞬态"若要有结论，探针必须先对**已知正确**的读数自校准（本轮的反面例子就是计数器列号取错还照打结论）。
**③ 校验脚本自身三处错（都已改正后重跑，记下来防重蹈）**：
- ①`PUT /configuration/candidate` 收的是**裸配置文档**，首轮脚本按 `GET /configuration` 的响应形状把
  `{"configuration":{…}}` **包裹体**PUT 上去 → 候选成了**空文档** → 提交 400（看着像"合法文档也被拒"，
  实际是脚本把响应形状当成了请求形状）。改成裸文档后 200 / `rev+1`。
- ②`GET /system/configuration/sessions` 的 class 是 **super-user**，首轮用 read-only token 读 → 403；
  改成 admin token 看（这本身是**正确**行为，不是缺陷）。
- ③H5 段 `echo` 里出现反引号 → 被 bash 当命令替换（日志里冒出 `user@api: command not found`）→ 改用「」重跑；
  另 `code -o /tmp/dl-b.json` 与函数内建的 `-o /dev/null` 冲突 → 下载体没落盘（该断言改用 HTTPS 直连重做）。
- ④**上传脚本时一条 ssh 喂了两个 `tr`**（`ssh host 'tr -d "\r" > a; tr -d "\r" > b' < file`）：stdin 全被第一条
  `tr` 吃掉，第二条写出**空文件**，而 `bash -n 空文件` 照样通过（**又一处假绿**）⇒ 后台上跑的探针其实是空脚本、
  日志 0 字节。**教训**：一次 ssh 只喂一个文件，上传后 `wc -l` 复核行数（不能只信 `bash -n`）。
