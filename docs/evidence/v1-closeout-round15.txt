方法：不是「看命令有没有报错」，而是**给每条断言配独立事实源，并用扰动判别来源**
--------------------------------------------------------------------------------
本次缺陷（4 类）全部由 `cli-semantic-check.sh` 这套**语义校验**找出——同一台机器上
256 条全功能冒烟是 **197 全绿**（其判定只看行首有没有 `%`，不看输出内容对不对）。
三种手法：
  ① 事实源对照：CLI 输出 vs 独立 oracle（VPP / 内核 / 配置库 / libvirt）；
  ② **扰动判别**：改动事实源（在 VPP 里直接建一个配置中没有的 BD、把接口链路翻 down），
     看 CLI 是否跟着变——**配置驱动的实现不会变**，一测就露；
  ③ round-trip：写→读→删→再读，验证配置通路自洽。

修复前（同一套校验，v1.1.4 二进制）：**通过 4 / 失败 6 / 登记 1**
--------------------------------------------------------------------------------

  ✗ S4 ports  无任何计数字段（契约 §1.1 要求；实际输出为配置 dump）
  ✗ S4 statistics 无任何计数字段（同上，且与 ports 逐字相同）

  ✗ S6 `| display set` 未实现（契约 §3 明列，实际 %% display 仅支持 json|xml）
  · S7 libvirt 有域 cli-vm 而 CLI 列表为空（口径未明，登记）

§2 结果判读（逐条）
================================================================================
① 虚拟交换机列表＝运行态：VPP 里 3 个 BD（`br0` / `sem-vs` / `sem2`）全部列出，
   并给出 BD-ID、Learn/Flood 状态、成员口数；**配置里没有的**标注「未在配置中（运行态存在）」。

   （修复前该行纹丝不动）。速率按 G/M/K 归一，驱动取 `interface_dev_type`（本例 `dpdk`）。
④ `| display set`：不再谎报支持——报错明确标注「未实现（附录 A #84）」并给出替代路径
   （`save <file>` / `show configuration` / `| display json`）；契约 §3、命令全表（原标 ✅
   属**误标**，已改 ⊘）、用户手册、语句树帮助文案均已同步更正。

================================================================================
§5 已知影响与未做
================================================================================
1. **输出格式变化**：`show virtual-switches` 由 JunOS 配置块改为**运行态表格**
   （BD-ID/Name/Learn/Flood/Ports/Note）；`show interfaces physical` 表头新增三列。
   依赖旧文本格式做解析的脚本需同步调整。
2. **与 REST 的分工（有意，非漂移）**：`GET /virtual-switches*` 仍返回**资源模型**
   （配置对象，供声明式操作）；CLI `show …` 返回**运行态**。与既有
   `show interfaces physical` 同构，已在决策 #84 明确写入。
3. **S7 未处理（登记）**：`show virtual-machine-functions` 只列配置中的 VNF；
   libvirt 里存在而未写入配置的域（如本次遗留的 `cli-vm`）不显示。契约对 VM 列表口径
   未明确（与 `<ifname>` 不同：VNF 是可声明资源，孤儿域是否该列出属产品口径），
   故仅登记，未在本轮改动。
4. **`| display set` 未实现（登记为独立特性）**：忠实实现需要 model→CLI 的**反向映射**
   （`save` 导出的是 JSON；`login user … password …`、`api tls cert-file … key-file …`
   这类别名语句无法由配置树反推为合法语句）。做 lossy 版本会在「复制配置」这件事上
   制造静默错误（比不支持更糟），故更正契约与四处宣称，留待把别名表做成**双向**后再实现。
5. `ports`/`statistics` 的计数取自 VPP stats 段（`state.InterfaceCounters`）；未见该接口
   统计细分（错误/drop）在本视图呈现——契约只要求「每端口收发计数」，已满足。
