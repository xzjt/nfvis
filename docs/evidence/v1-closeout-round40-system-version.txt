------ 0. 结论 -----
- **数据源勘察**（真机逐条核过，不凭记忆）：
  ubuntu ← `/etc/os-release`（VERSION_ID=26.04，退回 PRETTY_NAME）；libvirt ← `libvirtd --version`
  （12.0.0）；qemu ← `qemu-system-x86_64 --version`（10.2.1）；docker ← `docker version --format
  {{.Server.Version}}` 取**守护进程**版本（29.1.3）；vpp ← 既有 `network.Manager.Version()`
  （binary API `show_version`，与 `/vpp/status` 同源，26.06-release）。
- **DPDK 没有可靠来源**，勘察结论：本机 DPDK 静态链接进 VPP 的 `dpdk_plugin.so`
  （`ldd`/`/proc/<pid>/maps` 无独立 DPDK 库）；govpp 的 `ShowVersionReply` 只有
  program/version/build_date/build_directory，**不含 DPDK 版本**；`vppctl show version`（含
  verbose）与 `strings` 里也探不到版本串；dpkg 只有 vpp-plugin-dpdk 包（版本 26.06-release，
  那是 VPP 的版本，**不能拿来冒充**）。故**有意永不汇报 dpdk**，不伪造。
- 口径沿用决策 #116：**只汇报探测到的键**（取不到就不给，不编造空串）；形状守护白名单
  从 6 条**缩到 1 条**——ubuntu/vpp/libvirt/qemu/docker 改由守护经**注入的假源**真校
  （CI 上不再恒走白名单），只留 dpdk 一条并写明"无可靠来源、有意不汇报"。

**为什么守护服务器要注入假源**：真机可用性（命令在不在、os-release 在不在）由
