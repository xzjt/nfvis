§1 能力前提 spike（本会话真机，先于契约）
- `nft` v1.1.6 可用；宿主既有六张表（ip/ip6 × filter/nat/mangle）**全由 iptables-nft（docker/libvirt）管理**
  （`nft list ruleset` 自带「managed by iptables-nft, do not touch」警告）⇒ 产品只建独立 `inet` 表、绝不触碰其它表。
- **同 hook 的 base chain 相互独立、drop 全局生效**：在另一张表以更高优先级（-10）accept tcp/22，
  本表 drop-all 仍把新 SSH 连接拦死——「高优先 accept 不能豁免别处 drop」。
- **保留 `ct state established,related accept` 让既有会话在 drop-all 下存活**：长会话全程存活、新连接超时。
- **逐规则计数真实递增可读**（`icmp type echo-request counter` 3 包/180 字节）——与 VPP ACL 计数（#339 撤回）
  相反，这条路能给出读数。
- 救援通道盘点：open-vm-tools active（vmrun 带电源控制可用、**免 guest 凭据**）；VMware 控制台为操作者带外通道；
  VM 无串口（vmx 无 serial0）；本会话的 Computer Use 能力不可用（SDK 报 unavailable）——故验证保险采用
  **同会话兜底还原 + vmrun 复位**两级，均未依赖 GUI。

§2 实现（4acb6a1 契约文档 + e3152d8/4b24a66 实现；实现由子智能体承担、主会话逐点审查）
- 模型/校验：`SystemConfig.Firewall{DefaultPolicy, Rules[]}`；seq 唯一 1..9999、action 必填、source 裸 IP 归一
  /32//128、port 仅 tcp/udp、**至少一条匹配条件**、重复规则拒绝、**firewall 已配置而管理口未声明 ⇒ 提交期拒绝**
  （文案给照做路径 `set system management interface <ifname>`）。
- 数据面（`internal/system/firewall.go` + `_linux/_other`）：渲染纯函数（保留项固定顺序、用户规则按 seq 升序、
  匹配 family 分支、`comment "nfvis-rule-<seq>"` 身份标记）+ `Apply`（指纹 sha256 + 表存在性 ⇒ 幂等跳过；
  重建走「delete table + 建表」同批 `nft -f -` 单事务、无无过滤窗口；配置全空 ⇒ 回收表）+ `Read`
  （`nft -j` 按 comment 映射计数；applied 判定含「外来 comment＝检测到手工修改」；**不可读不得报 0**）。
- 守卫：`sysFirewallChanged` + `ErrFirewallConfirmRequired`（与 FR-CFG-012 同位同判据；#364 隐式确认序未动）。
- 接线：main.go OnCommitted + 启动各一次；失败只告警不阻塞（读视图 applied=false 如实呈现）。
- 读视图：CLI `show system firewall` / REST `GET /system/firewall` / Web 系统页只读卡（同源）。
- 套件：fulltest 阶段 2 新增 16 项（解析块 3 + 负例 plain-commit 被拒 + 负例「至少一条匹配条件」+
  confirmed 正例/确认/回读/清理 13 项；TEST-NET `192.0.2.0/24` 特征源、异常中断有兜底清理）。

§4 真机抓出的 P0 缺陷与修复（68865fb；dev111 抓到 → dev112 重验通过）
- **现象**：`set system firewall default-policy drop` + `commit confirmed 2`（不确认）——窗口内新 SSH 超时
  （预期）；**2 分钟超时后配置自动回滚（读视图回「未配置」）但 nft 表没有被回收（`policy drop` 残留）**，
  新 SSH 依旧被锁——**管理面锁死到重启**。经 `vmrun reset soft`（免凭据带外复位）恢复；
  复位后 nfvisd 启动下发把表回收（顺带实证「启动下发回收表」路径）。
- **根因**：`doConfirmedRollback` 只 `store.AppendRevision` 落库，**不走 `Commit`/`OnCommitted`** ⇒
  宿主侧重收敛（防火墙/TLS/syslog/日志保留，全在 main.go 的 OnCommitted 里）不触发。
- **修法**：回滚落库成功后补发 `e.onCommit(newRev, "system")`——回滚与 Commit 同为「已提交配置变更」，
  必须走同一通知；**同族受益者**：TLS 证书/syslog 转发/日志保留在 confirmed 超时回滚后同样会重新收敛
  （此前它们也有同款「回滚后不还原」缺口，一并修掉）。
- **红-绿**：新用例 `TestConfirmedTimeoutRollbackNotifiesOnCommit`（修前 OnCommitted 触发 2 次、
  修后 3 次且第三次 user=system）；dev112 重验 §4 场景：**窗口内锁死 → 超时 → 配置回滚 + 表回收 +
  访问自动恢复（G4 兜底核查输出「无需手动」）**。
- **如实登记**：`system.management.interface ens160` 的声明为本轮新写入的常驻配置（rev 944，confirmed 两步式
  提交，顺带验证管理口守卫）；软复位后 sem-vm 未自启系 libvirt autostart=**disable**（既成环境状态，非缺陷）。
