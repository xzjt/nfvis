§0 结论
四项验证全部通过：读视图（CLI/REST/Web 三面同源）如实给出**实测**的「数据面占用 1 页（1G）」与
「VNF 可起页数 = 空闲页数」，向导声明计入并告警。**Browser Use 复核抓到并修掉一个真缺陷**——
见 §3，这正是「界面交付必须实机复验」的价值。

§1 CLI/REST 三方对照（dev49 首验 + dev50 修正后复验）
- sysfs：1G 池 nr=2 / free=0；smaps 直证：`vpp_main` 持 `/memfd:seg_0-0`（主堆）1 页、
  `qemu-system-x86`（sem-vm）持 guest RAM 1 页。
- CLI（dev50，修正后两连读一致）：
  `1G 2 2 2 2 **1** 0 0 0 一致`（声明/实际/在用/持有/**数据面占用**/无主/空闲（可分配）/可回收/状态）
  + 说明行「数据面（VPP 主堆）固定占用 **1** 页（实测；不可配置释放）——VNF 可起页数 = 空闲页数（当前 0）」；
  REST `GET /system/hugepages`：`held_by_dataplane: 1` + 同文 note。
- 动态核对：停 sem-vm ⇒ `在用 1 / 持有 1 / 数据面占用 1 / **空闲 1**`（说明「空闲（0）→（1）」随动）；
  起 sem-vm ⇒ 回 `2/2/1/0`。数据面占用**不随 VNF 生命周期变化**（固定占用语义成立）。

§2 向导预演（真机 pty）
- 1G 问句带提示「数据面固定占用其中 1 页 ⇒ 可起 VNF 数 ≈ N−1」；
- 1G=1 时计划预览出告警行「⚠ 1G 池仅 1 页：数据面占 1，无法再起 VNF（装 VNF 建议 ≥2）」；
- 确认填 no ⇒「已中止（未做任何变更）」、配置未被改动。

§3 ⚠️ Browser Use 复核抓到的真缺陷（round134b 修正）
- 首版实现（dev48/49）归属为「**首个被扫描到的进程**」——Web 卡渲染 `数据面占用 2`、说明「固定占用 2 页」，
  而同一时刻 CLI 显示 1、REST 显示 **2**（Browser 内 fetch 实测）——**同一现场两个读数互相矛盾**。
- 根因：**vhost-user 会把 VNF 的 guest RAM 大页也映射进 VPP 进程**（该 dev:inode 同时出现在
  `vpp_main` 与 `qemu` 的 smaps 里）；按 /proc 目录扫描顺序归属时，谁先被扫到就归谁——sem-vm 停/起换了
  pid、字符串序一变，归属就在 1↔2 间**非确定翻转**。子智能体原注释「VPP 与 VNF 不会共享 1G 页」不成立。
- 修法（round134b）：**独占归属**——一页**仅由**数据面进程（comm 以 vpp 开头）映射、**无其它进程共享**
  才计入 `held_by_dataplane`（guest RAM 被 qemu 共享 ⇒ 排除；comm 读不到 ⇒ 按非数据面计，宁少不猜）。
  同步：单测新增「共享 guest RAM 排除」回归（构造 vpp 先扫描的顺序锁死旧实现会翻车）、既有归属测试
  断言改独占语义、契约行/openapi/手册/Web 静态说明措辞全部对齐。
- 修正后复验（dev50）：CLI **两连读稳定 dp=1**；Web 卡 1G 行「数据面占用 1」+ 说明「固定占用 1 页」。
- **最终复核（dev51 = `gh pr merge 283` 后的 v2 构建）**：Browser Use 重新加载（`?v=` 绕缓存）→
  登录 → 资源池页：表 `1G 2 2 2 2 1 0 0 0 一致`、说明「固定占用 1 页（实测；不可释放）——VNF 可起页数
  = 空闲页数（0）」，静态说明段含「仅由…无其它进程共享」口径；截图
  `docs/images/round134-web-pools-dataplane-column.png`。
- 教益（入册）：跨事实源对照（CLI vs REST vs 页面）能暴露**非确定性读数**；「首见/顺序依赖」类归属
  在共享映射（vhost-user/memfd 共享段）场景下必然翻转——归属判据要用**全量映射者集合**，不用顺序。
