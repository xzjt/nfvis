§0 结论
- **R142-2 收口**：libvirt 楔死（socket 可连、零响应）不再让任何调用无界挂起——
  ① 执行中的 RPC 到硬上界即**关闭自持 conn**（#349 同一中断手段）并如实报错；
  ② 探活据此在阈值窗口内判「连接中断」→ `COMPUTE_UNAVAILABLE`（运行期文案）→ 有界复连；
  ③ `kill -CONT`/底座恢复后自动复连、消警（#354 语义不变）；
  ④ VPP 侧提交不被 libvirt 卡死连带；`/metrics` 有界返回并如实给 `runtime_available=0`。
- **审查修正入册（重要）**：「上界一到无条件关连接」会**误杀合法长操作**（快照创建/回滚恰逢探活 =
  连接被探活打断）——已改为**排队/执行两段分开判**：排队到期 = 连接只是忙（`ErrConnBusy`，探活按
  健康跳过、**不关连接**）；执行中到期 = 判假死（关连接）。单测双向钉住（关 / 不关）。
- **边界（如实）**：楔死检出延迟取决于「第一个撞上楔死的调用」的上界——实测两种：空闲时首受害者是
  探活（5s 上界）≈ 35s 内出告警；首受害者是 30s 上界的巡检读 ≈ 70s。ctx 无 deadline 的读在楔死中
  最多等前一个调用的上界（实测 22.7s）后快速失败——**有界**（对照修复前：无界，拖到客户端 90s）。

§1 真机四维验证（三段 SIGSTOP 复现，均带时间戳）

1.1 第一段：检出 + 告警 + 读取有界（10:12:26 STOP）
  - STOP 前基线：`show virtual-machine-functions` 正常（sem-vm running）、告警仅常态 `HUGEPAGE_POOL_ORPHAN`。
  - **10:13:10**（STOP 后 44s）journal：
    `WARN VM 状态巡检 err="VM sem-vm 状态查询: libvirt 调用超时（执行中未在 30s 内返回，连接已关闭，
     将由常驻状态机自动复连）: context deadline exceeded"` ⇒ **30s 硬上界真的落到了阻塞点**（修复前此
     调用永不返回，巡检持 recoveryMu 卡死）。
  - **10:13:35**（STOP 后 69s）：`show alarms active` 出现
    `warning COMPUTE_UNAVAILABLE libvirt: libvirt 连接中断，正在自动重连：VM 生命周期动作暂时不可用，
     已有配置声明不受影响（原因：查找 domain __nfvis_probe__ 失败: invalid argument）…每 15 秒探活、
     连接未恢复时按有界尝试自动复连；重连成功后本告警自动消解，无需重启 nfvis…`
    journal 同刻：`libvirt 连接中断，开始自动复连`；**10:14:07**：`自动复连未成功，告警保持；将继续按
     接入节奏重试`（libvirtd 仍 STOP，复连按 #354 语义退回 30s 节奏、永不放弃）。
  - 楔死中的读取：`show virtual-machine-functions sem-vm` 返回 `state -;`（运行态如实不可用）——
    实测一次 0.4s（连接已被前序调用关闭后快速失败）、一次 22.7s（排在 30s 上界的巡检读之后，
    **有界**失败；对照修复前：无界、拖到客户端 90s 超时）。
  - 反例对照：STOP 期间 journal 的探活失败文案是「查找 domain __nfvis_probe__ 失败: invalid argument」
    ——连接已被上界关闭后 go-libvirt 对死连接的即时错误（可辨识、非静默）。

1.2 第二段：自愈（10:14:29 CONT）
  - **10:14:37**（CONT 后 8s）：`INFO libvirt 连接已恢复（自动复连成功）`（#354 的 onReconnected：
    换装 + 消警 + `EnsureConsistent` 补跑）。
  - 告警核对：`show alarms active` 中 `COMPUTE_UNAVAILABLE` **计数 0**（自动消解）；
    `show virtual-machine-functions sem-vm` 恢复可读；`/metrics` 的
    `nfvis_vnf_runtime_available{kind="vm"}=1`。

1.3 第三段：对抗性（/metrics 有界 + 错误不留「静默 0」）与跨对象（VPP 侧提交不被连带）
  - 10:15:20 STOP；40s 后（仍楔死）`set interfaces ens224 description wedge-probe` + `commit`
    **0.374s 成功**（revision 1674，随后 delete 1675）——libvirt 楔死**不连带** VPP 侧提交。
  - 10:16:37 STOP；8s 后 `/metrics` **2.027s 返回**，取值
    `nfvis_vnf_runtime_available{kind="vm"} 0`（查询不可用**如实置 0**，聚合 `nfvis_vnf_running{kind="vm"} 0`
    配套「不可信」信号——不在看板上静默呈「全停」而无提示）。
  - 同段读取：`show virtual-machine-functions sem-vm` 22.7s 后返回 `state -;`（有界，见 1.1）。
  - CONT 后 ~1s：`libvirt 连接已恢复（自动复连成功）`；告警 `COMPUTE_UNAVAILABLE` 计数 0。

1.4 无「误杀」观测（长操作保护）
  - 三段楔死之外，当日窗口内**零次**非预期复连/告警（journal 无其它「连接中断/恢复」对）；
  - 长 RPC 与探活交错时的「忙」路径由单测钉住：`TestCallQueuedTimeoutReportsBusyWithoutClosingConn`
    （排队超时返回 `ErrConnBusy`、**不关连接**、前面正在执行的调用**不受影响**完成）——探活对它按健康
    跳过（`dynamicCompute.Probe`），不再出现「快照创建恰逢探活 ⇒ 连接被关」的误杀。

§5 教训与边界（入册）
  1. **「超时就关连接」必须先分清「排队」与「执行中」**：排队超时关连接会误杀前面正在执行的合法
     长 RPC（审查抓到；快照创建/回滚恰逢 15s 探活即中招）。修正是两段分开 + `ErrConnBusy`，并由
     探活按健康跳过——「连接忙 ≠ 连接坏」。**写契约时把这条边界写进了 #362 的处置 ④**。
  2. **检出延迟如实登记**：硬上界保证「每个调用有界」，但楔死告警的延迟 = 首个受害者调用的上界 +
     两轮探活（实测 35s~70s 两种）。若将来要求更短，方向是给巡检读也带上更短 ctx（本轮未做）。
  3. **事故入册（本会话）**：审查期间用 `git checkout -- <file>` 误还原了子智能体**未提交**的实现
     （当时只有契约提交在库里）——从子智能体会话记录（`~/.zcode/cli/rollout/model-io-sess_subagent_*.jsonl`
     里 Write 工具参数的完整文件内容）找回并重打审查修正。**流程教训：子智能体产出先 commit（或至少
     `git add`）再动任何 git 还原类命令**。
  4. 非 unix 形态（qemu+tcp/tls，产品不支持）无自持 conn 可关，上界只能「返回失败」不能真中断——
     与 #349 同口径，注释与证据均如实说明。
