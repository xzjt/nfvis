------ 0. 结论 -----
控制台从"只读总览"扩到**可改配置**，语义与 CLI 同一套：
「开始编辑」（以 committed 为底稿建立 candidate、PUT 取锁）→ 表单/原始 JSON 编辑 →
差异预览 → 提交（成功即释放会话锁）→ 或丢弃。SSE 的 config-committed 事件顺带刷新配置卡。

**R44-1（可视验收抓到、本轮修复）**：配置视图按决策 #25 **移除**口令哈希，而写路径是
"以视图为底稿整文档回写"——回写把哈希抹掉（差异里立刻出现 `- password-hash «已隐藏»`），
提交即让该账号**失去口令、登不进去**。修法两层：引擎 `UpdateCandidate` 对入参缺失的
敏感叶子从 committed 同名用户**继承**；校验兜底拦下"没有口令的用户"。
判据：API 端到端用例**提交后用原口令重新登录成功**（变异验证：去掉继承即报红）。

**R44-2（登记观察项，未改行为）**：管理口地址/网关变更的 `commit confirmed` 强制按
FR-CFG-012 原文**只约束 SSH 会话**，控制台（api 来源）改管理口不会被要求确认（提交成功
但带"注意连通性"警告，页面已如实展示）。浏览器同样可能自锁（控制台就跑在管理地址上），
**建议评估是否把 api/console 来源纳入**——属规格口径变更，故只登记。

| 验收点 | 结果 |
|---|---|
| 配置卡（只读） | `（committed revision 3）`、版本/状态、展开后是完整 committed JSON（interfaces/resource_pools/…） |

| 表单改值 | 改主机名 → 消息"已写入 candidate（未保存）"、JSON 文本同步（**此处发现 `change` 不触发**：程序化赋值不置"值已改"标志 → 改监听 `input`） |
| 保存 | "已保存到 candidate（有未提交变更）" |
| 查看差异 | **修复前**：差异里多出 `[edit system login users admin] - password-hash «已隐藏»`（R44-1 现场）；**修复后**：只剩 `- hostname nfvis; + hostname nfvis-web;` |
| 提交 | "提交成功（revision 4）"，回到只读视图、版本号 4、JSON 含 nfvis-web；事件卡实时出现 `config-committed：revision=4`；**会话锁已释放**（sessions 返回 null） |
| 丢弃 | 再改主机名为 discard-me → 保存 → 丢弃 → committed 仍是 nfvis-web（discard-me 未生效） |
| 管理口变更（R44-2 现场） | 原始 JSON 里加 `system.management.address` → 提交成功（revision 5）+ 页面显示"提示：警告: 管理口地址/网关已变更，注意连通性"；**未被要求 confirmed**（按 FR-CFG-012 只约束 SSH 会话），确认按钮保持隐藏 |
| CLI 对照 | `show configuration` 显示 `hostname nfvis-web`、`management { address 192.168.155.129/24; }`——与 UI 提交逐项一致（同一 committed） |
| 会话锁 | 提交/丢弃后 `GET /system/configuration/sessions` 返回 `null`（无锁） |
