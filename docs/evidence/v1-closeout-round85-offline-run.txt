----- §4 安装路径抓到的缺陷 #181 / #182（红 → 绿）---------------------------------
本轮第一次干净机离线安装（旧构建）时，**.run 自己的独立自检**报了 17/18：
  [失败] AppArmor 未放行 /var/lib/nfvis（VNF 启动会被拒绝）
  → `/etc/apparmor.d/local/usr.lib.libvirt.virt-aa-helper` 存在但**0 字节**；`--verify` 复跑仍 17/18/1。
根因两条，都属「装机报成功、功能起不来」：
  #181：决策 #159 声称的放行实现被追加在 postinst 的 `exit 0` **之后**——死代码，永不执行。
  #182：即便把那段移到 exit 之前也不够——本机 libvirt 与 nfvis 落在**同一次 apt 事务**里，
    apt 先配置 nfvis、后配置 libvirt，postinst 探测 profile 的条件当时尚不成立 → 静默跳过。
修法（同一台机器上验证红→绿，证据见下）：
  · 规则只写一处（Go：`internal/system/apparmor.go` 的 `AppArmorLibvirt.Ensure`：幂等追加两条路径规则
    + `apparmor_parser -r` 重载；无 profile 静默跳过；写盘成功但重载失败如实报错）；
  · 三处共用：postinst 改调 `nfvisd -ensure-libvirt-apparmor`、nfvisd 启动时补一次、60s 巡检周期复核
    （覆盖「nfvisd 起来之后才装 libvirt」）；
  · 新增守护 `check_maint_scripts.sh`（顶层 exit 之后不得有可执行语句）+ 两处自校准进 `make check`。
红→绿实测（同一台暴露过缺陷的机器）：
  修复版 deb 两次构建哈希一致（d1232455…）→ `dpkg -i` → postinst 打印放行检查完成 →
  放行文件内容为两条规则 → `nfvisd -ensure-libvirt-apparmor` 复跑报「无需改动」（幂等）→
  `.run --verify` 转 **12/12（0 失败）**。
全新安装（干净快照 + 封锁出网）复验：18/18、退出码 0（§3）。

----- §9 观察与如实登记 -----------------------------------------------------------
1) 重启后 1G 池为何是 4 而不是基线的 1：**VPP 包自带的 `/etc/sysctl.d/80-vpp.conf` 有
   `vm.nr_hugepages=1024`**，开机时按缺省页大小（1G）尽力分配，实际拿到 4 页（dmesg
   `HugeTLB: registered 1.00 GiB page size, pre-allocated 1 pages` 是内核按 cmdline 预分配的 1 页，
   其余为 sysctl 追加）。安装前（默认页大小 2M）同一 sysctl 给出的是 2M=1024 页。
   `show system kernel` 会同时打印「内核基线(cmdline)」与「运行实际」，两者可不等而各自如实；
   本轮把资源池显式规划为 1G=4 / 2M=768 之后，三方一致。
2) 套件重跑口径：cli-fulltest 的阶段 3 头部写明「幂等：重复运行只会因『无变更』报错，属正常」；
   本机第二次跑（未清理上轮对象）出现 11 条此类失败，清理对象/镜像注册 + `request interfaces
   ens224 enable` + 恢复 docker 镜像后，单遍跑即 194/1。
3) `show vpp runtime` 未接入（附录 A #34）——已登记缺口，非本轮回归。
4) 快照恢复会清掉：make/go、`/root/ob`、镜像（`debian-12-generic-amd64.qcow2` 未复原，
   `alpine.qcow2` 与 docker `alpine:3.20` 本轮已放回）、口令（现为 LQo79mRLbzhYje8y@Aa1）。
