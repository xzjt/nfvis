## §0 能力前提核实（动手前，真机 spike — #338 的教训）

直接打 Docker Engine API：exec 建实例带 `Tty:true, AttachStdin:true`，`start` 请求带
`Connection: Upgrade` / `Upgrade: tcp` ⇒ 回 **`HTTP/1.1 101 UPGRADED`** +
`Content-Type: application/vnd.docker.raw-stream`，此后同一连接**全双工**：

```
状态行: HTTP/1.1 101 UPGRADED
升级头: ['HTTP/1.1 101 UPGRADED', 'Content-Type: application/vnd.docker.raw-stream', 'Connection: Upgrade', 'Upgrade: tcp']
读回: b'/ # echo SHELL-OK; id -u\r\nSHELL-OK\r\n0\r\n/ # \x1b[6n'
```

⇒ 可行，据此写实现（不重蹈「先写实现再发现底座不成立」）。

## §1 作用效果（真 pty，决策 #81：交互行为必须在 pty 下验）

```
$ script -qec "nfvis-cli" /dev/null        # 真 pty
nfvis> request container-functions sem-ct shell
正在打开 sem-ct 的容器终端（Ctrl-] 退出，60 秒内有效）…
[已进入 sem-ct 容器终端，Ctrl-] 退出]
/ # id -un; hostname
root
ebf1447cc32c
/ # 
[已退出容器终端]
```

- 进入的是容器内 `/bin/sh` 的**真 TTY**（有提示符 `/ #`、作业控制）；
- `id -un` ⇒ `root`、`hostname` ⇒ 容器 ID `ebf1447cc32c`（与 `docker exec` 一致）；
- **Ctrl-] 退出**、终端状态正常恢复（其后 `show version` 等命令照常，仅 #310 记载的「最多吃掉一个在途字节」边界）。

## §2 生命周期（含一处**口径被真机推翻并改写**）

**① 断开后的容器侧进程 —— 原口径「断开即释放」被对照实验推翻。**
会话前容器内**无** `sh`；一次会话（进入 → 执行 → Ctrl-]）结束后容器内**仍有 1 个 `/bin/sh`**：

```
基线:        （无 sh）
会话结束后:    13 /bin/sh
```

⇒ 「连接断则 exec 进程随之终止」是想当然。**已按实测改写契约/手册/命令树/全表/openapi/代码注释与
Web 文案**：**断开只关产品侧桥接**，容器内进程可能仍在运行（Docker 不提供 exec 进程的中止接口），
需清理时用 `exec` 杀进程或重启容器——**不谎称已释放**。

**② 前置**：容器 stop 后申请终端 ⇒ **409** + `容器 sem-ct 未处于运行态（当前 exited）；先 request
container-functions sem-ct start`（在签发 ticket 时就判，不给「连上就断」）。再 start 即可用。

## §3 跨对象组合（ticket 按资源键隔离）

同一张 ticket 表、不同键前缀（`ct/` 与 `vm/`），实测四态：

| 用例 | 结果 |
|---|---|
| 容器票用在 **VM 串口** WS | **401** ✓ |
| VM 票用在 **容器 shell** WS | **401** ✓ |
| 容器票用在容器 shell WS（合法但非 WS 握手） | 非 401（票被接受，随即因非握手结束） |
| 同一容器票**再次**使用 | **401** ✓（一次性） |

## §6 本轮实测修掉 3 处（均真机/交互复现）

1. **会话刚建立就断开**（pty 首次实测）：原实现用 `http.ReadResponse` 取 body —— Go 对 101 的 body
   语义与本用途不合（读侧立刻 EOF ⇒ 桥接两侧同时结束）。改为**手工解析状态行与响应头**（读掉空行即止），
   两端都用同一连接（读侧用**自己的** `bufio.Reader` 以免吃掉与响应头同包到达的首批数据）。
2. **「断开即释放」是想当然**（见 §2①）：对照实验推翻 ⇒ 契约/文档/注释/Web 文案全面改写为实测事实。
3. **CLI 断开/退出文案写死「串口」**：容器会话也显示「[已退出串口]」；改为按会话种类取词
   （`consoleKindLabel`，`ConsoleRequest.kind`），`copyConsole` 的标签改为参数传入（单测同步）。

**工具坑（入册）**：`node --check internal/api/ui/app.js` 对**含 `export` 的 ESM 漏报**「字符串里出现真换行」
这类语法错误（实测 rc=0 而 `vm.runInContext` 报 SyntaxError）——本项目真正拦得住的是
`contrib/scripts/web-console-config-selftest.sh`（make check 的 toolcheck 里跑）。

## §8 未在本轮（如实登记）

- **窗口尺寸同步**不做（Docker exec 有 `resize` API，WS 侧未接）——终端宽度变化不会同步给容器。
- 完整终端模拟（xterm 类）不引入（免构建约束）；Web 端为纯文本终端（ANSI 剥离后渲染）。
- 会话不可恢复（关连接即结束产品侧桥接；容器内进程另见 §2①）。
- `docker attach` 不涉及（那是容器主进程的 stdin，语义不同）。
