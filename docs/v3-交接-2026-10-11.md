## 3. 下一步（无强制项；候选按价值排序）

1. **R12-1 立项**（本轮按裁定跳过）：3×1G-only 布局下 VPP 吃满 1G 池、VNF 容量 0，且**提交校验放行、
   start 才报裸 QEMU 文案**（提交侧池账本不扣数据面占用）。涉及内存编排的**产品表态**：支持则改编排
   （把缓冲/辅助段落 2M、1G 留给 VNF），不支持则向导/校验挡下并给照做路径。
   相关实测口径（本轮新增）：VPP 三段 1G 页的归属（主堆 / `buffers-numa-0` / DPDK EAL `seg_0-0`）、
   **DPDK EAL 按「最大页优先」取页**（源码级依据见证据）、`buffers-per-numa`/`main-heap-size` 两个
   旋钮压不到 1 页。
2. **R13-E（中低）**：同时声明 1G+2M 池时 `memory hugepage-size 2M` 的 VM 起不来
   （`Unable to find any usable hugetlbfs mount for 2048 KiB`）——产品把 `/dev/hugepages` 只按**一个**
   页大小挂载。建议按声明池挂多个挂载点，或在 VM 校验期如实拒绝。
3. **R13-F（低）**：VM 内存小于其大页尺寸时提交期未拦（`size-mb 512` + `hugepage-size 1G` 提交成功，
   start 才报裸 QEMU 文案）。
4. **四套真机套件**（fulltest / 语义 / lifecycle / pty）——本批**未跑**（验证走的是换装二进制 + 逐条
   真机复验）。跑前先清上轮对象与确认夹具（`alpine.qcow2` + docker `alpine:3.20`），见 `docs/v2已做.md` §五。

## 4. 本轮的经验（避免重走）

- **契约先行**：附录 A 决策 → 守护条数（`make check` 的 `docscheck` 会比对 AGENTS.md 的「已定决策 N 项」
  与附录 A 实际条数）。
- **子智能体分域**：同包/同文件并行会互相打断编译与测试——**按包分域、必要时串行**（本轮 5 个子智能体
  逐个跑，api 测试单次约 8 分钟）。
- **「改完必须真机过一遍」**：本轮 3 处细化都是真机才暴露的（govpp 错误形状、delete 幂等、人话文案）。
- **交叉编译换装二进制**是快路径，但**正式发版仍须 deb 两次逐字节一致 + 四套件**。
- **lab 拓扑坑**：L2 域的 BD 含物理口接 VMnet8 时，guest 的 DHCP 广播会被外置 DHCP 抢先应答（产品侧
  租约如实记录，别误判为产品缺陷）。
