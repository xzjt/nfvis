## 2. 执行方式

测试直接装配 `store + config.Engine + 各 Provider`（不经 nfvisd HTTP），使用 `it-` 前缀对象；build tag `integration`，环境变量 `NFVIS_VPP_SOCK`（缺省 `/run/vpp/api.sock`），无 socket 自动跳过（CI 不跑）。

```bash
# nfvis-vm
pkill -x nfvisd            # 避免与守护进程争用同一网口（约定见 Makefile 注释）
cd /opt/nfvis/src/nfvis
make integration           # = go test -tags integration ./test/integration/... ./internal/orchestrator/...
```

## 5. 真机发现的坑（已记入交接文档）

1. **`ip_address_dump` 不支持 `~0` 全量**：VPP 26.06 传 `sw_if_index=~0`/`0` 均返回空（与 `bridge_domain_dump` 行为不同），必须按接口索引逐个 dump。已修 `govppDiagClient.InterfaceAddresses`（先枚举接口再逐口 dump）；影响 `ping source <ip>` 的地址反查。
2. **残留 L2 桥接造成 ICMP 丢包**：若 ens192/ens224 同时挂在同一 bridge-domain（两张 vNIC 同在 VMnet8），会形成环路（VPP `l2-fwd Reflection Drop` 激增），VMware/NAT 随后不回 ICMP；清除 BD 并重启 VPP 后 ping 恢复正常（2/3）。排查此类"ping 不通"先查是否有环路残留。
