## 4. 本批教训（入册）

1. **底座能力必须在其目标版本上 spike 实证，且「CRC 吻合」≠「功能可用」**：本批两处底座缺口——VPP 26.06 的
   `vxlan_tunnel_dump`/`v2_dump` **恒空**（CRC 与 VPP 自带 `api.json` 及本仓 binapi **逐一吻合**，但用 govpp 按 V1/V2
   发 dump 都立即 `<stop>`、零条目），以及 **`policer_classify_dump` 返回不了绑定**。分别导致 VXLAN 身份改 tag、
   storm control 改 `classify_table_by_interface`。**做法**：写独立 govpp spike 直连 `/run/vpp/api.sock` 实测，
   别只信 binapi 存在。
2. **同一类误判只在某个字段上修过，换个字段就漏**（#382）：路由差分的键早为 `distance` 排除了该坑（key 不含 distance），
   但**下一跳**没例外 ⇒ 改下一跳生成 `del-route`，而 del 段在 `ApplyVRF` **之后**执行 ⇒ 刚下发的新路由被同提交删掉
   （真机 `vppctl show ip fib` 全库查无、配置与读视图一切正常——**数据面黑洞**）。**通用判据**：
   「差分撤销」的键必须是**对象身份**（前缀/名字），不是它的可变参数；同键变更交给 Apply 路径的**替换**语义。
3. **只读代码会漏掉「持有层」这一层**（#375）：REST handler 的 `s.containers == nil` 分支永不命中（持有层非 nil、只是未接入）
   ⇒ 「Docker 启动时即不可达」落 500。**真机是唯一出口**。
4. **套件偶发失败也要定根**（#376）：`TestMetricsHistoryTruncatedAndLimit` 隔离下 5/5 通过、负载下偶发失败 ⇒
   定根为 #372 A8 的收窄锚点取墙钟 `until`（丢掉本应保留的旧点），另立决策修复。**「偶发」背后常是时序假设被放大成真缺陷**。
5. **可复现现场优先于推理**：R140-1 当初记录含混（「删除后仍吞包」vs「删除后条目仍在」），本批找到**可复现变体**
   （同域改 relay server ⇒ 旧条目未撤 ⇒ 删除后残留 + FIB `DHCP:` 锁）才把它统一解释并根治。
6. **排查「策略没生效」先怀疑流量没进路径**（#385）：packet-generator 的 **rx 接口必须与被测策略所在接口一致**
   （用 `pg-1` 作 rx 时策略不生效）、**16 字节帧会被当 runt 丢弃**（须补足 64 字节整帧）、
   **观测点要选对**（BVI 上的 flooded 副本会因非法载荷以太类型被丢 ⇒ 看 bvi1 的 rx 会得到「无变化」的假结论；
   `l2-flood` 计数才是直接量）。
7. **删了没删干净」的温床是「登记 vs 实况」脱节**（#385 缺陷②）：解绑必须按**实况**（并核形状认领），
   登记只作兜底；**挂上方向绝不容忍 `VALUE_EXIST` 等错误**（静默吞掉就是假成功）。
8. **提交纪律**：`NO_VERIFY=1` 提交后**必须补跑** `make check`；宿主内存紧时用 `GOFLAGS="-p=1" make check` 串行。

## 6. 工作方式（照旧，必须遵守）

**契约先行**（附录 A 决策行 + 契约文档（openapi/命令树/命令全表/手册）+ `AGENTS.md` 决策计数）→
**能力前提核实**（新底座/新 API **先 spike**，见教训 1）→ **子智能体实现**（提示写死口径；**产出先 commit**）→
关键点审查 → **PR base `v2`** → **真机四维验证**（作用效果 / 生命周期 / 跨对象 / **对抗性**；
关键功能要有**独立事实源**的定量对照，不得只看命令成功）→ `docs/evidence/v2-roundNN-*.txt` →
squash 合并 → 账目同步（`v2已做.md` / `v2待做.md` / `AGENTS.md` / 本交接）。
**「不留假功能」**：实现或契约与真机结论相悖即撤回/改写；**不可验证的维度如实登记，不伪造读数**。
