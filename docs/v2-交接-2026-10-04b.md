## 4. 本批教训（入册）

1. **子智能体产出先 commit，再动任何 git 还原类命令**：本会话**两次**用 `git checkout -- <file>` 误还原
   **未提交**的实现（第二次才长记性）。恢复路径：子智能体会话记录在
   `~/.zcode/cli/rollout/model-io-sess_subagent_agent_*.jsonl`，其中的 `Write`（整文件）/`Edit`（old/new 片段）
   工具参数可**重放恢复**（本会话两次都这样救回）。
2. **「超时就关连接」必须先分清「排队」与「执行中」**（#362 审查抓到）：排队超时关连接会**误杀前面正在执行的
   合法长 RPC**（快照创建恰逢 15s 探活即中招）⇒ 排队＝`ErrConnBusy`（探活按健康跳过）、执行中＝判假死关连接。
3. **文件 unlink ≠ 状态清零**（#365 真机暴露，A4 同族）：运行中的 SQLite 连接**持已删 inode**——读视图继续
   显示旧数据、磁盘空间不释放（实测 60 序列/80,598 样本 + `lsof` 12 个 `metrics.db (deleted)`）；修法＝
   「文件被删/替换 ⇒ 关旧连接重开」（`ReopenIfReplaced`），并**在读路径入口**调用以消除中间态。
4. **`format-data` 会重置 `resource-pools`**（设计如此、文档已写）：破坏性验收后必须重新声明资源池，
   否则夹具/VNF 提交校验会正确拒绝（「页大小 1G 无对应资源池」「隔离核不足：需要 1，可用 0」）。
5. **单测不得触碰生产路径**：format-data 类用例要把**全部**受管路径指向临时目录（零值 `Config` 的缺省指向
   `/var/lib/nfvis/…`，在真机上跑会误删现场）——本批新增 `testManagerConfig` 堵上。
6. **用户可见文本守护有效**：手册里写「（决策 #365…）」被 `archtest.TestUserVisibleTextHasNoInternalRefs`
   当场拦下；写手册/部署脚本时不要带内部编号（判据是「会不会到达操作者」）。
7. **故障注入要先自证生效**（#360）：`os.Remove` 对**空目录**同样成功 ⇒ 首版「punt 路径不可绑」注入被产品
   自清、实验静默走成功路径；改**非空目录**才稳定失败。同类：探针/守卫「没触发」≠「存在」。
8. **套件正控对现场时序敏感**（见 §3）：判定「回归」前先看是不是正控未热；本批每轮的 L3-2 跳过都属此类。
