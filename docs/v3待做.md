## 一、功能候选池（自 v2 待做移出；已承诺方向、未承诺时点）

### 网络数据面

1. **tap 接口 VM 接入**（差距分析 §一 6）——决策 #2 后置；现有 vhost-user / SR-IOV VF / memif 三种接入；
   兜底兼容非大页 VM（FR-NET-024 移 V2）。规模中。
2. **SNMP（v2c/v3）**（§一 7）——网络设备基本盘，全 0 命中（决策 #17 后置）。开工前先定 MIB 范围与只读/读写档。规模中大。
3. **sFlow/NetFlow/IPFIX 流量采样**（§一 8）——0 命中；开工前先定采样器形态与导出目标。规模中大。

### AAA 与安全

4. **RADIUS/TACACS+ 外部认证**（§一 10）——0 命中；现状仅本地用户 + class（外部 AAA 仅「预留」表述）。规模中。

### 计算编排

5. **VM 热迁移**（§一 13）——0 命中；依赖共享存储/双机形态。规模大。
6. **vCPU/内存/vNIC 热调整**（§一 14）——现仅关机状态可改（FR-CMP-012：热调整列 V2）。规模中大。

8. **外部镜像仓库对接（Docker Registry 协议 pull）**（§一 18）——现仅本地上传 + URL 拉取（FR-CMP-034 移 V2）。规模中。

10. **企业级镜像治理（签名验证/漏洞扫描）**（§一 20）——0 命中，商用化前置。规模大。

### 系统与运维

11. **整机镜像 A/B 升级**（§一 21）——现 `request system software add` 为 deb 级升级。规模大。
12. **自动定期配置备份**（§一 22）——现在只有手动 `request system configuration backup`。规模小-中。
13. **多节点集群与集中管理**（§一 23）——0 命中（单机定位，但功能清单上为零）。规模大。

### 自 v2「新发现空白」移出（含后续声明属 v3 的余量）

14. **组播（IGMP/multicast）**（§三 6）——全 0 命中（POC 定位下优先级低；若做组播转发/侦听需先定范围）。规模中大。
15. **事件外推 webhook**（§三 8）——告警出口只有远程 syslog 转发 + SSE 拉流；对接不了外部监控/工单系统的推送。规模小-中。
16. **独立 API 凭证（API key / 只读机器凭证）**（§三 10）——当前唯一凭证就是登录 Bearer token（REST/Web/CLI 桥共用一套）；
    与 v2 清单二.1（R79-1）的根治口径（会话与身份键分离）相关，**建议合并立项**。规模中。
17. **License / 授权管理**（§三 11）——0 命中（商用化前置）。规模中大。
18. **标准北向（NETCONF/RESTCONF/YANG）**（§三 12）——远期；现阶段 OpenAPI 已够用。规模大。
19. **STP/RSTP 与自动 blocking**（§三 2 余量）——v2 已收口 v1 的检测告警（`LOOP_SUSPECTED`）与 `learn-limit` 缓解；
    **破环本身未做**（VPP 无实现、内核 bridge 默认不开 STP），属 v3 待实现，开工前先定裁形态（两侧数据面的等价物不同）。规模中大。
20. **层级 shaper / 优先级队列 / 丢弃策略**（§三 5 余量）——v2 已收口出向限速（同策略可绑入/出向）；
    **层级 shaper / 优先级队列未做**，属 v3 待实现。规模中大。
21. **v6 的 DHCP/ND 业务面**（§三 4 余量）——v6 的诊断、ACL（含数据面 enforcement）、NAT44 校验期拒绝均已收口；
    **DHCPv6 / ND 等业务面待实现**，视 v3 立项（NAT66/NAT64 插件未接另计）。规模中大。

## 五、round41 新登记（2026-10-21，v3.0.23 发布件走查）

> 来源：`docs/evidence/v3-round41-clean-install-walkthrough-vpp-kernel.txt`。
> 本轮在**发布件**上完成了 VPP/内核双数据面全功能走查与数据面往返，四套件零失败
> （fulltest 297/0/26、语义 43/0/0、lifecycle 40/0/3、pty 10/10，与 v3.0.22 逐项一致）；
> 以下两条为走查中发现的**口径**项（无功能性缺失，但会让同一事实读出不同数字 / 误判命令失败）。

34. **R41-1（中）交换机「成员端口」同一事实三个数，契约未说明**——最小复现（rev 187~189）：
    只配 `set virtual-switches cal-test type l2` + `gateway ip 192.168.77.1/24`（产品据此建 BVI），
    则 `GET /virtual-switches` 该对象 `ports` = **null/0 条**、`GET …/ports` = **1 条**（bvi1,
    source=runtime）、CLI 列表 Ports 列 = **1**、CLI `show … ports` = **1 条**。
    更早的大现场（vs-lan 有 1 静态 + 2 VNF 派生 + 1 容器派生 + 2 运行态）出现
    **CLI 列表 3 / REST 列表 1 / ports 端点 6** 三数并存。
    根因：`internal/api/resources.go:346 handleGetVSwitches` 直接序列化 `model.VirtualSwitch`，
    其 `ports` 是**配置原始端口**；`/ports` 端点与 CLI 走 `switchPortViews`
    （`model.DerivedSwitchPorts` ∪ 运行态，并剔除内置 DHCP tap）。
    `docs/NFViS-openapi.yaml` 的 `VirtualSwitch.ports` **无 description**，读者无法分辨口径。
    影响：按列表 `ports` 判断「这个口在不在某交换机」会漏掉 VNF/容器派生与运行时口
    （bvi0/bvi1、vxlan、VNF vhost、容器 veth）——与 AGENTS.md「同一事实两视图必须并排读、
    口径须同一」红线相违。**修法待定裁**：① 契约补 description（列表＝配置声明，
    成员读视图见 `/ports`）；② 或列表改名/加 `ports_declared_count` + `ports_runtime_count`。
    **须先定口径再改实现**（改字段名是契约变更，属破坏性）。

35. **R41-2（中）内核数据面下已配 NAT 规则时 `show nat` 整条命令失败**——
    现场：`set system dataplane kernel` + 已配池/规则，VPP 侧同配置下 `show nat` 正常（rc=0）。
    内核下：先打印配置段（池/规则），随后 `%% 该能力在 Linux 内核网络数据面下不受支持：NAT 会话表`
    ⇒ **CLI 退出码 1**（`show nat sessions` 同）。对照同族 `show vxlan tunnels` 在内核下是
    **行内降级**（「运行态不可用（…不受支持…）」，配置字段照给，**退出码 0**）。
    REST 侧 `GET /nat`=200、`GET /nat/sessions`=**501 NOT_IMPLEMENTED**（这条是对的）。
    根因：`internal/api/cli_net_runtime_show.go:404 execShowNat` 把 `x.natRT.Sessions()` 的错误
    **原样带 `%%` 返回**，于是被 CLI 脚本模式判成「命令执行失败」。
    影响：内核数据面下任何 `show nat` 脚本/巡检都会判失败并**中止后续行**（`-c`/`-f` 在第 1 行停止），
    把「该能力在此数据面不存在」误报成「命令坏了」；与 `internal/api/rest_501_test.go` 已确立的
    「能力不受支持 ≠ 服务异常」口径不一致。
    **修法方向**：把 `netkernel.ErrUnsupported` 一类**能力哨兵**在 CLI 渲染层转成行内降级
    （照 `show vxlan tunnels` 既有做法），退出码 0；真实执行故障仍保留 `%%`。
