> 这三条在 `docs/v2待做.md` 第三节的对应条目里写明「属 v3 / 视 v3 定」，但此前未在 v3 侧落点；

## 三、数据面可切换（决策 #404）的未实现族

> 决策 #404 落地「VPP / Linux 内核网络」双数据面。**已实现**：物理口、bond、L2 交换机、
> L3 交换机、静态路由、NAT44、VXLAN、VNF vNIC 接入、诊断、**ACL、QoS 端口限速、端口镜像、
> 风暴抑制、端口安全**（后五族经真机内核验证，见 `docs/v3-数据面可切换-设计.md` §6.1）。
> 以下族在**内核数据面下提交期直接拒绝**，逐个补齐后从本清单移除（每族都要走契约先行 +
> 真机验证）。

1. **DHCP 中继**——内核侧对应 dhcrelay 或自研转发器；VPP 侧走 dhcp proxy 按 rx-VRF 中继。
   需要一个常驻用户态组件，属独立立项。
2. **DHCP 服务器**——内核侧对应 dnsmasq/kea 或自研；VPP 侧是「用户态服务器 + 每交换机一条
   内置 L2 tap + UDP/67 punt」。同样需要常驻组件。
3. **数据面 DNS 代理**——内核侧对应 dnsmasq 或自研域内转发器。**现状**：按域语句
   （`set virtual-switches <vs> dns proxy server`）提交期直接拒绝；全局上游（`set system dns proxy server`）
   属 `vpp` 段配置——提交给「vpp 段不生效」警告（不拒绝），该数据面下不提供服务。
4. **LLDP**——内核侧对应 lldpd 守护进程对接（读邻居表）。
5. **memif 容器接入**——内核侧无对应物；容器 vNIC 需另行设计（veth + bridge 是可选方向）。
6. **MAC 学习上限**——内核 bridge 无「学习条数上限」原语，需要替代方案（如 fdb 计数 + 告警）。
7. **抓包**——VPP 侧是 pcap trace；内核侧可用 tcpdump，但导出/下载/会话生命周期需要重做。
8. **VPP 专有口径**：`show vpp *`、`request vpp restart`、DPDK 接管、大页池的「数据面占用」
   列在内核数据面下**按设计如实报不支持**（不是待做项，是口径）。

> 另有两条**已实现但真机未验**（登记在 `docs/v3-数据面可切换-设计.md` §6.2）：VM 侧
> virtio + vhost-net 接入的连通性、安装器 `--dataplane kernel` 的整机流程——**均已真机验证并关闭**
> （见 `docs/evidence/v3-round1-clean-snapshot-datapath-switch.txt` §3/§10；NAT 真实转发见 §11）。
> 当前仍未验证的如实边界（`.run` 完整闭环、规模/吞吐、本批修复的真机复核状态等）见设计 §6.2。

### 本轮登记：新增提交期拒绝与口径差（按「已实现并拒绝 / 已实现 / 待实现」分类）

| 项 | 类别 | 现状 |
|---|---|---|
| 静态路由**多下一跳（ECMP）** | 已实现（提交期拒绝） | 内核侧无实现（`via a,b` 会被 iproute2 当非法参数炸掉整次提交）；提交期拒绝并提示拆成多条单跳 |
| `cross_connect`（点对点直通） | 已实现（提交期拒绝） | 内核侧只有学习/泛洪形态的桥，静默降级＝改变语义；提交期拒绝 |
| **NAT 规则跨转发域** | 已实现（提交期拒绝） | 内核 nft 不区分转发域、无跨表 leaking，规则恒不命中；提交期拒绝 |
| ~~`nat static` 的**跨域语义**~~ | **已定裁并落地（#419）** | 内核数据面下**多转发域配置即提交期拒绝** `nat static`（判据 = `vrfs[]` 全部条目 ∪ 带地址网关的 L2 网关 VRF，按内核 VRF 设备名去重；单域/全默认表放行；**VPP 不受限**）；文案点名歧义与涉及的域 + 替代。用户手册 §8.8、命令树与设计文档的拒绝清单已同步；红-绿用例覆盖判据表与端到端五态。 |
| VNF vNIC 接入 **type=l3 交换机** | 已实现（提交期拒绝） | 内核侧 l3 交换机不建桥，tap 无处可挂（起 VM 才失败）；提交期拒绝并指向「已配网关的 L2 交换机」 |
| **派生内核设备名撞名** | 已实现（提交期校验） | 两个对象（或对象与派生的网关 VRF 名）映射到同一内核设备名即拒绝；`naming.go` 的长度截断改用**全宽哈希**、注释口径与实现一致（`model` 侧同规则映射由测试钉住同步） |
| **ACL 链重建窗口** | 待实现（如实登记） | nft flush → 逐条重建非单事务，存在毫秒级 fail-open 窗口；改善需要「单事务下发」能力，不在本轮范围 |
| 诊断 **`count` 口径差** | 已实现（内核侧）/ VPP 侧无上界（如实登记） | 内核侧 `count` 上界 100（越界报错、不静默截断，另有 30 s 内部超时上界）；VPP 侧沿用无上界（受同档 30 s 内部超时约束）——两数据面口径差如实登记 |
| 诊断参数 **`-` 前缀守卫** | 已实现（内核侧） | 内核侧目标 / 源地址 / VRF 名以 `-` 开头直接拒绝（否则会被底层工具当选项解析）；**该守卫只在核内核侧**，VPP 侧沿用原样 |
| **风暴两档同配的口径** | 已实现（与 VPP 说明对齐） | 广播档不继续遍历（与 VPP 一致：广播帧只落广播档）；只配组播档时广播帧按目的 MAC 的 I/G 位落入组播档；同接口多族（QoS/风暴/镜像）经 `continue` 判决共存 |
| ~~**`cross-connect` 的 CLI 形态不一致**~~ | **已收口（随后一轮）** | 命令树叶子改为与模型同源的**显式取值开关**（`cross-connect true\|false`，按仓库既有布尔叶子写法），取值别名、`display set` 反推与文档（命令树设计、命令全表、手册）同步，并补「语句 → 模型」红-绿用例与候选守护。真机（dev4）复核：`set virtual-switches <n> cross-connect true` 返回 `[ok]`，提交被**内核侧**正确拒绝（不再出现 JSON 解码内部错）。 |
| ~~**删除交换机端口的叶子后留「空壳端口」**~~ | **已收口（随后一轮）** | 删除路径的合流点新增 `pruneEmptySwitchPorts`：`interface`/`vnf`/`container` 取值全空（vnf/container 还须无配套接口名）即回收该端口条目；**只在删除路径**生效、不重排 seq，`set` 路径的分步构建不受影响。真机（dev4）复核：删叶子后一次 `commit` 成功（修复前被「端口必须且只能指定…」拒绝）。 |
| **内核 tc 的 QoS/风暴计数不映射三档** | **已定裁：保持如实不映射（#420）** | 内核 `tc -s` 的 police 只有 dropped/overlimits，与 VPP 的 conform/exceed/violate 不对应；读视图继续如实说明「不映射」（**不把 dropped 猜成 exceed 造假读数**）。将来若要三档计数，须改用 tc 的三色 policing（`avrate`/peakrate）并重做限速语义与读视图，按新立项评估。 |
| **DPDK 接管不跨主机重启持久** | **已定裁：保留现状（#420）** | 主机重启后两块业务口回到 `vmxnet3`；产品不持久化（不设 `driver_override`、无 udev 规则、无配置项），但**如实报出**（`show interfaces physical` 报「已声明未生效」、恢复重放给照做指引），且**文档已覆盖**（用户手册 §5.3/§5.4 的「重启后的固定动作（数据口绑定不跨重启）：`request interfaces <数据口> bind-dpdk --yes` → `request vpp restart`」）。启动期自愈重绑（选项 A）与启动期点名告警（选项 C）**不实施**；如需自愈按新立项评估。 |
| **失败提交后的补偿残渣（观察项）** | **未复现（已降级）** | 真机（dev4）做「成员 up 导致 bond enslave 失败」的失败提交后，人工清场时曾见到一个空的 `b0`（DOWN 态，无告警）。**随后一轮做受控复现未成立**：用 apply 期确定性失败（不可达下一跳）造现场，补偿干净——链路 0 / 接口地址 0 / 本产品 nft 表 0、`show alarms` 无 active。且原触发路径已随「bond 成员先 down 再 enslave」的修复消失；无单独处置，保留为历史观察。 |
