## 三、数据面可切换（决策 #404）的未实现族

> 决策 #404 落地「VPP / Linux 内核网络」双数据面。**已实现**：物理口、bond、L2 交换机、
> L3 交换机、静态路由、NAT44、VXLAN、VNF vNIC 接入、诊断、**ACL、QoS 端口限速、端口镜像、
> 风暴抑制、端口安全**（后五族经真机内核验证，见 `docs/v3-数据面可切换-设计.md` §6.1）。
> 以下族在**内核数据面下提交期直接拒绝**，逐个补齐后从本清单移除（每族都要走契约先行 +
> 真机验证）。

1. **DHCP 中继**——内核侧对应 dhcrelay 或自研转发器；VPP 侧走 dhcp proxy 按 rx-VRF 中继。
   需要一个常驻用户态组件，属独立立项。
2. **DHCP 服务器**——内核侧对应 dnsmasq/kea 或自研；VPP 侧是「用户态服务器 + 每交换机一条
   内置 L2 tap + UDP/67 punt」。同样需要常驻组件。
3. **数据面 DNS 代理**——内核侧对应 dnsmasq 或自研域内转发器。
4. **LLDP**——内核侧对应 lldpd 守护进程对接（读邻居表）。
5. **memif 容器接入**——内核侧无对应物；容器 vNIC 需另行设计（veth + bridge 是可选方向）。
6. **MAC 学习上限**——内核 bridge 无「学习条数上限」原语，需要替代方案（如 fdb 计数 + 告警）。
7. **抓包**——VPP 侧是 pcap trace；内核侧可用 tcpdump，但导出/下载/会话生命周期需要重做。
8. **VPP 专有口径**：`show vpp *`、`request vpp restart`、DPDK 接管、大页池的「数据面占用」
   列在内核数据面下**按设计如实报不支持**（不是待做项，是口径）。

> 另有两条**已实现但真机未验**（登记在 `docs/v3-数据面可切换-设计.md` §6.2）：VM 侧
> virtio + vhost-net 接入的连通性、安装器 `--dataplane kernel` 的整机流程。
