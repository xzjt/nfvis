## 1. 用户定的三条工作口径（必须遵守）

1. **涉及 Web 的一律用 Browser Use 实机验证**（不是只看 DOM/守护测试）；且验证前**先确认页面加载的是当前构建**
   （升级后旧标签页/缓存会把旧 JS 呈现成「修复无效」），**可见性一律用 computed display/offsetParent 逐 id 判定**
   （不得用 `querySelectorAll('button')` 全集或 `innerText` 关键字命中来推断「可见」）。
2. **涉及数据面可以自行启动 VNF 验证**（可用 `contrib/scripts/cli-semantic-fixture.sh up` 造流量现场）。
3. **不留「不可判定」**：跑套件时先造好现场（对象/流量），让 UNKNOWN 项变成可判定；
   但**不得把 UNKNOWN 改成通过**（没正向控制时就该如实报 UNKNOWN）。

## 2. 工作流（每条决策都这样走）

1. **契约先行**：先改 docs 契约（命令树设计/命令全表/openapi/覆盖核查）+ 规格书附录 A 追加决策行 + AGENTS.md 决策条数；
2. **派子智能体实现**（提示里写死口径；注意：本会话中 Agent 调用**多次被「interrupted before resume」中断**，
   遇到时直接**重发**即可，第三次通常就成功；子智能体产出的报告要审）；
3. **审查**关键安全/一致性点（授权判定、写路径单源、假绿风险）；
4. **PR → base `v2` → squash 合并**（本会话用 `gh pr create --base v2` + `gh pr merge --squash --delete-branch`，均可直接成功）；
5. **真机验证**（见 §4 环境与纪律）→ 写 `docs/evidence/v2-roundNN-*.txt` → 提交推送。

### 4.3 验证纪律（本会话反复踩坑、务必遵守）
- **退出码不经管道**（`OUT=$(cmd | tr …); echo $?` 取到的是 `tr` 的状态）——重定向到文件再读 `$?`。
- **判定失败要锚定**：`grep -c '^%%'`；注意有的失败走**「校验失败（candidate 保留）」+ `%` 前缀**（脚本模式），只查 `%%` 会漏。
- **造现场的命令输出整段保留、先看错误行**，不得用 `grep -c` 把失败压成一个数字就往下走。
- **清场是硬性前置**：套件跑前清上轮对象；套件之间也可能需要清（`#323` 起 `cli-fulltest` 会自清场）。
