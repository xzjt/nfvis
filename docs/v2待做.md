## 一、账面欠款：规格书已承诺推迟、至今未做（9 条；原 11 条中第 10/11 条已由 #309/#305 收口）

### 网络数据面

1. **动态路由协议（OSPF/BGP）**（差距分析 §1-1）——完全未做；架构已预留 Linux-CP + FRR 扩展路径
   （vpp plugins 里 linux-cp 开关已暴露），决策 #6。
2. **VXLAN overlay**（§1-2）——全 0 命中。
3. **VRRP 网关冗余**（§1-3）——全 0 命中。
4. **静态路由 ECMP（多下一跳）**（§1-4）——0 命中。
5. **storm control / port security / MAC 数量限制**（§1-5）——0 命中。
   （注：决策 #337 的 `learn-limit` 是**环路缓解**，不等于本条的 storm control / port security 体系。）

### 可观测性

6. **ACL 逐规则命中计数**（§1-9）——决策 #68 的技术债。**已尝试并撤回（决策 #339，round118 真机实证；
   实现随 PR #265 回退）**：计数注册确在 stats segment（`/acl/<idx>/matches` 组合计数，口径以 VPP 源码定死），
   但**VPP 26.06 只注册、不写该计数**（启用全局 `acl_stats_intf_counters_enable` + 重绑定后仍恒 0），
   读视图恒 0 会误导故整体撤回。**对 #68 的更正**：「调该 API 会被误执行为 `acl_del`（危险）」实测不成立
   （请求 CRC 两面一致、正常执行；报错是 govpp 对**空应答** CRC 碰撞的识别噪声）。
   **后续路线**：a) 待 VPP 版本真正递增该计数后重启此能力；b) 退用插件 err 族计数（只有 permit/deny
   **总数**粒度、无逐规则）；c) 自研数据面计数通道（大，未评估）。

### AAA 与安全

7. **管理面主机防火墙策略配置**（§1-12）——0 命中（宿主 nftables 类管理）。

### 计算编排

8. **GPU 及通用 PCI 设备直通**（§1-15）——0 命中。
9. **容器 exec / 交互式终端**（§1-17）——容器只有 `log`，没有 exec。

## 二、已登记未修的缺口

**本节原 29 条已全部收口**（含 1 条误判撤回）——索引见 [`docs/v2已做.md`](v2已做.md) §二。
本节仅保留**环境受限、尚未取得证据**的项：

### 未验证（6 条，环境受限，与缺陷分开看待）

- **SR-IOV 全链路**（FR-NET-004/021）——nfvis-vm 为 vmxnet3，无 PF/VF 硬件；
  附带：`request sriov delete-vfs` 忽略 `vf <n>` 参数（决策 #94 已「诚实化」）。
- **LLDP 邻居表**（FR-NET-018）——环境无 LLDP 对端（启用与命令已验）。
- **容器 memif 通流**（T0-3 / FR-NET-022 容器侧）——离线无自带 memif 客户端的容器镜像。
- **真人 `Ctrl-]`**（T0-4 / FR-CMP-014）——需运行 VM + 真实交互 TTY。
- **§10 吞吐/容量类基准**——10GbE ≥14Mpps、vhost-user ≥8Gbps、≤10 VM/≤20 容器、恢复 ≤30s/≤3min；
  需流量发生器与目标硬件。
- **硬件健康极端场景**（FR-SYS-012）——VM 无 IPMI/温度传感器/smartctl（降级路径已验证）。

## 三、新发现：文档零登记、但同类产品标配的空白（原 8 条；**未做 5 条**，其余已收口）

（差距分析本节原编号 6、8、10、11、12 已移入 v3。**编号沿用原清单**；已收口部分见
[`docs/v2已做.md`](v2已做.md) §三——三.1 relay 半边 #335、三.2 环路检测 v1 #337、三.5 QoS 出向 #331、三.8 ping/traceroute #330。）

1. **DHCP server 本体**（差距分析 §3-1 余量）——relay 半边已收口（决策 #335）；
   **余**：DHCP server（租约池/状态机）与跨 VRF 的 server（v1 边界）。
   **附带未竟**：relay 的**端到端租约验证**——测试设备受环境工具链阻塞（guest 串口静默、无 exec、
   1G 大页仅 2 页），需换观测通道（修串口，或以预制带 DHCP server 的镜像）后补做（见 round113 证据 §3）。
2. ~~**L2 环路防护**~~——**已收口 v1（决策 #337）**：检测告警 + learn-limit 缓解；
   STP/RSTP 与自动 blocking 属 v3。
3. **DNS 转发/代理的数据面半边**（§3-3 余量）——`set dns server` 只是宿主解析器配置。**尝试未达已撤回
   （决策 #338，round116 真机实证）**：VPP 26.06 的 dns 插件**只在默认表解析上游**（binapi 无 VRF/fib 字段、
   CLI 无表参数），而产品 L3 域都是 VRF 且**无法在默认表配地址**——实测「客户端查询能到 VPP、VPP 永远发不出
   上游查询」（缓存永久 pending、pcap 无出向流量），配了就是假的。
   **后续路线（未立项）**：a) 补「默认表寻址」能力后再启；b) 待 VPP dns 支持按表/VRF；
   c) 自研域内 DNS 转发器（新服务，大）。**余**：管理网侧转发（宿主解析器已覆盖，深化另议）。
4. **IPv6 业务面完整性——余量**（§3-4）——**诊断侧已收口（决策 #330）**；
   **余**：NAT44 与 ACL 五元组的 **v6 覆盖专项核实**（另可选：v6 的 DHCP/ND 等业务面补齐，视 v3 定）。
5. ~~**QoS 深度**~~——**已收口出向（决策 #331）**；层级 shaper / 优先级队列 / 丢弃策略属 v3。
6. **历史时序数据**（§3-7）——`/metrics` 是即时快照、无时序存储；Web 总览 5s 轮询同样没有趋势图
   数据底座，容量规划与事后回溯无从谈起。
7. **`/metrics` 覆盖面**（§3-9）——`internal/metrics` 只采集宿主运行态（/proc 等）；
   VPP / VNF / 容器指标是否进 /metrics 未见证据（待专项核实）。
8. ~~**ping / traceroute 细项**~~——**已收口（决策 #330）**。

**另：ACL 线的口径提醒**（ACL 相关条目均已收口，见 `v2已做.md`）——ACL 只能绑 **L3 接口**
（网关/端口形态提交期拒绝，决策 #340）；绑定时产品自动放行非 IP/ARP（#341）。若将来底座支持其它形态，
须**先补命令树叶子**（契约先行）再启用（原 R119-1 的结论）。

## 四、v2 补齐顺序建议（按当前余量更新）

条目编号对本清单（「一.9」= 第一节第 9 条）。第 0 批与第 1 批（账面对齐、IPv6 诊断、QoS 出向、
DHCP relay、环路检测等）**已收口**，见 `docs/v2已做.md`。

- **第 2 批（剩余的网络 OS 基本盘）**：三.3 DNS 数据面代理（**先定路线**：默认表寻址 / 等 VPP / 自研）；
  三.1 DHCP **server 本体** + relay 端到端租约补验；三.4 余量（NAT/ACL 的 v6 专项核实）；
  一.6 ACL 逐规则计数（**依赖底座**：待 VPP 递增或退用 err 族总数）。
- **第 3 批（可观测性与运维治理）**：三.6 历史时序存储；三.7 `/metrics` 覆盖面核实。
- **第 4 批（计算编排深化）**：一.9 容器 exec/交互式终端；一.8 GPU/通用 PCI 直通。
- **第 5 批（平台化）**：一.1 动态路由（linux-cp + FRR）；一.2 VXLAN；一.3 VRRP；一.4 ECMP；
  一.5 storm control/port security/MAC 限制；一.7 管理面主机防火墙策略。
