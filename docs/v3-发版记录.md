- **内容（决策 #404~#410）**
  - **#404 开关与架构**：`system.dataplane vpp|kernel`（安装器 `--dataplane` / 向导第 1 问 / CLI 三处
    写同一事实源）；装配层按 committed 配置装配 `*network.L2Network`（VPP）或新增的
    `internal/orchestrator/netkernel`（`ip`/`bridge`/`nft`/`tc`）；两者实现**同一方法面**，装配与恢复
    巡检不分叉。缺省 `vpp`（既有安装升级后行为逐字不变），切换需重启服务生效。
  - **#405 第二批五族**：ACL（nftables，末尾隐式拒绝 + 非 IP/ARP 放行）、QoS 端口限速（tc police）、
    端口镜像（tc mirred）、风暴抑制（tc 按目的 MAC 分类）、端口安全（桥口关学习 + nft 源 MAC 白名单）。
  - **#406 安装期两套数据面的包都装**：`--dataplane` 只决定这次用哪一套跑，不决定装什么
    （气隙场景切回 vpp 无需二次安装）。
  - **#407 干净快照端到端验证**：内核集成用例 9/9 → `--dataplane kernel` 整机安装 **17/0/2** →
    经产品 CLI 下发并在内核侧逐条核对 → **一次提交 + 一次重启切回 vpp**（VPP 被拉起、无二次安装）。
    真机抓出并修掉 **11 条缺陷**。
  - **#408 真实转发验证**（宿主作对端）：六项 A/B 对照；补齐内核数据面域定义单测。
  - **#409 vhost-net VM 接入**：域定义 `<interface type='bridge'>` + `<driver name='vhost'>`、
    libvirt 自建 tap 挂在内核 bridge、宿主 `ping -n 20 <guest>` **20/20 0% 丢失**；
    修掉「vhost-user 型 vNIC 无条件要求大页」这条在内核数据面下不成立的约束。
  - **#410 NAT 真实转发**：`tcpdump` 在**转发方向**取证（规则在场源被 masquerade 改写为
    `192.168.99.1`，删掉后保持 `10.99.0.3`）；顺带修掉三条「命令成功、包全丢」型缺陷——
    产品从不设 `net.ipv4.ip_forward`、宿主 `FORWARD` 策略 DROP 吃掉数据面流量（改为产品自建
    `inet nfvis-forward` 挂 `forward priority -10`，只放行自己的数据面设备）、`delete nat` 残留空表。
  - 证据：`docs/evidence/v3-round1-clean-snapshot-datapath-switch.txt`（§1~§11）。
