## v3.0.22（2026-10-18）—— round39 真机走查六条缺陷收口（决策 #488~#493）+ 套件前置自举

- **tag** `v3.0.22` → **`v3 81f56b1`**（v3 线直提）；GitHub Release 四资产（deb/.run 各带 `.sha256` 旁车）。
- **本版由来**：在**恢复为「干净」快照**的 nfvis-vm 上走发布件真人路径（`nfvis-v3.0.21.run` 首装 18/0/0 →
  真 pty 向导 → 管理口/系统基线 → **VPP 全族** → **Web 黑盒** → **切内核** → **切回 vpp** 往返），
  六条缺陷全部为**真机复现 → 修 → 真机复验**（详见 `docs/evidence/v3-round39-clean-install-walkthrough-vpp-kernel.txt`）。
- **内容（决策 #488~#493）**
  - **#488（高）同交换机内 L3 地址迁移一次提交必失败**：`delete … l3-interface nic0` +
    `set … l3-interface nic1 ip address 192.168.200.1/24` 同提交 ⇒ VPP `-105 Address in use` + 整次回滚，
    只能拆两次提交。根因两处：plan() 的 `vrf[<名>]`（ApplyVRF 新）排在 `del-l3-if` 之前（ApplyVRF 只清
    **新声明里仍有**的接口地址），且 ApplyVRF 逐接口 clear→置表→add 按声明序先给后处理的口 add。
    修法：`del-l3-if` 前置（undo 仍 `ApplyVRF(旧)`）+ ApplyVRF 改**两趟**（先全清地址/置表、再统一配地址）。
  - **#489（高）NAT 的 inside 不随 L3 拓扑重算**：改完拓扑后 `show nat` 读视图正常，但 VPP 里 inside 仍是
    旧口 —— in2out 计数在涨、**0 会话**、`out2in: no translation`，只有手工重提规则才恢复。根因：只在 `nat`
    段本身变化时才排 `nat` 操作，而 inside/outside 是从「规则引用的 L3 交换机 l3-interface ∪ 挂其上的 vNIC
    ∪ 出接口所属转发域」**推导**的。修法：新增 `natDerivedInputs` 派生输入指纹（只含被引用对象），指纹变了
    就重放 `ApplyNAT`。
  - **#490（中）`l3-interface` 建出「半个对象」**：交换机未声明时该语句只建同名 VRF —— 列表看不见、详情报
    「不存在」、CLI **再也删不掉**（两种 delete 都报「无匹配配置」），只能整份 REST 候选改写。修法：
    `l3VrfOf(create)` 一并建出同名 `type=l3` 交换机（已存在时不动 type）。
  - **#491（中）`delete … type l3` 留无 type 空壳**：提交必被「type 必须为 l2 或 l3」打回。修法：清 type 后
    若只剩 name（裸壳）则整条回收。
  - **#492（中）同提交「DHCP 服务器换中继」必撞 `bind <BVI>:67`**：整次回滚，只能拆两次提交。修法：仅该
    方向把服务器停用前置；其余（含反向 relay→server）保持既有顺序逐字不变。
  - **#493（中）Web「历史趋势」图例色块空白**：内联 `style` 被 CSP（`default-src 'self'`，无 unsafe-inline）
    拦掉，色块退化透明；容器 exec「超时」框同族。修法：色块改类名上色（`.mh-sw-0…5`）、窄输入框改
    `.w-5em`；**不加 unsafe-inline**（不削 XSS 纵深防御）。守护三层（JS 无内联 style 键 / index.html 同禁 /
    图例类名↔CSS 配色成对），红-绿已验证。
  - **R39-T1（套件工具项，非产品缺陷）**：`cli-fulltest-phase2.sh` 的 S2-fw 段补「管理口前置自举 + 段末还原」
