## M4-2 资源池账本与分配

**关联**：FR-CMP-001~004、FR-SYS-010、FR-CFG-011①⑤⑨⑩⑪；任务 M4-2；决策 #39、#24。

**落地现状**：账本（`internal/model/resources.go` 的 `PoolLedger`）与四类校验在 M1/M2 已交付并由
`Engine` 默认校验链（`model.Validate` + `model.CheckResources`）执行；M4-2 本次补齐：

1. **账本语义修正**：`memory.backing=normal` 的 VM 用普通内存，**不占用大页池**（FR-CMP-019，决策 #39）。
   此前实现会为其扣减大页，导致无资源池时普通内存 VM 被误拒。
2. **契约回归**：`GET /resource-pools` 原返回 `cpu.{isolated,vpp_reserved,free,vm_allocated}`，
   与 OpenAPI `ResourcePool.cpu.{isolated_cores,numa,allocated[{vnf,cores}]}` 漂移，且缺运行态
   `free`/`vpp_reserved` 声明；按契约先行修正**契约 + 处理器**（契约见 OpenAPI，决策 #39）。
3. **健壮性**：未配置 `resource-pools` 时 GET 不再 nil panic，返回空视图。
4. 运行态视图抽为纯函数 `resourcePoolView(cfg)`，直接单测。

**单测**（本地，`make check` 全绿）：新增 normal backing 不占页/无池可建/混合 backing 三例；
`allocated` 按 VNF 名升序、`vpp_reserved`/`free`/`numa` 形状断言；覆盖率
`internal/model` 78.6%、`internal/api` 纳入全量测试。

**真机交叉核对**（nfvis-vm，新增 `test/integration/m4_pool_test.go`）：

```bash
cd /opt/nfvis/src/nfvis
go test -tags integration -count=1 -v -run TestResourceLedgerMatchesHostFacts ./test/integration/
--- PASS: TestResourceLedgerMatchesHostFacts
    真机 HugePages_Total=3 Free=1（VPP 等已占 2 页）
    真机：1G 大页 total=3 free=1；VPP 保留核=[4 5]；隔离核=6 个
```

断言：① 账本 1G 池总量 = 真机 `HugePages_Total`（3）；② 账本 `vpp_reserved` = 真机
`/etc/vpp/startup.conf` 的 `main-core 4` + `corelist-workers 5`（FR-SYS-010 先扣）；
③ 1 台 1G VM 账本占 1 页，且真机 `Free=1` 恰好可启动；④ 池缩减到存量之下 commit 报错
（FR-CMP-004）；⑤ `backing=normal` 在页池为 0 时仍通过（FR-CMP-019）。

**未验证项（如实标注）**：「`show resource-pools` 与实际 domain 一致」需真实 domain，
随 M4-3 创建 VM 后核对（vcpupin cpuset 与账本绑核、domain 内存与页池占用），证据记入
M4-3 一节。CLI `show resource-pools` 接线属 M4-12。
