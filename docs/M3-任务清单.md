## 任务清单

### M3-1 VPP 连接层（FR-SYS-007 版本锁定）

- **目标**：`internal/orchestrator/network/vpp.go` 实现 govpp 连接管理：连接/断开、断线自动重连、重连后触发恢复收敛、启动时版本校验（非 26.06 拒绝启动并给出明确错误）。
- **交付**：连接管理器 + 版本探测 + 单测（版本校验、重连状态机用假 socket/mock）。
- **验收**：VPP 未运行时 nfvisd 启动降级为告警而非崩溃；`systemctl restart vpp` 后自动重连并重放配置。

### M3-2 startup.conf 生成器（FR-SYS-008/009/010）

- **目标**：按 committed 配置生成 `/etc/vpp/startup.conf`：cpu（main-core / corelist-workers）、memory（main-heap-size / buffers-per-numa / hugepage-preference）、dpdk（**全局默认 + per-NIC 覆盖**两级、uio-driver）、plugins（acl/nat/span/lldp/bonding 等）。
- **约束**：worker 核 ⊆ 隔离核池且与 VNF 绑核互斥；hugepage-preference 与资源池页大小一致；变更产生 `pending_restart`（`/vpp/status` 暴露），`request vpp restart` 后清除。
- **验收**：单测断言生成文本（含 per-NIC 覆盖与回落默认）；改配置后 CLI commit 输出「需重启生效」警告；`vppctl show threads` 与配置一致。

### M3-3 L2 编排（FR-NET-010~012/015/016）

- **目标**：bridge domain 增删、端口挂接（物理口/bond/VLAN 子接口）、access/trunk VLAN、cross-connect、MAC 学习；`GET /virtual-switches/{name}/mac-table` 运行态。
- **验收**：真机上 CLI 建 L2 交换机 → 两张 vmxnet3 加入 → 对端可通（对外部网络或另一虚机）；`show virtual-switches <name> mac-table` 显示学到的 MAC；删端口后成员关系同步。

### M3-4 L3 编排 + BVI 网关（FR-NET-013/014，含 IPv4/IPv6）

- **目标**：VRF、L3 接口地址（v4/v6）、静态路由（含默认路由）、**L2 交换机的 BVI 三层网关**（BD 绑 BVI 入 VRF）；`GET /vrfs/{name}/routes` 运行态（FIB）。
- **验收**：真机验证 VM 经 L2 交换机跨网段互通（M4 前可用 VPP 自身两个接口模拟：一个在 BD、一个在 VRF）；网关 ACL 生效；IPv6 静态路由可下发。

### M3-5 ACL / NAT / SPAN / QoS 生效（规格书 §4.3）

- **目标**：ACL 绑定端口与 L3 接口（双向）、NAT44 源转换与静态映射、SPAN 镜像到分析口、端口限速（CIR/CBS）。
- **验收**：真机逐项可观测——ACL 命中计数增长且流量按预期 permit/deny；NAT 会话可查；SPAN 口抓包能看到镜像流量；限速后吞吐被限制在配置值附近。

### M3-6 bond（LACP/静态，FR-NET-017）与 LLDP（FR-NET-018）

- **目标**：bond 创建/成员增删/LACP active|passive|关闭；LLDP 全局与按接口开关、`GET /protocols/lldp/neighbors` 运行态。
- **验收**：bond 口可作为虚拟交换机端口与 L3 接口引用；`show bonds` 显示成员与 LACP 状态；`show lldp neighbors` 能看到对端（需对端支持 LLDP，可用相邻虚机验证）。

### M3-7 运行态聚合与剩余运行态端点

- **目标**：建立 `internal/state`（骨架 §2）作为 show/API 的运行态数据源；补齐 `/interfaces`（统计/链路）、`/interfaces/{name}/sriov` PUT（VF 创建）、`mac-table`、`routes`、`lldp/neighbors`、`/vpp/*`（status/config/restart）。
- **验收**：`show interfaces physical statistics` 显示真实收发包；`/vpp/status` 的 threads/buffers 与 vppctl 一致；sriov VF 创建后 VF 数变化可见。

### M3-8 恢复收敛（FR-OPS-010/011）

- **目标**：`internal/recovery` 启动收敛（committed ⇄ VPP 实际状态 diff → 补建/修正 → 不可收敛项转告警）；VPP 重启后自动重放。
- **验收**：手工在 VPP 侧删除一个 BD 后重启 nfvisd → 配置被恢复；无法收敛的项（如物理口被移除）进入 `/alarms` 而非阻塞启动。

### M3-9 CLI 操作命令接入（替换占位符）

- **目标**：`ping`、`traceroute`（支持 `vrf` 参数）、`monitor interfaces`、`clear interfaces statistics` 从占位符改为真实执行。
- **验收**：命令树与执行器一致（gen_test 覆盖）；真机可用。

### M3-10 集成测试与真机验收

- **目标**：`test/integration` 覆盖「建交换机 → 通流 → 改配置 → 收敛」主链路，跑在 nfvis-vm。
- **验收**：`make integration` 在 nfvis-vm 全绿；验收记录（拓扑图 + 命令 + 结果）附在 PR。

## 技术提示（勿凭记忆写调用代码）

- govpp binary API 结构体/消息随版本变化大：**写任何 VPP 调用前用 context7 查 govpp 与 VPP 26.06 文档**，查不到时以版本锁定的 binapi 生成结果与 VPP 源码为准（AGENTS.md「外部文档查询」）。
- VPP 侧实现以「配置 → VPP 对象」的声明式映射为原则：编排器只负责把 committed 配置收敛到 VPP，不在 VPP 里做状态判断（状态判断在 config/state 层）。
- 每新增一个运行态端点，先改 `docs/NFViS-openapi.yaml` 并在附录 A 记决策，再写 handler（M2 的 W9 守护会直接拦住未登记路由）。
