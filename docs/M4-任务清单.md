## 前置条件 M4-P0：验证环境就绪（阻塞 M4 真机项）

- nfvis-vm 已具备 libvirt 12、Docker、1G 大页（M3-P0 已装）；补充确认：
  - `virsh version`、`virsh net-list`、`/dev/kvm` 可用；QEMU 支持 `vhost-user`（`qemu-system-x86_64 -device virtio-net-pci,help | grep vhost`）。
  - Docker daemon 运行（`docker info`）；memif socket 目录规划（如 `/run/nfvis/memif/`）。
  - 1G 大页 ≥ 2 页（vhost-user VM 必需大页）；准备一个小体积测试镜像（qcow2，可 cloud-init）。
  - **vhost-user socket 需 VPP 侧创建**：确认 VPP 26.06 的 `vhost_user` 插件可用（`vppctl show plugins | grep vhost`）。
- 集成测试约定沿用 M3：build tag `integration` + 环境变量（`NFVIS_VPP_SOCK`、`NFVIS_LIBVIRT_URI`、`NFVIS_DOCKER_HOST`），无环境跳过，CI 不跑。

## 任务清单

### M4-1 libvirt 连接层与 domain XML 组装

- **目标**：`internal/orchestrator/compute` 的 libvirt 连接（`qemu:///system`）+ domain XML 生成：vCPU/绑核、大页内存（2M/1G 页池）、vhost-user vNIC、SR-IOV hostdev、串口、cloud-init seed ISO 挂载、数据盘。
- **交付**：`domain_xml.go`（纯函数，单测断言 XML 片段）+ libvirt 薄适配层（`_libvirt.go` 命名，沿用覆盖率排除约定）+ 连接/版本探测。
- **验收**：单测断言 XML（含绑核 cpuset、hugepage、vhost-user socket 路径）；真机 `virsh dumpxml` 与配置一致。

### M4-2 资源池账本与分配（FR-CMP-001~004）

- **目标**：按 committed `resource-pools`（大页页池 + 隔离核列表）建立分配账本：创建/修改 VNF 时分配 vCPU（绑核 + NUMA 亲和）与大页内存；删除归还；配额不足/池缩减被占用时 commit 失败并给出明细（缺多少核/内存/NUMA）。
- **交付**：账本（可确定性重算，避免持久化漂移）+ 校验（接 FR-CFG-011① 内存类型校验）；`/resource-pools` 运行态总量/已分配/空闲。
- **验收**：单测覆盖分配/归还/不足/缩减被占用；真机 `show resource-pools` 与实际 domain 一致。

### M4-3 VNF 生命周期（FR-CMP-010~013）

- **目标**：`ApplyVMFunction`/`DeleteVMFunction`：定义 domain（资源分配 + vNIC + cloud-init + 数据盘）→ 按 `autostart` 启动；`request virtual-machine-functions <name> start|stop|restart`；`GET` 状态来自 libvirt；删除级联 vNIC/VPP 端口/快照并二次确认。
- **交付**：ComputeProvider 实现 + 生命周期端点/CLI（`request ...` 族，契约已声明）；apply 计划中 VM 在资源池/网络之后。
- **验收**：真机创建 VM → `virsh list` 运行 → stop/start/restart → 删除后 domain 与 VPP 端口均清理；操作入审计（FR-OPS-031）。

### M4-4 vNIC 接入：vhost-user / SR-IOV / VPP 联动（FR-NET-020/021/023）

- **目标**：VPP 侧建 vhost-user socket（`VirtualEthernetHostvpp`）并与虚拟交换机/L3 接口挂接；VM 侧 virtio-net 指向该 socket；SR-IOV VF 直通 hostdev（占用 VF 时禁止其 PF 进 BD）；VNF vNIC 删除/迁移时同步 VPP 接口与 BD 成员关系；VM 关机（vhost-user 断连）时端口置 down 并告警。
- **交付**：网络 Provider 补 `ApplyVhostUser`/绑定、compute 侧 hostdev；断连检测与告警。
- **验收**：真机 VM 经 vhost-user 与 VPP 通流（ping 对端）；`vppctl show interface` 可见 vhost 口且状态随 VM 启停变化。

### M4-5 cloud-init 与串口 console（FR-CMP-014/016）

- **目标**：NoCloud seed ISO（user-data + SSH 公钥，meta-data 含 hostname/instance-id）；`request virtual-machine-functions <name> console` telnet-to-serial，`Ctrl-]` 退出，console 访问入审计（FR-OPS-032）。
- **验收**：真机注入 user-data 后 VM 内可见（如主机名/用户）；console 可进可退。

### M4-6 快照与附加数据盘（FR-CMP-015/018）

- **目标**：qcow2 快照创建/列出/回滚/删除（含数据盘）；附加 virtio 数据盘（空盘容量或镜像克隆），生命周期随 VM。
- **验收**：真机快照后回滚，VM 内文件状态符合预期。

### M4-7 容器编排（Docker + memif，FR-CMP-020~022）

- **目标**：`internal/orchestrator/container`：按 committed 创建容器（镜像、CPU/内存限制、env/command/args、重启策略），memif vNIC（VPP 建 memif endpoint + socket 挂载进容器）；start/stop/restart/删除；`GET 状态/日志`。
- **验收**：真机容器经 memif 与 VPP 通流；异常退出产生告警（FR-CMP-022）。

### M4-8 镜像仓库（FR-CMP-030~033）

- **目标**：`/images`：本地仓库目录、`/data/incoming/` scp 导入（成功自动清理）、HTTP(S) URL 拉取（进度/sha256/断点续传）、元数据（类型/大小/sha256/格式/备注/导入时间）、删除前校验引用；容器镜像经 Docker API 删除。
- **验收**：真机 URL 拉取 + sha256 校验 + 导入 VM；删除被引用镜像报错。

### M4-9 计算/容器的恢复收敛（FR-OPS-010/012）

- **目标**：`ComputeProvider/ContainerProvider.EnsureConsistent`：启动/重连后对比 committed 与实际 domain/容器，补建/修正缺失对象，不可收敛项转告警；VPP 重启后 vhost-user 重连恢复（FR-OPS-011）；整机重启后按配置自启 VNF（FR-OPS-012）。
- **验收**：真机手工 `virsh undefine` 一个 VM 后重启 nfvisd → 被补建；不可收敛项进 `/alarms` 不阻塞启动。

### M4-10 运行态端点与告警接入

- **目标**：补齐 `/virtual-machine-functions/{name}/console|snapshots`、`/container-functions/{name}/logs`、VM/容器状态字段、资源池分配视图；VM/容器异常退出触发 critical 告警（FR-CMP-017/022，接 M3-8 `AlarmStore`）。
- **验收**：端点注册（W9 守护）+ 真机状态/日志可用；kill QEMU 进程后 `/alarms` 出现 critical。

### M4-11 集成测试与真机验收（FR-OPS-012）

- **目标**：`test/integration` 扩展覆盖「建交换机 → 建 VM（vhost-user）→ 通流 → 改配置（vCPU/内存）→ 删除归还资源」「建容器（memif）→ 通流」；真机验收记录（拓扑 + 命令 + 结果）。
- **验收**：`make integration` 在 nfvis-vm 全绿（无环境跳过）；验收记录附 PR。

## M4 Done 定义

1. M4-P0、M4-1~M4-11 全部完成；
2. `make check` + `/contract-check` 全绿，契约零漂移（新增运行态端点先改契约）；
3. nfvis-vm 现场演示：VM（vhost-user）创建/启动/console/快照/删除、容器（memif）创建/通流、镜像 URL 拉取导入、资源池分配与归还；
4. `virsh undefine` VM / 手工删容器后重启 nfvisd → 恢复收敛；整机重启后按配置自启；
5. 覆盖率门槛不下降（新增 `internal/orchestrator/compute`、`container` 纳入门槛或按 `_libvirt.go`/`_docker.go` 薄适配层排除，需在任务内明确）。

## 技术提示（勿凭记忆写调用代码）

- **libvirt**：domain XML 元素与 go 绑定版本敏感（libvirt 12），写 XML/连接前用 context7 或官方文档核对；真机 `virsh dumpxml` 为准。
- **Docker Engine API**：字段随版本变化，用官方 API 文档核对（context7）。
- **VPP vhost-user/memif**：`vhost_user`/`memif` 插件参数与 socket 路径以 VPP 26.06 实测为准；govpp binapi 结构以版本锁定为准。
- **cloud-init NoCloud**：seed ISO 卷标 `cidata`、`user-data`/`meta-data` 文件名，以 cloud-init 官方文档为准。
- **资源账本**：以 committed 配置确定性重算，避免"持久化分配表 + 配置"双源漂移（事务 rollback 后必须一致）。
