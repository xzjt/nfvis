## D. 技术方案（已设计，待实现）

### D-1 govpp v0.13.0 stats 限制的解决（三层，建议按顺序）

**实测事实**：govpp pinned v0.13.0（上游最新仅 v0.14.0-alpha）；statsclient 能正确解码接口计数/内存/线程，**只有 buffer 池与 ACL 受影响**；**VPP 自带 `/usr/bin/vpp_get_stats` 可用**（同版本解码保证正确，支持 `dump|ls|poll` + `machine` 格式 + 路径 pattern），实测 `/buffer-pools/default-numa-0/{used,available,cached}` 数值正确。

1. **第一层（当天可完成，推荐先做）**：在 `internal/orchestrator/network/stats_linux.go` 增加"同版本工具回退源"——statsclient 解码失败/缺项时改调 `vpp_get_stats dump machine [pattern]` 解析（每行 `value /path`）；`show vpp buffers` / `/metrics` 增加**来源标注**（`statsclient|vpp_get_stats`）与"不可用+原因"，不静默省略。先解决 buffer 池（FR-SYS-005）。
2. **第二层（ACL 计数，两步）**：① ACL 绑定时调用 binapi **`ACLStatsIntfCountersEnable`**（govpp binapi 已含该消息）开启计数；② 用 `vpp_get_stats dump machine '/acl*'` 确认真实路径后解析。**若开启后仍无条目** → ACL 命中计数正式降 V2 并改规格书（勿改为解析 `vppctl` 文本）。
3. **第三层（中期，V2 候选）**：升级 govpp（仅 alpha，牵动全部 binapi，升级前须在 nfvis-vm 跑全量 `make integration`）；或自解析 stats segment（格式自描述、跨版本稳定，~300 行 + 单测，去掉 statsclient 与子进程依赖）。
