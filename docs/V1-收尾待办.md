## 3. 环境要点（真机前必读）

### 3.1 常用命令

```bash
# 从开发机同步代码并构建（VM 直连 proxy.golang.org 不通，须用 GOPROXY）
git archive --format=tar.gz -o /tmp/nfvis.tgz HEAD
scp -q /tmp/nfvis.tgz nfvis-vm:/tmp/
ssh root@nfvis-vm 'export PATH=$PATH:/usr/local/go/bin; export GOPROXY=https://goproxy.cn,direct; \
  rm -rf /opt/nfvis/src/nfvis && mkdir -p /opt/nfvis/src/nfvis && tar -xzf /tmp/nfvis.tgz -C /opt/nfvis/src/nfvis && \
  cd /opt/nfvis/src/nfvis && go build -o /tmp/nfvisd.new ./cmd/nfvisd && go build -o /tmp/nfvis-cli.new ./cmd/nfvis-cli && echo rebuilt'

# 起 nfvisd（开发用明文；**默认是 HTTPS**，见 3.2）
ssh root@nfvis-vm 'pkill -x nfvisd >/dev/null 2>&1; sleep 1; rm -f /tmp/nfvis.db*; \
  setsid /tmp/nfvisd -db /tmp/nfvis.db -listen 127.0.0.1:18443 -init-admin-password "Admin@12345" -allow-plaintext \
  >/root/nfvisd.out 2>&1 </dev/null & sleep 4; pgrep -x nfvisd >/dev/null && echo up'

# 真机集成（无 VPP socket 自动跳过，CI 不跑）
ssh root@nfvis-vm 'export PATH=$PATH:/usr/local/go/bin; export GOPROXY=https://goproxy.cn,direct; \
  cd /opt/nfvis/src/nfvis && make integration'
```

### 3.2 ⚠️ 默认 HTTPS（决策 #72，易踩）

- nfvisd **默认自动生成自签证书并启用 HTTPS**（`/var/lib/nfvis/tls/`）。
  - 开发/测试要明文：**必须显式 `-allow-plaintext`**（该开关是权威的，会忽略已装/自签证书）。
  - `curl` 用 https 需 `-k` 或 `--cacert /var/lib/nfvis/tls/server.crt`。
  - `nfvis-cli` **无需额外参数**（缺省固定本机守护进程证书，`-ca`/`-insecure` 可覆盖）。
  - `make e2e` 用 `NFVIS_API=https://…`（证书经 `NFVIS_E2E_CA` 固定，缺省同上路径）。
- **监听地址收敛**：`-listen` 为通配（`""`/`0.0.0.0`/`::`）且已配置管理口地址时，收敛为管理口地址
  （管理口地址未配在本机时不收敛，避免启动失败）。

### 3.3 网卡 DPDK 绑定（决策 #72）

```bash
# 绑定/解绑（会中断流量，须 --yes）；已接管的网卡在内核中无 netdev，只能用 PCI 地址
nfvis-cli -c "request interfaces 0000:13:00.0 unbind-dpdk to-driver vmxnet3 --yes"
nfvis-cli -c "request interfaces ens224 bind-dpdk --yes"
```
- **实测平台行为**：① 绑定后内核网卡消失 → 只能按 PCI 定位，且结果须**按 PCI 回读驱动**；
  ② 清空 `driver_override` + `rescan` **不足以**让内核重新探测原生驱动 → 必须给 `to-driver`。
- 该卡不得正被 VPP 使用（操作前先 `systemctl stop vpp`）。

### 3.4 ⚠️ 跑集成测试前必须重置 VPP（本轮踩过）

真机验证若在 VPP 里建过对象（BD/VRF/端口），**跑 `make integration` 前必须 `systemctl restart vpp`**，
否则残留拓扑会污染用例（本轮遗留 3 个 bridge domain 导致 `TestE2EFlow` 的 VRF ping 0 received，
排查了一轮；决策 #37 亦记录过"同挂一个 BD 致 NAT 不回 ICMP"的陷阱）。

### 3.5 其它环境事实

- VPP **不自启**（`systemctl start vpp`）；虚机重启后需重绑 DPDK（步骤见 `docs/M3-进度交接.md`）。
  **重绑目前是带外手工步骤**，产品侧已有 `bind-dpdk` 命令可替代。
- nfvis-vm 直连 proxy.golang.org 不通；`git push` 需 ssh key（开发机已配）。
- **开发机内存限制**：本机 commit 限额约 2 GB，`go test ./...`（并行编译）会 `fatal error: out of memory`；
  用 `go test -p 1 ./...` 全绿。CI 不受影响。

## 5. 本轮踩坑记录（勿重蹈）

1. **口令哈希泄露**：commit 的审计详情是完整 diff，而 `/audit-logs` 只需 `ClassReadOnly` →
   read-only 账号可取他人哈希。**教训**：脱敏要覆盖"日志/审计/视图"全链路，且脱敏须在**渲染层**
   （放进 `Flatten` 会让"仅改口令"被判为无变更）。
2. **"声明了但无实现"反复出现**：`sriov.vf-count`、`max-sessions`、`facility/severity`、
   `management ip address`、物理口 link 告警都属此类。**教训**：命令树/契约里声明的字段若执行器未映射
   会**静默无效**，比缺功能更危险；复核时优先查这类。
3. **契约与实现漂移**：`/audit-logs` 声明 `offset` 却静默忽略；LLDP `system_name` 在 govpp 里根本取不到。
4. **复核要用"证伪"而非采信标签**：本轮 15 条降级里 6 处措辞/证据不准，1 处是真缺陷
   （"无真机证据"的 IPv6 实际藏着 v6 路由不可见的 bug）。
5. **脚本化 `pkill -f` 会杀掉自己的 ssh 会话**（命令行含匹配串时）——用 `pkill -f "[u]dp_listen"` 这类括号技巧规避。
